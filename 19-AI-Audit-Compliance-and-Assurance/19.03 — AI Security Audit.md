# 19.03 — AI Security Audit

## Part 1 — AI Security Audit Foundations, Scope, Criteria, Risk and Core Concepts

### 1. Definition of AI Security Audit

An AI Security Audit is a systematic, independent, and evidence-based examination of AI systems, AI security controls, processes, technologies, and governance arrangements against defined security criteria.

An AI Security Audit may evaluate:

* AI application security
* Model security
* Data security
* Identity and access management
* AI infrastructure
* API security
* Prompt and input security
* Retrieval-augmented generation security
* Agent security
* AI supply-chain security
* Monitoring
* Incident response
* Security governance

An AI Security Audit should have a defined objective, scope, criteria, procedures, evidence requirements, and reporting mechanism.

**AI Security Audit ≠ General Cybersecurity Audit Automatically.**

---

### 2. Purpose of AI Security Audit

The purpose of an AI Security Audit is to determine whether defined AI security requirements and controls are appropriately designed, implemented, and operating according to the applicable audit criteria.

Potential objectives include:

* Evaluating AI security governance
* Testing security controls
* Identifying control weaknesses
* Assessing AI attack-surface management
* Evaluating security monitoring
* Assessing model and data protection
* Evaluating AI incident preparedness
* Assessing third-party AI security
* Supporting risk management

The exact purpose depends on the approved audit engagement.

---

### 4. AI Security Audit vs Cybersecurity Audit

A conventional cybersecurity audit may examine enterprise information systems generally.

An AI Security Audit addresses security characteristics specific to AI systems and their lifecycle.

These may include:

* Model behavior
* Prompt injection
* Training-data poisoning
* Model extraction
* Model supply chain
* RAG security
* Agentic tool abuse
* AI-specific access paths
* AI model integrity
* AI provider dependencies

The boundary depends on the defined audit scope.

---

### 5. AI Security Audit vs AI Security Assessment

An AI security assessment evaluates a defined security condition against specified criteria.

An audit generally includes a more formal methodology involving:

* Audit objective
* Audit scope
* Audit criteria
* Audit procedures
* Evidence
* Findings
* Conclusions
* Reporting
* Follow-up

**Security Assessment ≠ Security Audit Automatically.**

---

### 6. AI Security Audit vs Penetration Test

A penetration test attempts to identify or demonstrate exploitable weaknesses through controlled security testing.

An AI Security Audit evaluates broader governance and control conditions.

A security audit may review whether penetration testing:

* Was required
* Was appropriately scoped
* Was performed
* Addressed relevant AI attack surfaces
* Produced documented results
* Was followed by remediation

**Penetration Test ≠ Complete AI Security Audit.**

---

### 7. AI Security Audit vs AI Red Teaming

AI red teaming uses adversarial techniques to identify weaknesses in AI systems.

Examples include:

* Prompt injection
* Jailbreaking
* Data extraction
* Tool abuse
* Model manipulation
* Adversarial inputs

An audit may evaluate whether appropriate red-team activities exist and whether findings are remediated.

**Red Teaming ≠ Audit Automatically.**

### 14. AI Security Audit Population

The population is the set of AI systems, controls, records, transactions, events, or configurations potentially subject to testing.

Examples include:

* All AI applications
* All production models
* All model changes
* All AI privileged accounts
* All AI security incidents
* All AI suppliers

Population definition should precede sampling.

### 15. AI Security Audit Materiality

Materiality concerns the significance of a security condition in relation to the audit objective.

Potential considerations include:

* Confidentiality impact
* Integrity impact
* Availability impact
* Model integrity
* Data sensitivity
* Business criticality
* Regulatory exposure
* Safety implications
* Customer impact
* Systemic dependency

Materiality methodology should be documented.

---

### 16. AI Security Audit Risk

AI security audit risk is the possibility that the audit conclusion may be inappropriate because relevant security conditions were not adequately identified, evaluated, or reported.

Potential sources include:

* Incomplete scope
* Incomplete population
* Insufficient evidence
* Sampling limitations
* Incorrect test logic
* Data-quality issues
* Auditor judgment error

---

### 17. AI Security Risk vs AI Security Audit Risk

AI security risk concerns the possibility of harm arising from a security condition.

### 21. AI Security Control Objective

Examples include:

* AI identities are uniquely identifiable.
* AI access is appropriately authorized.
* Sensitive AI data is protected.
* Model changes are controlled.
* Security events are monitored.
* AI systems can be contained during security incidents.

### 22. AI Security Control

A security control is a measure designed to address a defined security risk or achieve a defined security objective.

Examples include:

* Authentication

* Network segmentation
* Secrets management
* Security monitoring
* Vulnerability management
* Model integrity verification
* Prompt filtering
* Tool authorization

---

### 23. AI Security Control Design

Control-design testing evaluates whether a security control is capable of addressing the identified risk when operating as intended.

Questions may include:

* Does the control address the relevant threat?
* Is ownership defined?
* Is the control sufficiently specific?
* Is the frequency appropriate?
* Does it cover the relevant AI component?
* Does it generate evidence?

---

### 24. AI Security Control Implementation

Implementation testing determines whether the designed control has actually been established.

* Configuration
* Deployment records

* Procedures
* Access settings
* Security tooling
* System architecture

### 25. AI Security Control Operating Effectiveness
