# 14.07 — Personal Data in AI Prompts

## Part 1 — Personal Data in AI Prompts Foundations

### 1. Definition of Personal Data in AI Prompts

Personal data in AI prompts refers to information relating to an identified or identifiable individual that is entered, transmitted, processed, stored, retrieved, or otherwise exposed through an AI interaction.

Examples include:

* Names
* Email addresses
* Telephone numbers
* Employee information
* Customer records
* Financial information
* Location information
* Identifiers
* Health information
* Performance information

---

### 2. Purpose of Prompt Privacy

Prompt privacy protects individuals from unnecessary or unauthorized exposure of personal data through AI interactions.

The objective is to ensure that personal data entered into an AI system is:

* Necessary
* Authorized
* Appropriately protected
* Used for a defined purpose
* Minimized
* Retained appropriately
* Disclosed only to authorized recipients

---

### 3. AI Prompts as Data-Processing Interfaces

An AI prompt should be treated as a potential data-processing interface rather than merely a text field.

```text id="prompt14p7-01"
User
 |
 v
Prompt
 |
 v
AI Application
 |
 +--> Logging
 +--> Provider
 +--> Context
 +--> RAG
 +--> Memory
 |
 v
Model
 |
 v
Output
```

A single prompt can therefore cause personal data to enter multiple downstream systems.

---

### 4. Personal Data Identification in Prompts

Organizations should identify personal data that users may enter into prompts.

Potential categories include:

* Direct identifiers
* Indirect identifiers
* Professional information
* Behavioral information
* Financial information
* Sensitive information
* Free-text descriptions

Free-text prompts are particularly important because users may enter information that was not anticipated by the application designer.

---

### 5. Direct Identifiers

Direct identifiers can identify an individual without requiring significant additional information.

Examples include:

* Full name
* Email address
* Telephone number
* Government identifier
* Employee number

Prompt controls should identify and appropriately handle such information.

---

### 6. Indirect Identifiers

Information that does not independently identify a person may become identifying when combined with other information.

Examples include:

* Job title
* Department
* Location
* Age
* Date
* Unique event
* Customer characteristics

AI systems should consider the combined information available to the model and surrounding systems.

---

### 7. Free-Text Privacy Risk

Free-text prompts create significant privacy uncertainty because users may disclose information beyond the expected schema.

```text id="prompt14p7-02"
Expected Input
     |
     v
Name + Question
     
Actual User Input
     |
     +--> Name
     +--> Customer Details
     +--> Medical Information
     +--> Internal Records
     +--> Secrets
     |
     v
AI Processing
```

The system should therefore not assume that a prompt contains only the fields intended by its interface.

---

### 8. Prompt Data Classification

Prompt content should be classified according to applicable data-classification rules.

Possible classifications include:

* Public
* Internal
* Confidential
* Personal
* Sensitive
* Restricted

Classification should influence whether the information can be transmitted to the AI system.

---

### 9. Prompt Purpose Limitation

Personal data should only be entered into an AI prompt when it is necessary for the defined processing purpose.

For example, an AI system intended to summarize an employee's work performance may not require the employee's full home address.

**Purpose relevance ≠ unrestricted data access.**

---

### 10. Prompt Data Minimization

Prompt construction should minimize personal information.

```text id="prompt14p7-03"
Full Record
    |
    v
Required Attributes
    |
    v
Minimal Prompt
    |
    v
AI Model
```

Users and applications should avoid sending complete records when only selected attributes are required.

---

### 11. Prompt Data Necessity

The organization should determine whether personal data is actually required for the AI task.

Potential alternatives include:

* Removing identifiers
* Replacing identifiers with tokens
* Aggregating information
* Using synthetic data
* Using pseudonyms
* Sending only necessary fields

---

### 12. Prompt Data Pseudonymization

Pseudonymization can reduce direct exposure of identifiers.

Example:

```text id="prompt14p7-04"
Before:
"Analyze the performance of Jonathan Morales."

After:
"Analyze the performance of EMP-1047."
```

The mapping between the pseudonym and individual must remain appropriately protected.

**Pseudonymization ≠ anonymization.**

---

### 13. Prompt Anonymization

Where genuinely anonymous information can satisfy the use case, personal identifiers may be removed or transformed so that individuals are no longer identifiable using reasonably available means.

However, simply removing a name does not automatically make prompt data anonymous.

---

### 14. Prompt Redaction

Redaction removes unnecessary personal or sensitive information before transmission.

```text id="prompt14p7-05"
Raw Prompt
   |
   v
Detection
   |
   v
Redaction
   |
   v
Sanitized Prompt
   |
   v
AI Model
```

---

### 15. Prompt Tokenization

Tokenization can replace sensitive values with controlled tokens before AI processing.

Example:

```text id="prompt14p7-06"
Original:
Customer: Maria Lopez
Account: 12345678

Tokenized:
Customer: [CUST_4821]
Account: [ACCOUNT_7712]
```

The token mapping should be separately protected.

---

### 16. Prompt DLP

Data Loss Prevention controls can inspect prompts before they reach the model.

DLP may detect:

* Personal identifiers
* Financial information
* Credentials
* Secrets
* Sensitive documents
* Restricted information

---

### 17. Prompt Privacy Gateway

A prompt privacy gateway can provide a centralized enforcement point.

```text id="prompt14p7-07"

 +--> Authorization
 +--> Policy
 |
 v

 |
 v
```

---

### 18. Prompt Authorization

The ability to submit a prompt does not automatically authorize the user to submit any personal data.

Authorization should consider:

* User identity
* Role
* Purpose
* Data classification
* Application
* Destination
* Processing context

**Prompt access ≠ personal-data processing authorization.**

---

### 19. Prompt Context

Personal data may enter the model through context even when the user did not explicitly type it.

Context can include:

* Conversation history
* User profile
* RAG results
* Memory
* Tool results
* System instructions

Therefore, prompt privacy must include contextual data.

---

### 20. Conversation History Privacy

Conversation history may contain personal information accumulated over multiple interactions.

The system should evaluate:

* Retention
* Access
* Searchability
* Sharing
* Export
* Deletion
* Cross-user isolation

---

### 21. Prompt Memory Privacy

If prompts are stored as AI memory, personal information may persist beyond the original interaction.

```text id="prompt14p7-08"
Prompt
 |
 v
Memory Decision
 |
 +--> Do Not Store
 |
 +--> Store
       |
       v
Scoped Memory
       |
       v
Future Context
```

**Memory capability ≠ permission to retain.**

---

### 22. Prompt RAG Privacy

Prompt processing may trigger retrieval of additional personal information.

The system should evaluate:

* User authorization
* Tenant
* Purpose
* Data source
* Retrieval scope
* Output disclosure

**Retrieval capability ≠ retrieval authorization.**

---

### 23. Prompt Tool Privacy

Tools invoked because of a prompt may access personal information.

For example, an AI assistant may use a prompt to query:

* CRM
* HR system
* Email
* Database
* Ticketing platform

Tool access should be separately authorized.

---

### 24. Prompt Agent Privacy

An agent may transform a prompt into multiple actions.

```text id="prompt14p7-09"
User Prompt
     |
     v
Agent
     |
 +---+---+---+
 |   |   |   |
CRM DB Email API
 |   |   |   |
 +---+---+---+
     |
     v
Personal Data
```

The initial prompt authorization should not automatically authorize every downstream agent action.

---

### 25. Prompt Provider Transmission

Personal data may leave the organization's controlled environment when prompts are transmitted to an external AI provider.

The organization should know:

* What data is transmitted
* Why it is transmitted
* Where it is processed
* Who processes it
* Whether it is retained
* Whether it is used for training

---

### 26. Prompt Provider Training Use

The organization should determine whether submitted prompts may be used by the provider for:

* Model training
* Model improvement
* Analytics
* Abuse monitoring
* Diagnostics

The approved provider configuration should align with organizational requirements.

---

### 27. Prompt Provider Retention

Prompt retention should be explicitly assessed.

Retention may occur in:

* Application logs
* AI gateways
* Provider systems
* Monitoring platforms
* Debugging systems
* Backups

Deleting the conversation from the user interface does not automatically establish deletion everywhere.

---

### 28. Prompt Logging Privacy

Logging complete prompts can create a secondary personal-data repository.

```text id="prompt14p7-10"
User Prompt
    |
    +----------> Model
    |
    +----------> Log
                    |
                    v
              Personal Data
```

Logging should therefore be minimized and protected.

---

### 29. Prompt Monitoring Privacy

Security and operational monitoring should avoid unnecessarily collecting complete prompt content.

Where possible, monitoring can use:

* Metadata
* Event types
* Classification
* Hashes
* Redacted content
* Structured indicators

---

### 30. Prompt Error Handling

Error messages can accidentally disclose personal information.

Examples include:

* Echoing the original prompt
* Displaying sensitive tool output
* Returning internal identifiers
* Exposing provider request content

Error-handling architecture should therefore be privacy-aware.

---

### 31. Prompt Output Privacy

Personal data entered into a prompt may appear in the model output.

The system should evaluate:

* Recipient
* Authorization
* Sensitivity
* Purpose
* Accuracy
* Disclosure risk

**Model output ≠ automatically authorized disclosure.**

---

### 32. Prompt Cross-User Isolation

Prompt information must remain isolated between users.

Potential leakage paths include:

* Conversation history
* Memory
* Cache
* RAG
* Logs
* Shared context
* Application state

---

### 33. Prompt Cross-Tenant Isolation

Multi-tenant AI applications should enforce tenant boundaries throughout prompt processing.

```text id="prompt14p7-11"
Tenant A Prompt
      |
      v
Context A
      |
      v
Model
      |
      v

Tenant B Prompt
      |
      v
Context B
      |
      v
Model
      |
      v
Output B

A Data -------- X -------- B Data
```

Shared infrastructure should not imply shared authorization.

---

### 34. Prompt Sensitive-Data Handling

Prompts containing sensitive information should receive stronger controls.

Potential controls include:

* DLP
* Blocking
* Redaction
* Encryption
* Restricted providers
* Human approval
* Enhanced logging controls

---

### 35. Prompt Special-Category Data

Where special-category personal data may enter prompts, the organization should evaluate the applicable legal requirements and safeguards.

The system should not rely solely on users to recognize sensitive categories.

---

### 36. Prompt Accuracy

AI systems may process inaccurate personal information submitted through prompts.

The organization should distinguish:

* User-provided information
* Authoritative records
* AI-generated information
* AI-generated inference

AI output should not automatically overwrite authoritative personal records.

---

### 37. Prompt Injection and Privacy

Prompt injection can manipulate an AI system into disclosing information that the user is not authorized to receive.

For example:

```text id="prompt14p7-12"
Attacker Prompt
      |
      v
Prompt Injection
      |
      v
AI Model
      |
      v
Unauthorized Retrieval
      |
      v
Personal Data Exposure
```

Prompt-injection defenses should therefore be considered part of AI privacy protection when they affect personal-data disclosure.

---

### 38. Prompt Data Exfiltration

An attacker may attempt to use prompts to extract personal data from:

* RAG
* Memory
* Conversation history
* Tools
* Databases
* Model behavior

The architecture should prevent prompt access from becoming unrestricted data-extraction capability.

---

### 50. Core Principle of Personal Data in AI Prompts

**Personal data entered into an AI prompt is not merely user-provided text; it is a potential personal-data processing event that can propagate through the application, context, model, provider, RAG, memory, tools, agents, logs, monitoring systems, and downstream services.**

The organization should therefore control prompt data according to its **purpose, necessity, authorization, classification, minimization, destination, retention, and potential impact on individuals**.

The fundamental principles are:

**Prompt access ≠ authorization to process personal data.**

**Data availability ≠ permission to process.**

**User input ≠ unrestricted processing authorization.**

**Technical capability ≠ authorized capability.**

**Model capability ≠ privacy authority.**

**Prompt capability ≠ provider authorization.**

**Retrieval capability ≠ retrieval authorization.**

**Memory capability ≠ permission to retain.**

**Tool capability ≠ data-access authorization.**

**Agent capability ≠ privacy authority.**

**Provider capability ≠ permission to process personal data.**

**Pseudonymization ≠ anonymization.**

**Redaction ≠ guaranteed privacy.**

**Encryption ≠ privacy compliance.**

**Prompt filtering ≠ authorization.**

**Prompt logging ≠ harmless monitoring.**

**Model output ≠ authorized disclosure.**

**Human review ≠ automatic privacy assurance.**

**Privacy control implementation ≠ privacy control effectiveness.**

**Privacy testing ≠ permanent privacy assurance.**

**A privacy-protective prompt architecture must ensure that personal data is minimized before processing, authorized independently of model capability, protected throughout downstream processing, prevented from crossing unauthorized user or tenant boundaries, retained only when justified, and continuously monitored and reassessed as prompts, models, context, RAG, memory, tools, agents, providers, and processing purposes change.**

## Part 2 — Personal Data in AI Prompts Controls

### 51. AI Prompt Privacy Control Framework

The organization should establish a control framework governing how personal data is entered, transmitted, processed, stored, retrieved, logged, and deleted through AI prompts.

```text id="prompt14p7-15"
Prompt
  |
  v
Detection
  |
  v
Classification
  |
  v
Authorization
  |
  v
Minimization
  |
  v
AI Processing
  |
  v
Output / Retention
```

The framework should apply to both user-generated and application-generated prompts.

---

### 52. Prompt Privacy Planning Control

Prompt privacy requirements should be identified before deploying an AI application.

Planning should establish:

* Expected prompt data
* Permitted personal data
* Prohibited data
* Processing purpose
* Provider destination
* Retention
* Logging
* Monitoring
* Exception handling

---

### 53. Prompt Privacy Scope Control

The control scope should include all locations where prompt information may be processed.

This includes:

* User interface
* Browser
* Application
* AI gateway
* Model gateway
* Provider
* RAG
* Memory
* Tools
* Agents
* Logs
* Monitoring
* Backups

---

### 54. Prompt Data Classification Control

Prompt information should be classified before or during processing where technically feasible.

Classification should identify:

* Public
* Internal
* Confidential
* Personal
* Sensitive
* Restricted

The classification should determine which AI processing paths are permitted.

---

### 55. Prompt Personal-Data Detection Control

The organization should implement mechanisms to identify personal data in prompts.

Detection may use:

* Pattern matching
* Data classifiers
* DLP
* Named-entity recognition
* Structured-field detection
* Custom rules

Detection should be treated as a control signal rather than proof that every instance has been identified.

---

### 56. Prompt Sensitive-Data Detection Control

The system should identify sensitive information that requires enhanced handling.

Potential categories include:

* Financial information
* Health information
* Government identifiers
* Authentication information
* Employment information
* Other restricted data

---

### 57. Prompt Special-Category Data Detection Control

Where applicable, controls should identify potential special-category personal data.

Possible outcomes include:

* Allow
* Redact
* Mask
* Route to approved model
* Require authorization
* Block

---

### 58. Prompt Purpose Validation Control

The system should verify that personal data entered into a prompt is relevant to the approved processing purpose.

```text id="prompt14p7-16"
Prompt Data
    |
    v
Purpose Check
    |
 +--+--+
 |     |
Relevant  Irrelevant
 |           |
Allow       Remove / Block
```

---

### 59. Prompt Data-Minimization Control

The application should send only the personal data necessary for the AI task.

Controls may remove:

* Unnecessary identifiers
* Unnecessary attributes
* Unnecessary historical information
* Unnecessary metadata

---

### 60. Prompt Field-Level Minimization Control

Structured AI applications should minimize personal data at the field level.

Example:

```text id="prompt14p7-17"
Customer Record
   |
   +--> Name       --> Needed
   +--> Address    --> Not Needed
   +--> Phone      --> Not Needed
   +--> Order ID   --> Needed
   |
   v
Minimal Prompt
```

---

### 61. Prompt Redaction Control

Personal information that is not necessary should be redacted before AI processing.

```text id="prompt14p7-18"

   |
   v

   |
   v
Redaction
   |
   v
Sanitized Prompt
   |
   v

```

---

### 62. Prompt Pseudonymization Control

Where identifiers are unnecessary, pseudonyms or tokens should be used where appropriate.

```text id="prompt14p7-19"
"Maria Lopez"
      |
      v
"CUSTOMER_4821"
      |
      v
AI Processing
```

The mapping table must remain separately protected.

---

### 63. Prompt Anonymization Control

Where feasible, information should be anonymized so that individuals are no longer identifiable using reasonably available means.

The control should not treat simple name removal as automatic anonymization.

---

### 64. Prompt Tokenization Control

Tokenization should replace sensitive values with controlled references.

The system should ensure that token mappings are not unnecessarily transmitted to the model.

---

### 65. Prompt DLP Control

DLP should inspect prompts for restricted information before transmission.

Potential actions include:

* Allow
* Warn
* Redact
* Block
* Require approval
* Route to a restricted processing path

---

### 66. Prompt Authorization Control

The ability to access an AI application should not automatically authorize access to every category of personal data.

Authorization should consider:

* Identity
* Role
* Purpose
* Data classification
* Application
* Destination

**AI access ≠ personal-data access authorization.**

---

### 67. Prompt User-Identity Control

The identity of the user submitting the prompt should be reliably established where required.

Identity should support:

* Authorization
* Accountability
* Audit
* Incident investigation

---

### 68. Prompt Purpose-Identity Binding Control

Where appropriate, the system should bind the processing purpose to the authenticated user or application context.

### 69. Prompt Tenant-Isolation Control

Prompt processing should maintain tenant boundaries.

Controls should prevent one tenant's prompt information from becoming available to another tenant.

---

### 70. Prompt Session-Isolation Control

Conversation sessions should be isolated from unrelated users and sessions.

Isolation should cover:

* Prompt history
* Context
* Memory
* Caches
* Tool results

---

### 71. Prompt Conversation-Privacy Control

Conversation history should be governed as potentially sensitive personal data.

Controls should address:

* Access
* Retention
* Search
* Export
* Sharing
* Deletion

---

### 72. Prompt Context-Privacy Control

The system should control personal information automatically inserted into prompts.

Context should be:

* Authorized
* Relevant
* Minimized
* Purpose-bound
* Traceable

---

### 73. Prompt Context-Source Control

Every automated context source should be identifiable.

Potential sources include:

* CRM
* HR
* ERP
* Email
* RAG
* Memory
* User profile
* Tool output

### 74. Prompt RAG Authorization Control

RAG retrieval should verify authorization before personal data is added to model context.

```text id="prompt14p7-21"
  |
  v

  |

Authorization
  |
  v
RAG Retrieval
  |
  v
Authorized Context
```

**Retrieval capability ≠ retrieval authorization.**

---

### 75. Prompt Vector-Store Privacy Control

Vector stores should preserve source-data authorization boundaries.

Controls should address:

* Tenant isolation
* Metadata filtering
* Access control
* Index security
* Deletion synchronization

---

### 76. Prompt Memory Authorization Control

Memory retrieval should be separately authorized.

A user who can interact with an AI assistant should not automatically receive all historical information stored in memory.

---

### 77. Prompt Memory Retention Control

The organization should establish what prompt information can be retained as memory.

Retention should be:

* Purpose-based
* Limited
* Authorized
* Reviewable
* Deletable

### 78. Prompt Tool-Access Control

AI tools invoked through prompts should have explicit permissions.

```text id="prompt14p7-22"
  |
  v
AI
  |
  v

  |
  v

  |
 +--+--+
 |     |

```

The model should not independently determine whether a tool action is authorized.

---

### 79. Prompt Agent-Authority Control

Agents should operate within explicitly defined authorization boundaries.

Controls should constrain:

* Data access
* Tool access
* External communication
* Transactions
* System changes

**Agent capability ≠ authority.**

---

### 80. Prompt Provider-Transmission Control

Before personal data is transmitted to an external AI provider, the system should verify that the provider is approved for the applicable data and purpose.

---

### 81. Prompt Provider Data-Use Control

The organization should control whether the provider may use prompt information for:

* Training
* Improvement
* Analytics
* Diagnostics
* Abuse monitoring

The approved processing mode should be technically and contractually aligned.

---

### 82. Prompt Provider Retention Control

Provider retention should be identified and governed.

The organization should know:

* What is retained
* Retention period
* Processing location
* Access
* Deletion mechanism

---

### 83. Prompt Geographic-Processing Control

Prompt data should only be sent to approved processing locations where geographic restrictions apply.

---

### 84. Prompt Cross-Border Control

Where personal data is transferred across borders, applicable privacy and transfer requirements should be evaluated.

The prompt gateway should not silently create an unauthorized international transfer.

---

### 85. Prompt Encryption Control

Prompt data should be protected appropriately in transit and at rest.

Encryption should protect the data but does not itself establish authorization to process it.

**Encryption ≠ privacy authorization.**

---

### 86. Prompt Logging Control

Logging should be minimized and designed to avoid unnecessary duplication of personal data.

The organization should determine whether it really needs:

* Full prompt
* Partial prompt
* Redacted prompt
* Metadata
* Event identifier

---

### 87. Prompt Monitoring Control

Monitoring should provide sufficient visibility without unnecessarily collecting the underlying personal data.

Where possible, monitoring should use:

* Metadata
* Classification
* Event type
* Hashes
* Redacted values
* Policy decisions

---

### 88. Prompt Error-Handling Control

Error messages should not echo personal data unnecessarily.

Controls should prevent exposure through:

* Exceptions
* Debug logs
* API errors
* Stack traces
* User interfaces

---

### 89. Prompt Output-Privacy Control

Outputs containing personal data should be evaluated before delivery where required.

Evaluation may include:

* Recipient authorization
* Data classification
* DLP
* Sensitive-data detection
* Human review

---

### 90. Prompt Recipient-Authorization Control

The recipient of AI-generated information should be authorized to receive the information.

The system should prevent one user's personal information from appearing in another user's output.

---

Multi-tenant AI applications should validate tenant boundaries before returning outputs.

Cross-tenant exposure should be treated as a material privacy control failure.

---

### 93. Prompt Personal-Data Retention Control

The organization should define retention for personal data contained in:

* Prompts

* Logs
* Provider systems

* Conversation storage

### 117. Core Control Principle

**Prompt access ≠ authorization to process personal data.**

**Data availability ≠ permission to process.**

**Technical capability ≠ authorized capability.**

**Model capability ≠ privacy authority.**

**Model output ≠ authorization.**

**Retrieval capability ≠ retrieval authorization.**

**Memory capability ≠ permission to retain.**

**Tool capability ≠ data-access authorization.**

**Agent capability ≠ privacy authority.**

**Provider capability ≠ permission to process personal data.**

**Prompt detection ≠ complete detection.**

**DLP ≠ authorization.**

**Redaction ≠ anonymization.**

**Pseudonymization ≠ anonymization.**

**Encryption ≠ privacy compliance.**

**Logging ≠ harmless monitoring.**

**Human review ≠ automatic privacy assurance.**

**Policy ≠ technical enforcement.**

**Control implementation ≠ control effectiveness.**

**Passing a prompt privacy test ≠ permanent privacy assurance.**

**Prompt privacy controls are effective only when they are technically enforced, independently authorized, appropriately minimized, protected against bypass, continuously tested, observable, attributable, evidenced, and capable of being modified, restricted, revoked, or reassessed when the AI processing environment changes.**
