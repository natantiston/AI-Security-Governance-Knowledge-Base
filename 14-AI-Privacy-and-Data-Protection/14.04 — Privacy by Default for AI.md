# 14.04 — Privacy by Default for AI

## Part 1 — Privacy by Default for AI Foundations

### 1. Definition of Privacy by Default for AI

Privacy by Default for AI means that an AI system should operate with privacy-protective settings automatically, without requiring users or administrators to manually activate basic privacy protections.

The default configuration should minimize unnecessary:

* Data collection
* Data access
* Data retention
* Data disclosure
* Model context
* Memory
* Provider sharing
* Logging

---

### 2. Purpose of Privacy by Default for AI

The purpose is to ensure that privacy protection is the **starting condition** of an AI system rather than an optional configuration.

```text id="pbd14d1-01"
AI Deployment
     |
     v
Privacy-Protective Defaults
     |
     v
Minimum Necessary Processing
     |
     v
Authorized Expansion
     |
     v
Controlled AI Operation
```

Users should not need to understand complex AI architecture to avoid unnecessary privacy exposure.

---

### 3. Privacy by Default vs Privacy by Design

Privacy by Design establishes privacy as an architectural requirement.

Privacy by Default establishes privacy as the **initial operating state**.

```text id="pbd14d1-02"
Privacy by Design
       |
       v
Architecture contains
privacy controls
       |
       v
Privacy by Default
       |
       v
System starts with
protective settings
```

The two principles should operate together.

---

### 4. Default Privacy as a Security Boundary

Default settings should establish a protective baseline before users interact with the AI system.

Examples include:

* Restricted data access
* Minimal retention
* Disabled unnecessary memory
* Restricted external sharing
* Limited logging
* Least-privilege tool access

---

### 5. Default Data Collection

AI systems should not collect personal data merely because the system is technically capable of collecting it.

Default collection should be limited to information necessary for the approved purpose.

---

* Training
* Profiling
* Marketing
* Analytics
* Employee monitoring
* Unrelated decision-making

This should apply to:

* Users
* Applications

* Agents

### 11. Default Session Isolation

AI sessions should be isolated by default where the use case requires separate privacy boundaries.

Conversation history, memory, context, and tool results should not automatically cross session boundaries.

---

Conversation histories should have privacy-protective defaults.

The system should avoid unnecessary:

* Long-term storage
* Administrative visibility
* Provider sharing
* Secondary use
* Training use
* Cross-user access

---

### 13. Default Memory State

Persistent AI memory should not automatically be enabled simply because the platform supports it.

Where memory is unnecessary, the default should be:

**Memory disabled or minimized.**

Where memory is required, it should have controlled scope and retention.

### 50. Core Principle of Privacy by Default for AI

**Privacy by Default for AI means that an AI system should begin and remain in a privacy-protective state unless a specific, justified, authorized requirement permits broader processing.**

The default operating state should minimize unnecessary:

* Personal-data collection
* Data access
* Context
* Memory
* Retrieval
* Tool permissions
* Agent authority
* Provider sharing
* Retention
* Logging
* External disclosure

The fundamental principles are:

**Default access ≠ unrestricted access.**

**Data availability ≠ permission to process.**

**Technical capability ≠ authorized capability.**

**Model capability ≠ privacy authority.**

**Model output ≠ authorization.**

**Retrieval capability ≠ retrieval authorization.**

**Memory capability ≠ permission to retain.**

**Tool capability ≠ data-access authorization.**

**Agent capability ≠ agent authority.**

**Provider capability ≠ permission to process personal data.**

**User choice ≠ privacy-protective default.**

**Configuration availability ≠ authorized configuration.**

**Encryption ≠ Privacy by Default.**

**Privacy by Design ≠ Privacy by Default.**

**Privacy-protective configuration ≠ permanent privacy assurance.**

**A privacy default is effective only when it is technically enforced, resistant to unauthorized modification, observable, testable, attributable, and continuously reassessed as the AI system, data, processing purpose, providers, and operating environment change.**

The fundamental architectural separations remain:

**Privacy by Default ≠ Privacy by Design.**

**Default access ≠ unrestricted access.**

**Data availability ≠ permission to process.**

**Technical capability ≠ authorized capability.**

**Model capability ≠ privacy authority.**

**Model output ≠ authorization.**

**Retrieval capability ≠ retrieval authorization.**

**Memory capability ≠ permission to retain.**

**Tool capability ≠ data-access authorization.**

**Agent capability ≠ agent authority.**

**Provider capability ≠ permission to process personal data.**

**Configuration availability ≠ authorized configuration.**

**Encryption ≠ Privacy by Default.**

**Privacy-protective configuration ≠ privacy assurance.**

**Privacy testing ≠ permanent privacy assurance.**

**A privacy-protective default is effective only when it is technically enforced, protected against unauthorized modification, observable, testable, attributable, continuously monitored, and capable of being reassessed, restricted, rolled back, or revoked when the AI system or its processing environment changes.**
