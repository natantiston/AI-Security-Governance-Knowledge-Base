# 14.04 — Privacy by Default for AI

## Part 1 — Privacy by Default for AI Foundations

### 1. Definition of Privacy by Default for AI

Privacy by Default for AI means that an AI system should operate with privacy-protective settings automatically, without requiring users or administrators to manually activate basic privacy protections.

The default configuration should minimize unnecessary:

* Data collection
* Data access
* Data retention
* Data disclosure
* Model context
* Memory
* Provider sharing
* Logging

---

### 2. Purpose of Privacy by Default for AI

The purpose is to ensure that privacy protection is the **starting condition** of an AI system rather than an optional configuration.

```text id="pbd14d1-01"
AI Deployment
     |
     v
Privacy-Protective Defaults
     |
     v
Minimum Necessary Processing
     |
     v
Authorized Expansion
     |
     v
Controlled AI Operation
```

Users should not need to understand complex AI architecture to avoid unnecessary privacy exposure.

---

### 3. Privacy by Default vs Privacy by Design

Privacy by Design establishes privacy as an architectural requirement.

Privacy by Default establishes privacy as the **initial operating state**.

```text id="pbd14d1-02"
Privacy by Design
       |
       v
Architecture contains
privacy controls
       |
       v
Privacy by Default
       |
       v
System starts with
protective settings
```

The two principles should operate together.

---

### 4. Default Privacy as a Security Boundary

Default settings should establish a protective baseline before users interact with the AI system.

Examples include:

* Restricted data access
* Minimal retention
* Disabled unnecessary memory
* Restricted external sharing
* Limited logging
* Least-privilege tool access

---

### 5. Default Data Collection

AI systems should not collect personal data merely because the system is technically capable of collecting it.

Default collection should be limited to information necessary for the approved purpose.

---

### 6. Default Data Minimization

AI systems should start with the minimum necessary information.

```text id="pbd14d1-03"
Available Data
      |
      v
Purpose Filter
      |
      v
Relevance Filter
      |
      v
Minimum Necessary Data
      |
      v
AI Processing
```

Additional data should require an appropriate justification and authorization.

---

### 7. Default Purpose Limitation

AI data should initially be available only for approved purposes.

A system should not assume that information collected for one AI function can automatically be reused for:

* Training
* Profiling
* Marketing
* Analytics
* Employee monitoring
* Unrelated decision-making

---

### 8. Default Access Restrictions

Personal data should be inaccessible by default unless access is required for the approved function.

This should apply to:

* Users
* Applications
* Models
* Agents
* Tools
* Administrators

---

### 9. Default Least Privilege

AI components should begin with the minimum permissions necessary.

```text id="pbd14d1-04"
AI Component
     |
     v
Minimum Permissions
     |
     +--> Required Data
     +--> Required API
     +--> Required Tool
     |
     X
Unnecessary Access
```

Additional privileges should be explicitly granted.

---

### 10. Default Tenant Isolation

Multi-tenant AI systems should begin with tenant isolation enabled.

```text id="pbd14d1-05"
Tenant A
  |
  +--> Data A
  +--> RAG A
  +--> Memory A

Tenant B
  |
  +--> Data B
  +--> RAG B
  +--> Memory B

A -------- X -------- B
```

Shared infrastructure should not create shared data access.

---

### 11. Default Session Isolation

AI sessions should be isolated by default where the use case requires separate privacy boundaries.

Conversation history, memory, context, and tool results should not automatically cross session boundaries.

---

### 12. Default Conversation Privacy

Conversation histories should have privacy-protective defaults.

The system should avoid unnecessary:

* Long-term storage
* Administrative visibility
* Provider sharing
* Secondary use
* Training use
* Cross-user access

---

### 13. Default Memory State

Persistent AI memory should not automatically be enabled simply because the platform supports it.

Where memory is unnecessary, the default should be:

**Memory disabled or minimized.**

Where memory is required, it should have controlled scope and retention.

---

### 14. Default Memory Scope

When memory is enabled, the default scope should be as narrow as practical.

Possible boundaries include:

* User
* Tenant
* Application
* Workspace
* Session

Memory should not automatically become enterprise-wide context.

---

### 15. Default RAG Access

RAG systems should begin with restricted retrieval permissions.

```text id="pbd14d1-06"
AI Request
     |
     v
Retrieval Gateway
     |
     v
Default: DENY
     |
     v
Authorized Scope
     |
     v
Approved Retrieval
```

The default state should not expose every searchable enterprise document.

---

### 16. Default Vector-Store Isolation

Vector stores should begin with appropriate tenant, user, and repository boundaries.

Searchability should not be interpreted as authorization.

---

### 17. Default Context Minimization

AI systems should provide only necessary context to the model.

Unnecessary:

* Conversation history
* User attributes
* Documents
* Memory
* Tool results

should not automatically enter the context window.

---

### 18. Default Prompt Privacy

AI prompt interfaces should use privacy-protective defaults.

Examples include:

* DLP enabled
* Sensitive-data warnings
* Redaction
* Classification
* Restricted external transmission

---

### 19. Default Sensitive-Data Handling

Sensitive personal data should receive stronger default restrictions.

Possible default behavior:

```text id="pbd14d1-07"
Sensitive Data
     |
     v
Detection
     |
 +---+---+
 |       |
BLOCK   Controlled
          |
          v
     Authorized Use
```

---

### 20. Default DLP Enforcement

DLP should be enabled by default where appropriate for the AI use case.

The system should not require every user to understand which information should not be submitted to an AI service.

---

### 21. Default Redaction

Where personal information is unnecessary, automatic redaction or masking should be preferred over relying exclusively on user awareness.

---

### 22. Default Provider Sharing

AI systems should not automatically transmit enterprise personal data to external providers unless that transfer is part of an approved processing architecture.

---

### 23. Default Provider Training Restrictions

Where provider configuration permits, enterprise data should not automatically be made available for provider model training or unrelated service improvement.

Provider settings should align with approved organizational requirements.

---

### 24. Default Provider Retention

Provider retention should use the most privacy-protective configuration compatible with the approved service.

Long-term provider retention should not be assumed to be necessary.

---

### 25. Default Geographic Processing

Where geographic restrictions apply, AI services should default to approved processing regions.

Unauthorized regions should not be selectable through ordinary user configuration.

---

### 26. Default Data Residency

Cloud and AI services should use approved storage and processing locations by default where residency requirements apply.

---

### 27. Default Logging Minimization

AI systems should not automatically log every piece of user content indefinitely.

```text id="pbd14d1-08"
AI Event
   |
   v
Logging Policy
   |
 +--+--+
 |     |
Metadata  Necessary Content
   |          |
   +----+-----+
        |
        v
Controlled Log
```

---

### 28. Default Monitoring Privacy

Monitoring should collect enough information for security and operational purposes while minimizing unnecessary personal-data exposure.

---

### 29. Default Error Privacy

Error messages should not expose unnecessary personal data.

Stack traces, debugging information, and alerts should be designed to avoid uncontrolled disclosure.

---

### 30. Default Tool Permissions

AI tools should begin with narrowly scoped permissions.

For example, an AI assistant that can read calendars should not automatically receive:

* Email deletion
* Financial-system access
* HR-system access
* Administrative privileges

---

### 31. Default Agent Authority

Agents should begin with constrained authority.

```text id="pbd14d1-09"
Agent
 |
 +--> Identity
 +--> Purpose
 +--> Tool Scope
 +--> Data Scope
 +--> Action Scope
 |
 v
Default Restricted Authority
```

Agent capability should never automatically become enterprise authority.

---

### 32. Default Human Approval

High-impact AI actions should require explicit human approval where the risk and applicable requirements warrant it.

The system should not assume that autonomous execution is the default for sensitive actions.

---

### 33. Default Output Protection

AI outputs should be subject to privacy controls before disclosure where appropriate.

Possible controls include:

* DLP
* Sensitive-data detection
* Redaction
* Recipient authorization
* Human review

---

### 34. Default External Sharing Restrictions

AI-generated content containing personal information should not automatically be shared with:

* External users
* External applications
* Third-party providers
* Public channels

---

### 35. Default Retention

AI data should begin with an appropriate retention period rather than indefinite retention.

Retention should cover:

* Prompts
* Outputs
* Conversations
* Memory
* RAG data
* Logs
* Evaluation data

---

### 36. Default Deletion

Systems should provide automated deletion according to defined retention requirements.

```text id="pbd14d1-10"
Data Created
     |
     v
Retention Period
     |
     v
Expiration
     |
     v
Deletion
     |
     v
Verification
```

---

### 37. Default Backup Privacy

Backups should inherit privacy-protective defaults.

Controls should include:

* Encryption
* Restricted access
* Retention
* Geographic controls
* Deletion lifecycle

---

### 38. Default Data-Subject Rights

AI architectures should begin with the capability to identify and manage applicable personal data for individual rights requests.

Rights should not depend on the AI model remembering where personal data was stored.

---

### 39. Default Privacy for Development

Development environments should use privacy-protective defaults.

Examples include:

* Synthetic data
* Masked data
* Restricted production-data access
* Separate credentials
* Limited logging

---

### 40. Default Privacy for Testing

Testing environments should minimize real personal-data exposure.

```text id="pbd14d1-11"
Production Data
      |
      v
Need Assessment
      |
 +----+----+
 |         |
No Need   Approved Need
 |             |
 v             v
Synthetic    Protected Data
```

---

### 41. Default Training Data Restrictions

AI training pipelines should begin with restricted access to personal data.

Only approved datasets should enter training workflows.

---

### 42. Default Fine-Tuning Restrictions

Fine-tuning pipelines should default to controlled datasets with:

* Provenance
* Approval
* Access control
* Minimization
* Retention

---

### 43. Default Model Access

Models should not automatically have access to every enterprise data source.

Model access should be mediated through application and authorization layers.

---

### 44. Default API Privacy Controls

AI APIs should begin with:

* Authentication
* Authorization
* Rate controls
* DLP
* Data classification
* Logging controls

---

### 45. Default Administrative Access

Administrators should not automatically have unrestricted visibility into AI conversations, memory, prompts, or personal data.

Administrative access should be justified and controlled.

---

### 46. Default Privacy Monitoring

The organization should monitor whether privacy-protective defaults remain enabled.

Monitoring should identify:

* Configuration changes
* Disabled controls
* Expanded permissions
* Increased retention
* New providers
* New data sources
* Memory activation
* Geographic changes

---

### 47. Default Configuration Integrity

Privacy-protective configurations should be protected from unauthorized modification.

```text id="pbd14d1-12"
Approved Configuration
        |
        v
Configuration Control
        |
        v
Integrity Verification
        |
   +----+----+
   |         |
 VALID     ALTERED
   |         |
   v         v
Operate    Block / Alert
```

---

### 48. Default Privacy Assurance

Privacy defaults should be tested rather than assumed to be effective.

Testing should verify that the system actually starts and remains in the intended privacy-protective state.

---

### 49. Enterprise Privacy-by-Default Principle

Privacy by Default should establish a **minimum necessary processing baseline** for every AI system.

```text id="pbd14d1-13"
Default State
     |
     v
Minimum Data
Minimum Access
Minimum Retention
Minimum Sharing
Minimum Context
Minimum Memory
Minimum Logging
     |
     v
Controlled Expansion
     |
     v
Explicit Authorization
```

Any expansion beyond the baseline should be justified, authorized, and traceable.

---

### 50. Core Principle of Privacy by Default for AI

**Privacy by Default for AI means that an AI system should begin and remain in a privacy-protective state unless a specific, justified, authorized requirement permits broader processing.**

The default operating state should minimize unnecessary:

* Personal-data collection
* Data access
* Context
* Memory
* Retrieval
* Tool permissions
* Agent authority
* Provider sharing
* Retention
* Logging
* External disclosure

The fundamental principles are:

**Default access ≠ unrestricted access.**

**Data availability ≠ permission to process.**

**Technical capability ≠ authorized capability.**

**Model capability ≠ privacy authority.**

**Model output ≠ authorization.**

**Retrieval capability ≠ retrieval authorization.**

**Memory capability ≠ permission to retain.**

**Tool capability ≠ data-access authorization.**

**Agent capability ≠ agent authority.**

**Provider capability ≠ permission to process personal data.**

**User choice ≠ privacy-protective default.**

**Configuration availability ≠ authorized configuration.**

**Encryption ≠ Privacy by Default.**

**Privacy by Design ≠ Privacy by Default.**

**Privacy-protective configuration ≠ permanent privacy assurance.**

**A privacy default is effective only when it is technically enforced, resistant to unauthorized modification, observable, testable, attributable, and continuously reassessed as the AI system, data, processing purpose, providers, and operating environment change.**
