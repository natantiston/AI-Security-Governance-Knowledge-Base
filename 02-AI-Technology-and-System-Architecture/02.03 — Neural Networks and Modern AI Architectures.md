# 02.03 — Neural Networks and Modern AI Architectures

## Part 1 — Neural Network Foundations and Core Concepts

### 01. Introduction to Neural Networks

Neural networks are computational models inspired loosely by the structure and behavior of biological neural systems.

In modern AI, neural networks are among the primary technologies used to build systems for:

* Image recognition
* Speech recognition
* Natural language processing
* Recommendation systems
* Fraud detection
* Cybersecurity analytics
* Generative AI
* Large language models
* Autonomous systems

For an AI GRC professional, the objective is **not** to become a neural-network engineer.

The objective is to understand enough about neural networks to answer questions such as:

* What is the system actually doing?
* What data does it require?
* Where can failures occur?
* What can be attacked?
* What needs to be governed?
* What evidence should exist?
* What risks increase when architectures become more complex?

---

## 02. Biological Inspiration

The term "neural network" comes from the conceptual analogy with biological neurons.

A biological neuron receives signals, processes them, and produces a response.

An artificial neural network similarly:

```text
Inputs
  ↓
Processing
  ↓
Output
```

However, artificial neural networks are mathematical and computational systems. They should not be assumed to reproduce the actual operation of the human brain.

---

## 03. Artificial Neuron

The fundamental conceptual building block of a neural network is the artificial neuron.

A simplified neuron receives multiple inputs:

```text
x₁ ──┐
x₂ ──┤
x₃ ──┼──→ [ Neuron ] ──→ Output
x₄ ──┤
x₅ ──┘
```

The neuron combines the inputs using numerical parameters called **weights**.

---

## 04. Weighted Inputs

Each input is associated with a weight.

Conceptually:

```text
x₁ × w₁
x₂ × w₂
x₃ × w₃
     ↓
   Sum
```

The weights determine how strongly individual inputs influence the result.

For a simple neuron:

[
z = w_1x_1 + w_2x_2 + ... + w_nx_n + b
]

where:

* (x) = input
* (w) = weight
* (b) = bias
* (z) = pre-activation value

---

## 05. Bias

A bias is an additional learned parameter that shifts the neuron's activation.

The simplified equation is:

[
z = wx + b
]

Without a bias term, the model's flexibility can be unnecessarily restricted.

In governance terms, the important point is that **weights and biases are learned model parameters** and therefore form part of the model artifact that needs appropriate protection and version control.

---

## 06. Activation Function

The result of the weighted calculation is passed through an activation function.

```text
Inputs
  ↓
Weighted Sum
  ↓
Activation Function
  ↓
Neuron Output
```

Activation functions allow neural networks to model nonlinear relationships.

Without nonlinear activation functions, stacking many linear layers would still result in a fundamentally linear transformation.

---

## 07. Common Activation Functions

Common activation functions include:

* Sigmoid
* Tanh
* ReLU
* Leaky ReLU
* GELU
* Softmax

Different architectures use different activation functions depending on their purpose.

---

## 08. Sigmoid

The sigmoid function produces an output between 0 and 1.

[
\sigma(x)=\frac{1}{1+e^{-x}}
]

Conceptually:

```text
Large negative → close to 0
       0       → around 0.5
Large positive → close to 1
```

Sigmoid can be useful for binary classification outputs.

---

## 09. Tanh

The hyperbolic tangent function produces values between approximately -1 and +1.

[
\tanh(x)
]

It was historically common in neural-network architectures, particularly recurrent networks.

Modern architectures often use other activation functions instead.

---

## 10. ReLU

ReLU stands for **Rectified Linear Unit**.

It is commonly represented as:

[
ReLU(x)=\max(0,x)
]

Conceptually:

```text
Negative input → 0
Positive input → input
```

ReLU became highly important in deep-learning architectures because it is computationally simple and can help neural networks learn efficiently.

---

## 11. GELU

GELU stands for **Gaussian Error Linear Unit**.

It is commonly used in modern transformer-based architectures.

GELU provides a smooth nonlinear transformation rather than the hard cutoff used by ReLU.

This becomes particularly relevant when studying:

* Transformers
* Foundation models
* Large language models

---

## 12. Softmax

Softmax converts a vector of values into a probability-like distribution whose elements sum to 1.

For example:

```text
Before Softmax

Cat       3.2
Dog       1.8
Bird      0.4

        ↓

After Softmax

Cat       0.75
Dog       0.18
Bird      0.07
```

Softmax is commonly associated with multiclass classification outputs.

---

## 13. Neuron Output

The complete simplified neuron can therefore be represented as:

```text
Inputs
 │
 ├── x₁ × w₁
 ├── x₂ × w₂
 ├── x₃ × w₃
 └── x₄ × w₄
       ↓
 Weighted Sum
       +
     Bias
       ↓
 Activation Function
       ↓
    Output
```

A neural network combines many such computational units.

---

## 14. Layers

Neural networks are organized into layers.

A basic network contains:

```text
Input Layer
     ↓
Hidden Layer
     ↓
Output Layer
```

More complex networks may contain hundreds or even thousands of computational layers or transformation stages, depending on how the architecture is defined.

---

## 15. Input Layer

The input layer represents the information provided to the model.

Examples include:

### Image

```text
Pixels
 ↓
Input Layer
```

### Text

```text
Tokens
 ↓
Input Representation
```

### Fraud Detection

```text
Transaction Features
 ↓
Input Layer
```

The input representation is therefore strongly dependent on the application.

---

## 16. Hidden Layers

Hidden layers perform intermediate transformations.

For example:

```text
Input
 ↓
Hidden Layer 1
 ↓
Hidden Layer 2
 ↓
Hidden Layer 3
 ↓
Output
```

The internal representations learned by these layers are often not directly understandable to humans.

This is one reason neural networks can present explainability challenges.

---

## 17. Output Layer

The output layer produces the model's final output.

Examples include:

```text
Classification → Class
Regression → Number
Detection → Objects
Language Model → Token probabilities
```

The output structure depends on the task.

---

## 18. Deep Neural Networks

A neural network with multiple hidden layers is commonly called a **deep neural network (DNN)**.

Conceptually:

```text
Input
 ↓
Layer 1
 ↓
Layer 2
 ↓
Layer 3
 ↓
Layer 4
 ↓
Layer 5
 ↓
Output
```

The term "deep learning" largely refers to the use of such multi-layer neural networks.

---

## 19. Why Depth Matters

Additional layers allow the network to learn increasingly complex representations.

For example, in image recognition:

```text
Pixels
 ↓
Edges
 ↓
Shapes
 ↓
Parts
 ↓
Objects
 ↓
Classification
```

The exact internal representations are learned rather than manually programmed.

---

## 20. Representation Learning

One of the major advantages of neural networks is their ability to learn representations from data.

Traditional machine learning may depend heavily on manually designed features.

Neural networks can learn useful representations automatically.

Conceptually:

```text
Raw Data
   ↓
Neural Network
   ↓
Learned Representation
   ↓
Prediction
```

This is called **representation learning**.

---

## 21. Parameters

Neural networks contain parameters that are learned during training.

The most important parameters are:

* Weights
* Biases

A modern neural network may contain millions, billions, or even trillions of parameters.

The number of parameters is an important technical characteristic, but it does not by itself determine model quality.

---

## 22. Hyperparameters

Hyperparameters are configuration values chosen by developers or training processes rather than directly learned as model weights.

Examples include:

* Learning rate
* Batch size
* Number of layers
* Number of training epochs
* Optimizer
* Dropout rate
* Architecture configuration

This distinction is important:

```text
Parameters
     ↓
Learned from data

Hyperparameters
     ↓
Configured during development
```

---

## 23. Parameters vs. Hyperparameters

A useful GRC distinction is:

| Parameter               | Hyperparameter                    |
| ----------------------- | --------------------------------- |
| Learned during training | Configured before/during training |
| Weight                  | Learning rate                     |
| Bias                    | Batch size                        |
| Model coefficients      | Number of layers                  |
| Part of trained model   | Training configuration            |

Both can affect model behavior and therefore may need version control.

---

## 24. Training a Neural Network

Training involves repeatedly exposing the network to data and adjusting its parameters.

Simplified:

```text
Training Data
     ↓
Neural Network
     ↓
Prediction
     ↓
Loss
     ↓
Parameter Update
     ↓
Repeat
```

The objective is to reduce the difference between model predictions and desired outcomes.

---

## 25. Forward Pass

During a forward pass, information flows from the input through the network toward the output.

```text
Input
 ↓
Layer 1
 ↓
Layer 2
 ↓
Layer 3
 ↓
Output
```

The network generates a prediction.

---

## 26. Loss Function

The model's prediction is compared against the expected result using a loss function.

Conceptually:

```text
Prediction
     ↓
Compare
     ↑
Expected Result
     ↓
Loss
```

The loss represents how poorly the model performed for that training example or batch.

---

## 27. Common Loss Functions

Examples include:

* Mean Squared Error
* Mean Absolute Error
* Binary Cross-Entropy
* Categorical Cross-Entropy

The appropriate loss function depends on the learning problem.

---

## 28. Backpropagation

Backpropagation calculates how model parameters contributed to the error.

Conceptually:

```text
Forward Pass
     ↓
Prediction
     ↓
Loss
     ↓
Backward Pass
     ↓
Gradients
     ↓
Parameter Updates
```

Backpropagation is fundamental to modern neural-network training.

---

## 29. Gradient

A gradient indicates how changing parameters affects the loss.

The training process uses gradients to determine how parameters should be adjusted.

Conceptually:

```text
Current Parameters
        ↓
Calculate Gradient
        ↓
Determine Direction
        ↓
Update Parameters
```

---

## 30. Gradient Descent

Gradient descent is an optimization method used to minimize the loss function.

A simplified update can be represented as:

[
\theta_{new} = \theta_{old} - \eta \nabla L(\theta)
]

where:

* (\theta) = model parameters
* (\eta) = learning rate
* (L) = loss
* (\nabla L) = gradient

The important governance concept is that training is an **optimization process**, not a deterministic process of manually programming rules.

---

## 31. Learning Rate

The learning rate controls the size of parameter updates.

Conceptually:

```text
Very Small Learning Rate
→ Slow Learning

Very Large Learning Rate
→ Unstable / Overshooting

Appropriate Learning Rate
→ More Effective Optimization
```

The learning rate is therefore an important training hyperparameter.

---

## 32. Batch

A batch is a group of training examples processed together.

For example:

```text
Dataset
 ↓
Batch 1
Batch 2
Batch 3
Batch 4
```

Batch size affects:

* Memory requirements
* Training speed
* Optimization behavior

---

## 33. Epoch

An epoch represents one complete pass through the training dataset.

For example:

```text
Dataset
 ↓
Epoch 1
 ↓
Epoch 2
 ↓
Epoch 3
```

Training may involve many epochs.

Too few epochs can result in undertraining, while too many can contribute to overfitting.

---

## 34. Overfitting

Overfitting occurs when a model learns the training data too closely and performs poorly on new data.

Conceptually:

```text
Training Performance
       ↑
       │
       │       Excellent
       │
       │
       └──────────────→
             Test Performance
             Poor
```

A model that memorizes training examples may not generalize effectively.

---

## 35. Underfitting

Underfitting occurs when a model is too simple or insufficiently trained to capture important patterns.

Conceptually:

```text
Training Performance → Poor
Testing Performance  → Poor
```

The model has not learned enough from the data.

---

## 36. Generalization

Generalization refers to the ability of a model to perform well on previously unseen data.

This is one of the central objectives of machine learning.

```text
Training Data
     ↓
Learning
     ↓
Model
     ↓
Previously Unseen Data
     ↓
Useful Predictions
```

Strong training performance alone does not demonstrate strong generalization.

---

## 37. Regularization

Regularization techniques can reduce overfitting.

Examples include:

* L1 regularization
* L2 regularization
* Dropout
* Early stopping
* Data augmentation

These techniques constrain or modify training to improve generalization.

---

## 38. Dropout

Dropout temporarily disables a subset of neurons during training.

Conceptually:

```text
Layer
○ ○ ○ ○ ○ ○
 \  X  / X
  ↓
Randomly dropped units
```

This can reduce excessive dependence on particular neurons and help generalization.

---

## 39. Batch Normalization

Batch normalization normalizes intermediate activations during training.

It can help stabilize and accelerate training in certain architectures.

From a GRC perspective, it is primarily an engineering detail, but configuration changes involving such components can still affect model behavior.

---

## 40. Neural Network Initialization

Training usually begins with initialized parameter values.

Initialization can influence:

* Training stability
* Convergence
* Performance

Modern frameworks provide initialization strategies designed for different architectures.

---

## 41. Weight Updates

During training, weights are repeatedly updated.

Conceptually:

```text
Initial Weights
      ↓
Forward Pass
      ↓
Loss
      ↓
Backpropagation
      ↓
Updated Weights
      ↓
Repeat
```

The final weights become part of the trained model.

---

## 42. Convergence

Training is often considered to converge when optimization reaches a satisfactory region where further updates produce relatively small improvements.

However, convergence does not necessarily mean that the model is:

* Correct
* Fair
* Secure
* Robust
* Appropriate for production

This distinction is highly important for GRC.

---

## 43. Training Success vs. Governance Success

A model can successfully converge while still presenting significant risks.

For example:

```text
Training Converges
       ↓
High Accuracy
       ↓
BUT
       ↓
Sensitive Data Exposure
       ↓
Security Risk
```

Technical success and governance success are therefore different concepts.

---

## 45. Binary Classification

Binary classification has two primary classes.

Examples:

```text
Fraud / Not Fraud
Malware / Benign
Spam / Not Spam
```

The output may be represented as a probability.

## 46. Multiclass Classification

Multiclass classification selects among multiple categories.

For example:

```text
Network Traffic
       ↓
Normal
Malware
Phishing
Scanning
Command-and-Control
```

The output may provide a score or probability for each category.

## 47. Multilabel Classification

In multilabel classification, one input can belong to multiple categories simultaneously.

For example:

```text
Document
 ↓
Finance
Confidential
Legal
Customer Data
```

This differs from multiclass classification, where the model typically chooses one class from a set.

## 48. Regression

Regression predicts a numerical quantity.

Examples include:

* Revenue
* Temperature
* Risk score
* Demand
* Probability estimate

A neural network can therefore be used for both classification and numerical prediction.

## 49. Neural Network Inputs

Inputs may be:

* Numerical values
* Categorical values
* Images

* Text
* Time series

Different data types often require different architectures or preprocessing techniques.

## 50. Neural Network Architecture

An architecture defines how computational components are organized.

A basic architecture can be represented as:

```text
Input
  ↓
Dense Layer
  ↓
Dense Layer
  ↓
Output
```

Modern architectures can be significantly more complex.

Examples include:

* Convolutional Neural Networks
* Recurrent Neural Networks
* Transformers
* Autoencoders
* Generative Adversarial Networks
* Graph Neural Networks

---

## 51. Fully Connected / Dense Networks

In a fully connected layer, each neuron in one layer is connected to neurons in the next layer.

Conceptually:

```text
○ ○ ○
|\|/|
|/|\|
○ ○ ○
|\|/|
|/|\|
○ ○ ○
```

These networks are useful for many structured-data problems but may be inefficient for certain high-dimensional data types.

---

## 52. Convolutional Neural Networks

Convolutional Neural Networks, or **CNNs**, are particularly important for spatial data such as images.

A simplified architecture:

```text
Image
 ↓
Convolution
 ↓
Activation
 ↓
Pooling
 ↓
Convolution
 ↓
Classification
```

CNNs can learn spatial patterns such as:

```text
Edges
 ↓
Shapes
 ↓
Objects
```

---

## 53. Recurrent Neural Networks

Recurrent Neural Networks, or **RNNs**, were designed to process sequential information.

Examples include:

* Time series
* Speech
* Text

A simplified concept is:

```text
Input₁ → State₁
           ↓
Input₂ → State₂
           ↓
Input₃ → State₃
```

The state carries information from earlier steps.

---

## 54. Long Short-Term Memory

**LSTM**, or Long Short-Term Memory, is a type of recurrent architecture designed to better handle longer-term dependencies.

LSTMs introduced gating mechanisms that help control information flow through the network.

They were historically important in:

* Speech recognition
* Language processing
* Time-series analysis

---

## 55. Gated Recurrent Units

**GRU**, or Gated Recurrent Unit, is another recurrent architecture.

GRUs use gating mechanisms while generally having a simpler structure than LSTMs.

Both LSTM and GRU are examples of architectures designed to handle sequential dependencies.

---

## 56. Autoencoders

An autoencoder learns to reconstruct its input.

Conceptually:

```text
Input
 ↓
Encoder
 ↓
Latent Representation
 ↓
Decoder
 ↓
Reconstructed Input
```

Applications may include:

* Dimensionality reduction
* Anomaly detection
* Representation learning
* Data reconstruction

---

## 57. Generative Adversarial Networks

A **Generative Adversarial Network (GAN)** contains two competing components:

```text
Generator
    ↓
Creates Samples
    ↓
Discriminator
    ↓
Evaluates Samples
```

The generator attempts to create realistic samples while the discriminator attempts to distinguish generated samples from real ones.

GANs have been used for:

* Image generation
* Synthetic data
* Image transformation

---

## 58. Graph Neural Networks

Graph Neural Networks, or **GNNs**, operate on graph-structured data.

A graph consists of:

```text
Nodes
 +
Edges
```

Examples include:

* Social networks
* Network topology
* Fraud relationships
* Knowledge graphs
* Recommendation systems

GNNs can learn representations based on relationships between entities.

---

## 61. Neural Network Explainability

Neural networks are often described as "black boxes" because their internal decision process can be difficult to interpret.

The problem is not necessarily that the model is completely impossible to analyze.

Rather, the relationship between:

```text
Input
  ↓
Millions/Billions of Parameters
  ↓
Intermediate Representations
  ↓
Output
```

can be difficult for humans to understand directly.

---

## 62. Explainability vs. Interpretability

These terms are related but should not be treated as identical.

**Interpretability** generally concerns how inherently understandable a model or mechanism is.

**Explainability** generally concerns methods used to provide understandable explanations of model behavior.

The distinction becomes important when designing AI governance requirements.

---

## 63. Neural Network Robustness

Robustness refers broadly to the ability of a model to maintain acceptable behavior under changes or disturbances.

Potential disturbances include:

* Noisy data
* Distribution changes
* Unexpected inputs
* Adversarial manipulation
* Environmental changes

Robustness testing is therefore relevant to model assurance.

When reviewing a neural-network system, the GRC professional should ask:

1. What type of neural network is being used?
2. Why was this architecture selected?
3. What data is being used?
4. What parameters does the model contain?
5. What hyperparameters were selected?
6. How was the model trained?
7. How was overfitting evaluated?
8. What validation was performed?
9. What are the known limitations?
10. What security threats were considered?
11. How is the model version controlled?

## 68. Core Takeaway

The most important concept from this part is that a neural network is **not simply an algorithm that produces an answer**.

It is a layered computational system whose behavior emerges from:

* Architecture
* Data
* Parameters
* Training process
* Optimization
* Learned representations
* Inputs

## 70. Feedforward Neural Networks

A feedforward neural network is one of the simplest neural-network architectures.

Information moves in one direction:

```text
Input
  ↓
Layer 1
  ↓
Layer 2
  ↓
Layer 3
  ↓
Output
```

There are no explicit feedback loops in the basic architecture.

Feedforward networks are commonly used for:

* Classification
* Regression
* Structured-data prediction

---

## 71. Multilayer Perceptron

A **Multilayer Perceptron (MLP)** is a common type of feedforward neural network.

A simplified MLP consists of:

```text
Input Layer
     ↓
Dense Layer
     ↓
Dense Layer
     ↓
Output Layer
```

Each layer contains neurons connected to neurons in the following layer.

MLPs remain useful even though more specialized architectures dominate many modern AI applications.

---

## 72. Why Specialized Architectures Matter

Different types of data have different structural characteristics.

For example:

| Data         | Important Structure                 |
| ------------ | ----------------------------------- |
| Tabular data | Feature relationships               |
| Image        | Spatial relationships               |
| Audio        | Temporal/frequency relationships    |
| Text         | Sequential/contextual relationships |
| Graph        | Relationships between entities      |
| Video        | Spatial + temporal relationships    |

Specialized architectures attempt to exploit these characteristics.

---

## 73. Convolutional Neural Networks

A **Convolutional Neural Network (CNN)** is designed particularly for spatial data.

Images are an important example.

A simplified CNN:

```text
Image
  ↓
Convolution
  ↓
Activation
  ↓
Pooling
  ↓
Convolution
  ↓
Activation
  ↓
Pooling
  ↓
Classification
```

CNNs became foundational in computer vision.

---

## 74. Convolution Operation

A convolution applies a small numerical filter, often called a kernel, across an input.

Conceptually:

```text
Image
████████
████████
████████
████████

     ↓

Kernel
██
██

     ↓

Feature Map
████
████
```

The operation allows the network to identify local patterns.

## 75. CNN Feature Detection

Different layers can learn increasingly complex visual features.

For example:

```text
Early Layers
     ↓
Edges
     ↓
Textures
     ↓
Shapes
     ↓
Object Parts
     ↓
```

The network learns these representations from training data rather than requiring every feature to be manually programmed.

## 76. Pooling

Pooling reduces the spatial dimensions of feature maps.

Common approaches include:

* Max pooling
* Average pooling

Conceptually:

```text
Large Feature Map
       ↓
    Pooling
       ↓
Smaller Feature Map
```

Pooling can reduce computational requirements and provide some degree of spatial invariance.

* Adversarial examples
* Training-data poisoning
* Data-quality problems
* Distribution changes
* Model extraction

For example, a computer-vision security system could potentially be manipulated by specially crafted inputs.

* How are images protected?
* How is the model validated?
* What happens when the camera fails?
* What happens when the model is uncertain?
* Can a human override the decision?

---

## 79. Recurrent Neural Networks

RNNs were designed to process sequential information.

Unlike a basic feedforward network, an RNN maintains an internal state.

Conceptually:

```text
Input₁ → State₁
           ↓
Input₂ → State₂
           ↓
Input₃ → State₃
           ↓
Input₄ → State₄
```

Earlier information can influence later processing.

---

## 80. Sequential Data

RNNs can be useful when order matters.

Examples include:

* Speech
* Text
* Sensor readings
* Time series
* Network events

For example:

```text
Event 1
   ↓
Event 2
   ↓
Event 3
   ↓
Event 4
```

The sequence itself contains information.

---

## 81. Recurrent State

The recurrent state provides a mechanism for carrying information from previous steps.

A simplified representation is:

[
h_t = f(x_t,h_{t-1})
]

where:

* (x_t) = current input
* (h_{t-1}) = previous state
* (h_t) = current state

This allows the model to incorporate previous information.

---

## 82. The Long-Sequence Problem

Traditional RNNs can have difficulty retaining information over long sequences.

This is related to problems involving:

* Vanishing gradients
* Exploding gradients
* Long-term dependencies

These limitations motivated architectures such as LSTM and GRU.

---

## 83. LSTM Architecture

An LSTM uses gates to control information flow.

A simplified representation is:

```text
Previous State
      ↓
 ┌──────────────┐
 │ LSTM Cell    │
 │              │
 │ Input Gate   │
 │ Forget Gate  │
 │ Output Gate  │
 └──────────────┘
      ↓
Current State
```

The gates help determine what information should be:

* Retained
* Forgotten
* Added
* Exposed

---

## 84. GRU Architecture

A GRU is another gated recurrent architecture.

Compared with LSTM, it generally uses fewer gating components.

Both architectures attempt to improve the ability of recurrent systems to capture longer-term dependencies.

---

## 85. RNNs vs. Transformers

Transformers changed modern sequence processing substantially.

A simplified comparison:

| RNN                                 | Transformer                                 |
| ----------------------------------- | ------------------------------------------- |
| Sequential processing               | Highly parallelizable                       |
| Recurrent state                     | Attention-based                             |
| Historical dependency through state | Direct attention relationships              |
| Can struggle with long dependencies | Better handling of long-range relationships |
| Historically important for NLP      | Dominant in modern foundation models        |

This transition is extremely important for understanding modern AI.

---

## 86. Attention Mechanism

Attention allows a model to determine which parts of an input are particularly relevant when processing another part.

For example:

```text
"The company released a new model because it was successful."
```

When interpreting "it", the model may need to determine which earlier word or concept is relevant.

Attention provides a mechanism for relating different elements of the sequence.

---

## 87. Self-Attention

Self-attention allows elements within the same sequence to interact with one another.

Conceptually:

```text
Token 1 ───────┐
Token 2 ───────┼──→ Attention Relationships
Token 3 ───────┤
Token 4 ───────┘
```

Each token can consider information from other tokens.

---

## 88. Query, Key and Value

Self-attention commonly uses three representations:

* Query
* Key
* Value

Conceptually:

```text
Input
 ↓
Query
Key
Value
 ↓
Attention Calculation
 ↓
Weighted Information
```

The mathematical formulation commonly includes:

[
Attention(Q,K,V)
================

softmax\left(\frac{QK^T}{\sqrt{d_k}}\right)V
]

For GRC purposes, the important idea is that the model computes relationships between elements of the input.

---

## 89. Attention Scores

Attention produces scores indicating how strongly one element should consider another.

Conceptually:

```text
Token A
   ↓
Which tokens are relevant?
   ↓
Token B → High attention
Token C → Low attention
Token D → Medium attention
```

These relationships are learned during training.

---

## 90. Why Attention Matters

Attention allows models to capture relationships across a sequence without requiring information to pass through a single recurrent state.

This became one of the key reasons transformers became dominant in modern language AI.

---

## 91. Transformer Architecture

A simplified transformer architecture can be represented as:

```text
Input Tokens
     ↓
Token Embeddings
     ↓
Positional Information
     ↓
Self-Attention
     ↓
Feed-Forward Network
     ↓
Normalization
     ↓
Repeated Transformer Blocks
     ↓
Output
```

Real implementations can be substantially more complex.

---

## 92. Transformer Block

A typical transformer block contains components such as:

```text
Input
  ↓
Self-Attention
  ↓
Residual Connection
  ↓
Normalization
  ↓
Feed-Forward Network
  ↓
Residual Connection
  ↓
Normalization
  ↓
Output
```

Many transformer blocks are stacked together.

---

## 93. Residual Connections

Residual connections provide a shortcut around a transformation.

Conceptually:

```text
        ┌───────────────┐
        │               ↓
Input ──┼──→ Layer ──→ Add ──→ Output
        │
        └───────────────┘
```

They help deep networks train effectively.

Residual connections are now common in modern deep architectures.

---

## 94. Layer Normalization

Normalization techniques help stabilize neural-network computations.

Transformers commonly use **layer normalization**.

Normalization is an engineering mechanism, but changes to normalization architecture can affect:

* Training behavior
* Performance
* Stability

Therefore, architecture changes should be governed appropriately.

---

## 95. Positional Information

Self-attention by itself does not inherently provide the order of tokens.

Transformers therefore use mechanisms for representing position.

These may include:

* Positional encodings
* Learned position embeddings
* Rotary positional embeddings
* Other positional mechanisms

This allows the model to distinguish different token positions.

---

## 96. Encoder Architecture

A transformer encoder processes input representations and produces contextualized representations.

Conceptually:

```text
Input
 ↓
Embedding
 ↓
Encoder Block
 ↓
Encoder Block
 ↓
Encoder Block
 ↓
Contextual Representation
```

Encoder architectures are useful for tasks such as:

* Classification
* Representation learning
* Information extraction

---

## 97. Decoder Architecture

A transformer decoder generates or processes output sequences.

Conceptually:

```text
Context
 ↓
Decoder
 ↓
Token
 ↓
Next Token
 ↓
Next Token
```

Decoder architectures are fundamental to autoregressive language models.

---

## 98. Encoder-Decoder Architecture

An encoder-decoder architecture combines both components.

```text
Input
  ↓
Encoder
  ↓
Representation
  ↓
Decoder
  ↓
Output
```

This architecture became particularly important for:

* Translation
* Summarization
* Sequence-to-sequence tasks

---

## 99. Autoregressive Generation

An autoregressive model predicts the next token based on previous tokens.

For example:

```text
"The security team"
        ↓
"The security team identified"
        ↓
"The security team identified a"
        ↓
"The security team identified a vulnerability"
```

The generation process occurs token by token.

---

## 100. Causal Attention

In autoregressive language models, a token generally should not attend to future tokens during generation.

A causal mask prevents access to future positions.

Conceptually:

```text
Token 1 → Token 1
Token 2 → Token 1, Token 2
Token 3 → Token 1, Token 2, Token 3
Token 4 → Token 1, Token 2, Token 3, Token 4
```

This preserves the directionality required for next-token prediction.

---

## 101. Bidirectional Attention

Some transformer models allow tokens to use information from both earlier and later positions.

Conceptually:

```text
Token 1 ↔ Token 2 ↔ Token 3 ↔ Token 4
```

This can be valuable for contextual representation tasks.

The architectural choice depends on the intended use.

---

## 102. Encoder-Only Models

Encoder-only transformer models are commonly used for understanding and representation tasks.

Examples of tasks include:

* Classification
* Similarity
* Entity recognition
* Search representation

They are different from autoregressive generation models.

---

## 103. Decoder-Only Models

Decoder-only transformers are commonly used for autoregressive generation.

They form the architectural foundation of many modern large language models.

Conceptually:

```text
Prompt
 ↓
Transformer Decoder Stack
 ↓
Next-Token Probabilities
 ↓
Generated Output
```

---

## 104. Encoder-Decoder Models

Encoder-decoder models process an input and generate a related output.

For example:

```text
English Text
    ↓
Encoder
    ↓
Representation
    ↓
Decoder
    ↓
Spanish Text
```

This makes them particularly useful for sequence-to-sequence tasks.

## 113. Mixture-of-Experts

The router determines which experts process a particular input.

## 114. Sparse Activation

In some MoE architectures, only a subset of experts is activated for a particular input.

This distinction is important:


## Part 3 — Transformers, Attention, and Modern Model Design

### 151. Why Transformers Changed AI

The transformer architecture represents one of the most significant developments in modern artificial intelligence.

Before transformers, many language and sequence-processing systems relied heavily on recurrent architectures such as:

* RNNs
* LSTMs
* GRUs

Transformers introduced a fundamentally different mechanism for handling relationships between elements of a sequence: **attention**.

This enabled highly scalable architectures that became the foundation for many:

* Foundation models
* Large language models
* Generative AI systems
* Multimodal models
* AI assistants

---

## 152. The Transformer at a High Level

A simplified transformer can be represented as:

```text
Input
  ↓
Tokenization
  ↓
Embeddings
  ↓
Positional Information
  ↓
Transformer Blocks
  │
  ├── Attention
  ├── Feed-Forward Network
  ├── Normalization
  └── Residual Connections
  ↓
Output Representation
  ↓
Prediction / Generation
```

A real production architecture may contain many additional components.

---

## 153. Transformer Blocks

A transformer is normally constructed by stacking multiple transformer blocks.

Conceptually:

```text
Input
  ↓
Transformer Block 1
  ↓
Transformer Block 2
  ↓
Transformer Block 3
  ↓
...
  ↓
Transformer Block N
  ↓
Output
```

Each block transforms the representation of the input.

The repeated transformations allow increasingly complex contextual representations to emerge.

---

## 154. What Does a Transformer Learn?

A transformer does not simply memorize individual sentences.

During training, it learns statistical relationships between representations.

For language models, these relationships may include:

* Syntax
* Semantic relationships
* Context
* Patterns
* Associations
* Long-range dependencies

The resulting model can use those learned representations to predict or generate outputs.

---

## 155. Tokens

Language models generally do not process raw text directly.

Text is converted into **tokens**.

For example:

```text
"Cybersecurity governance"
        ↓
Tokenization
        ↓
["Cyber", "security", " governance"]
```

The exact tokenization depends on the model and tokenizer.

Tokens may represent:

* Whole words
* Subwords
* Characters
* Punctuation
* Special symbols

---

## 156. Token IDs

Tokens are mapped to numerical identifiers.

Conceptually:

```text
Text
 ↓
Tokenizer
 ↓
Tokens
 ↓
Token IDs
 ↓
Neural Network
```

For example:

```text
"security"
      ↓
Token
      ↓
ID: 12345
```

The actual ID is model-specific.

---

## 157. Vocabulary

A tokenizer has a vocabulary containing the tokens it recognizes.

The vocabulary can contain:

* Words
* Subwords
* Numbers
* Punctuation
* Special tokens

Vocabulary design affects how text is represented and processed.

---

## 158. Embeddings

Token IDs themselves do not contain meaningful semantic information.

They are mapped into numerical vectors called **embeddings**.

Conceptually:

```text
Token ID
   ↓
Embedding Lookup
   ↓
Vector
   ↓
[0.12, -0.45, 0.87, ...]
```

These vectors provide the neural network with a richer representation.

Embeddings will be examined in detail in **02.09 — Embeddings and Representation Models**.

---

## 159. Contextual Representation

A major feature of transformer models is that token representations can become contextual.

For example, the word:

```text
"bank"
```

can have different meanings in:

```text
"I deposited money at the bank."

"The boat reached the river bank."
```

The surrounding context influences the resulting representation.

---

## 160. Self-Attention Revisited

Self-attention allows each token to consider other tokens in the sequence.

Conceptually:

```text
Token 1 ────────┐
Token 2 ────────┤
Token 3 ────────┼──→ Attention
Token 4 ────────┤
Token 5 ────────┘
```

The model calculates relationships between tokens.

---

## 161. Query, Key, and Value

Each input representation is transformed into:

```text
Query
Key
Value
```

Conceptually:

```text
Input Representation
       │
       ├──→ Query
       ├──→ Key
       └──→ Value
```

These transformations are produced using learned parameters.

---

## 162. Query

A **query** represents what the current token is looking for in the context.

Conceptually:

```text
Current Token
     ↓
"What information is relevant to me?"
     ↓
Query
```

This is a conceptual interpretation rather than a literal human-readable question.

---

## 163. Key

A **key** represents information used to determine how relevant another token may be.

Conceptually:

```text
Token Representation
       ↓
Key
       ↓
"How relevant am I to this query?"
```

---

## 164. Value

The **value** contains the information that is actually incorporated once attention determines relevance.

Conceptually:

```text
Key → Determines Relevance
Value → Provides Information
```

This distinction is important for understanding attention.

---

## 165. Attention Calculation

A simplified attention mechanism is:

[
Attention(Q,K,V)
================

softmax
\left(
\frac{QK^T}{\sqrt{d_k}}
\right)V
]

The process can be viewed as:

```text
Q × K
  ↓
Similarity Scores
  ↓
Scaling
  ↓
Softmax
  ↓
Attention Weights
  ↓
Weighted Values
  ↓
Output
```

---

## 166. Why Scale by √dₖ?

The scaling factor:

[
\sqrt{d_k}
]

helps prevent the dot-product values from becoming excessively large as the dimensionality increases.

Without appropriate scaling, the softmax function can become too concentrated and make optimization more difficult.

This is an implementation detail, but it explains part of why attention works effectively.

---

## 167. Attention Weights

Attention produces weights representing the relative importance of different elements.

Conceptually:

```text
Query: Token A

Token B → 0.60
Token C → 0.25
Token D → 0.10
Token E → 0.05
```

The model can therefore emphasize some contextual information more strongly than others.

---

## 168. Attention Is Not a Human Explanation

This distinction is critical for AI governance.

It is tempting to assume:

> "The token with the highest attention score explains why the model made its decision."

That conclusion is generally too simplistic.

Attention weights describe part of the model's internal computation. They should not automatically be treated as complete causal explanations.

---

## 169. Multi-Head Attention

Transformers commonly use **multi-head attention**.

Instead of one attention mechanism:

```text
Input
 ↓
Attention
 ↓
Output
```

multiple attention heads operate in parallel:

```text
             ┌→ Head 1 ─┐
Input ───────┼→ Head 2 ─┼→ Combine
             ├→ Head 3 ─┤
             └→ Head 4 ─┘
```

Each head can learn different relationships.

---

## 170. Why Multiple Heads?

Different attention heads can potentially capture different types of relationships.

For example:

```text
Head 1 → Syntax
Head 2 → Local relationships
Head 3 → Long-range relationships
Head 4 → Semantic relationships
```

These interpretations are illustrative rather than fixed rules.

The model learns the representations during training.

---

## 171. Concatenation of Attention Heads

The outputs of multiple attention heads are generally combined.

Conceptually:

```text
Head 1 ─┐
Head 2 ─┤
Head 3 ─┼→ Concatenate → Linear Transformation
Head 4 ─┘
```

The resulting representation becomes the output of the multi-head attention layer.

---

## 172. Feed-Forward Network

After attention, transformer blocks typically contain a feed-forward network.

A simplified structure is:

```text
Attention Output
      ↓
Linear Transformation
      ↓
Activation
      ↓
Linear Transformation
      ↓
Output
```

This component performs additional nonlinear transformation of the representation.

---

## 173. Attention vs. Feed-Forward Processing

A useful conceptual distinction is:

```text
Attention
   ↓
Mixes information between tokens

Feed-Forward Network
   ↓
Transforms each token representation
```

Together, these mechanisms provide powerful representational capacity.

---

## 174. Residual Connections

Transformers commonly use residual connections.

Conceptually:

```text
                 ┌──────────────┐
                 │              ↓
Input ───────────┼→ Attention → Add
                 │              ↓
                 └──────────→ Output
```

The original representation is added to the transformed representation.

This helps information and gradients flow through deep networks.

---

## 175. Layer Normalization

Normalization is used to stabilize the internal representations.

A simplified transformer block may therefore be:

```text
Input
 ↓
Normalization
 ↓
Attention
 ↓
Residual Connection
 ↓
Normalization
 ↓
Feed-Forward Network
 ↓
Residual Connection
 ↓
Output
```

The precise arrangement varies between architectures.

---

## 176. Pre-Normalization vs. Post-Normalization

Transformer designs may place normalization before or after major sublayers.

### Pre-Normalization

```text
Input
 ↓
Norm
 ↓
Attention
 ↓
Residual
```

### Post-Normalization

```text
Input
 ↓
Attention
 ↓
Residual
 ↓
Norm
```

Architectural details such as this can influence training stability and performance.

---

## 177. Positional Information

Attention alone does not inherently encode the order of tokens.

For example:

```text
A B C
```

and

```text
C B A
```

contain the same elements but have different meanings.

Transformers therefore require a mechanism to represent position.

---

## 178. Positional Encodings

One approach is to add positional information to token embeddings.

Conceptually:

```text
Token Embedding
      +
Position Information
      ↓
Transformer Input
```

This provides information about where each token occurs.

---

## 179. Learned Position Embeddings

A model can learn positional representations during training.

Conceptually:

```text
Position 1 → Vector
Position 2 → Vector
Position 3 → Vector
...
```

These vectors become part of the learned model parameters.

---

## 180. Sinusoidal Positional Encoding

The original transformer architecture introduced deterministic sinusoidal positional encodings.

They use mathematical functions based on sine and cosine at different frequencies.

The objective is to provide a structured representation of relative and absolute positions.

---

## 181. Rotary Positional Embeddings

Modern transformer architectures may use **Rotary Positional Embeddings (RoPE)**.

RoPE incorporates positional information by rotating vector representations in a structured mathematical way.

RoPE has become particularly important in many modern language-model architectures.

---

## 182. Context Window

A model's **context window** is the amount of information it can process within a particular inference context.

Conceptually:

```text
┌───────────────────────────────┐
│          Context Window       │
│                               │
│ System Instructions           │
│ User Input                    │
│ Previous Messages             │
│ Retrieved Information         │
│ Tool Results                  │
│                               │
└───────────────────────────────┘
```

The exact context limit varies by model.

---

## 183. Context Length and Risk

A larger context window can enable more information to be processed, but it does not automatically mean:

* Better reasoning
* Better accuracy
* Better security

Large contexts can also introduce:

* More irrelevant information
* Higher computational costs
* Greater information exposure
* More complex prompt-injection opportunities

---

## 184. Attention Complexity

Standard self-attention has computational characteristics that can become expensive as sequence length increases.

The attention matrix compares tokens against other tokens.

For a sequence of length (n), the attention relationship matrix is approximately:

[
n \times n
]

This means the number of pairwise relationships grows approximately quadratically with sequence length.

---

## 185. Long-Context Challenges

As context grows:

```text
Short Context
     ↓
Moderate Computation

Long Context
     ↓
More Attention Relationships
     ↓
More Memory / Compute
```

This creates architectural and operational challenges.

Modern systems use various techniques to improve long-context efficiency.

---

## 186. KV Cache

During autoregressive inference, models can cache previously calculated **keys and values**.

This is called the **KV cache**.

Conceptually:

```text
Previous Tokens
      ↓
Cached K/V
      ↓
New Token
      ↓
Attention
      ↓
Next Token
```

KV caching can significantly improve generation efficiency.

---

## 187. KV Cache Security

The KV cache may contain information derived from the user's context.

Therefore, organizations should consider:

* Memory isolation
* Tenant isolation
* Data lifetime
* Access controls
* Secure disposal

This becomes especially relevant in multi-tenant AI infrastructure.

---

## 188. Inference

Inference is the process of using a trained model to produce an output.

```text
Input
 ↓
Trained Model
 ↓
Inference
 ↓
Output
```

Training and inference are therefore different lifecycle activities.

---

## 189. Training vs. Inference

| Training                          | Inference                                 |
| --------------------------------- | ----------------------------------------- |
| Learns parameters                 | Uses existing parameters                  |
| Usually computationally expensive | Often optimized for latency               |
| Uses training data                | Uses production input                     |
| Changes model parameters          | Normally does not change model parameters |
| Development activity              | Operational activity                      |

This distinction is important for governance.

---

## 190. Inference Optimization

Organizations may optimize models for production using:

* Quantization
* Pruning
* Distillation
* Caching
* Specialized hardware
* Batching

These optimizations can affect model behavior and should therefore be validated where material.

---

## 191. Quantization

Quantization reduces the numerical precision used to represent model parameters or activations.

For example:

```text
Higher Precision
     ↓
FP32
     ↓
FP16
     ↓
INT8
     ↓
Lower Memory / Compute
```

The exact formats vary by implementation.

---

## 192. Quantization Trade-Offs

Quantization can provide:

* Lower memory consumption
* Faster inference
* Lower infrastructure cost

But excessive quantization may affect:

* Accuracy
* Numerical stability
* Certain model capabilities

Therefore, quantized models should be treated as controlled model variants.

---

## 193. Pruning

Pruning removes or reduces less important components of a model.

Conceptually:

```text
Large Model
     ↓
Remove Redundant Components
     ↓
Smaller Model
```

The objective can be improved efficiency while maintaining acceptable performance.

---

## 194. Knowledge Distillation

Knowledge distillation transfers useful behavior from a larger model into a smaller model.

Conceptually:

```text
Large Teacher Model
        ↓
     Knowledge
        ↓
Small Student Model
```

This can produce smaller models suitable for lower-cost deployment.

---

## 195. Model Compression and Governance

When a production model is compressed, governance should consider:

* Whether performance changed
* Whether security properties changed
* Whether validation was repeated
* Whether the compressed model has a new version
* Whether the approved model artifact changed

A smaller model is still a model requiring governance.

---

## 196. Encoder-Only Transformer

An encoder-only transformer can be represented as:

```text
Input
 ↓
Tokenization
 ↓
Embeddings
 ↓
Encoder Blocks
 ↓
Contextual Representation
 ↓
Task Head
 ↓
Output
```

It is often suitable for understanding tasks.

---

## 197. Decoder-Only Transformer

A decoder-only transformer is commonly structured as:

```text
Prompt
 ↓
Tokenization
 ↓
Embeddings
 ↓
Decoder Blocks
 ↓
Next-Token Prediction
 ↓
Generated Token
 ↓
Repeat
```

This architecture is particularly important for LLMs.

---

## 198. Encoder-Decoder Transformer

An encoder-decoder architecture:

```text
Input
 ↓
Encoder
 ↓
Encoded Representation
 ↓
Decoder
 ↓
Output
```

It can be used for tasks where one sequence is transformed into another.

---

## 199. Cross-Attention

Encoder-decoder systems can use **cross-attention**.

The decoder uses information from the encoder's representation.

Conceptually:

```text
Encoder Output
       ↓
Cross-Attention
       ↑
Decoder State
       ↓
Output
```

This allows the generated sequence to incorporate information from the input.

---

## 200. Self-Attention vs. Cross-Attention

| Self-Attention                            | Cross-Attention                             |
| ----------------------------------------- | ------------------------------------------- |
| Relates elements within the same sequence | Relates one representation to another       |
| Used extensively in transformers          | Common in encoder-decoder systems           |
| Builds contextual relationships           | Connects input context to output generation |

Understanding this distinction helps when reviewing complex AI architectures.

---

## 201. Causal Language Modeling

Decoder-only language models are commonly trained using a causal language-modeling objective.

The basic task is:

```text
Given:
"The security team identified"

Predict:
" a"
```

The model learns to predict the next token based on previous context.

---

## 202. Next-Token Prediction

At a high level:

```text
Input:
"The company deployed"

        ↓

Model

        ↓

Probability Distribution

a      0.40
the    0.20
an     0.08
its    0.06
...
```

The system selects or samples a token according to its generation strategy.

---

## 203. Probability Distribution

The model typically produces logits that are converted into probabilities.

Conceptually:

```text
Model Output
     ↓
Logits
     ↓
Softmax
     ↓
Token Probabilities
```

The probabilities represent the model's estimated likelihood for candidate tokens under its learned distribution.

---

## 204. Logits

Logits are unnormalized numerical scores.

For example:

```text
Token A → 4.2
Token B → 2.1
Token C → 0.8
```

Softmax converts these into probability-like values.

The logits themselves are not probabilities.

---

## 205. Temperature

During generation, a parameter called **temperature** can alter the distribution.

Conceptually:

```text
Lower Temperature
     ↓
More deterministic

Higher Temperature
     ↓
More varied / exploratory
```

Temperature does not retrain the model.

It changes the sampling behavior during inference.

---

## 206. Top-k Sampling

Top-k sampling restricts token selection to the k most probable candidates.

For example:

```text
All Tokens
    ↓
Top 50 Candidates
    ↓
Sampling
    ↓
Selected Token
```

This can reduce extremely unlikely outputs.

---

## 207. Top-p Sampling

Top-p, or nucleus sampling, selects from the smallest set of tokens whose cumulative probability exceeds a chosen threshold.

Conceptually:

```text
Token Probabilities
       ↓
Cumulative Probability
       ↓
Probability Mass Threshold
       ↓
Candidate Set
       ↓
Sampling
```

---

## 208. Deterministic vs. Stochastic Generation

Generation can be:

### More deterministic

```text
Greedy / constrained selection
```

### More stochastic

```text
Sampling
```

This distinction matters because the same prompt may produce different outputs depending on inference configuration.

---

## 209. Non-Determinism

AI systems can produce different results due to:

* Sampling
* Random seeds
* Hardware behavior
* Parallel computation
* Model versions
* System changes

Therefore, exact reproducibility may require careful control of the entire inference environment.

---

## 210. Reproducibility

A governance process may need to establish whether an output can be reproduced.

Relevant artifacts may include:

* Model version
* Prompt
* System instructions
* Input data
* Inference parameters
* Retrieval context
* Tool outputs
* Random seed where applicable
* Runtime configuration

This becomes especially important for regulated or high-impact applications.

---

## 211. Determinism Is Not the Same as Correctness

A model can consistently produce the same incorrect output.

Therefore:

```text
Reproducibility
      ≠
Correctness
```

Both should be considered separately.

---

A foundation model generally refers to a large model trained on broad data that can support multiple downstream applications.

Conceptually:

```text
 ┌──────┼────────┐
 ↓      ↓        ↓

 ↓      ↓        ↓
```

The architecture is often based on transformers, although the broader concept is not limited to a single architecture.

Later stages may include:

```text

 ↓

 ↓

 ↓
```

## 214. Instruction Tuning

```text
     +

     ↓
```

This helps adapt a base model to respond to user instructions.

## 215. Preference Optimization

Models can also be optimized based on preferred outputs.

The objective is generally to encourage behavior considered more useful or aligned with desired criteria.

Approaches may include:

* Human preference data
* Reward models

These mechanisms become important when studying AI alignment and safety.

Alignment techniques can improve desired behavior but do not guarantee:

```text
AI Model
   ↓
Recommendation
   ↓
Human Review
   ↓
Decision
```

Human oversight can reduce certain risks, but only if the human has:

* Appropriate authority
* Relevant expertise
* Adequate information
* Sufficient time
* Ability to override the system

---

## 239. Human-on-the-Loop

Another model is human-on-the-loop oversight.

The AI operates automatically while humans monitor the system and intervene when necessary.

```text
AI
 ↓
Automated Operation
 ↓
Monitoring
 ↓
Human Intervention if Needed
```

This is different from requiring human approval for every action.

---

## 240. Human-in-the-Loop vs. Human-on-the-Loop

| Model                 | Human Role                                              |
| --------------------- | ------------------------------------------------------- |
| Human-in-the-loop     | Reviews or approves decisions/actions                   |
| Human-on-the-loop     | Monitors automated operation and intervenes when needed |
| Human-out-of-the-loop | No meaningful human intervention                        |

The appropriate approach depends on risk.

---

```text
 ↓
```

## 244. Data Minimization

A well-designed AI architecture should avoid unnecessary data exposure.

Conceptually:

```text

     ↓

```

rather than:

```text

     ↓

```

Data minimization can reduce both privacy and security risks.

## 245. Least Privilege

For example:

```text
   ↓

   ↓
```

```text

   ↓
Administrator
   ↓
Entire Enterprise
```

Least privilege is especially important for tool-connected AI.

Modern AI architectures can benefit from zero-trust principles:

AI should not automatically be trusted simply because it operates inside an enterprise network.

Modern AI architecture is best understood as a chain of interconnected technical and governance components:

```text
 ↓

 ↓

 ↓

 ↓

 ↓

 ↓
```

A governance program that controls only the model is incomplete.

The GRC professional must understand **where the model sits within the larger system**, what it can access, what can influence it, what actions its outputs can trigger, and what controls exist at every trust boundary.

> **AI security and AI governance must be applied to the system architecture surrounding the model—not only to the neural network itself.**

# 283. Prompt Injection

# 284. Prompt Injection Is an Architecture Problem

Prompt injection should not be treated only as a "model problem."

```text
 ↓

 ↓

 ↓
```

# 323. Architecture Drift

Architecture drift occurs when the deployed system diverges from the approved design.

For example:

```text
Approved Architecture
       ↓
New API Added
       ↓
New Database Added
       ↓
New External Provider Added
       ↓
Actual Architecture ≠ Approved Architecture
```

Continuous architecture governance helps detect this.

# 330. Common AI Architecture Governance Failures

Organizations frequently encounter problems such as:

### Failure 1 — Model-only governance

The organization governs the model but ignores the application.

### Failure 2 — No data-flow visibility

Nobody knows where prompts or documents are sent.

### Failure 3 — Excessive privileges

AI applications receive more permissions than required.

### Failure 4 — Uncontrolled third-party models

Employees deploy models without provenance or validation.

### Failure 5 — Poor version control

The organization cannot determine which model produced an output.

### Failure 6 — No rollback

A problematic model cannot easily be replaced.

### Failure 7 — Stale architecture diagrams

Documentation no longer matches production.

# 336. Final Architecture Principle

The most important lesson from **02.03 — Neural Networks and Modern AI Architectures** is:

> **An AI model is a component within an AI system, and an AI system is a component within a broader business and technology ecosystem.**

Therefore, AI security governance must consider the entire chain:

```text
Business
   ↓
Application
   ↓
AI Orchestration
   ↓
Model
   ↓
Data
   ↓
Infrastructure
   ↓
External Dependencies
```

The GRC professional's job is not to redesign the neural network.

The job is to understand enough of the architecture to determine:

**what must be protected, what can go wrong, who is accountable, which controls are required, and what evidence demonstrates that the AI system remains within its approved risk boundaries.**
