# 02.06 — Generative AI

## Part 1 — Generative AI Fundamentals, Concepts, Evolution, and Core Architecture

---

# 1. Introduction to Generative AI

**Generative Artificial Intelligence (Generative AI or GenAI)** refers to AI systems capable of generating new content based on patterns learned from data.

Generated content can include:

* Text
* Images
* Audio
* Video
* Code
* Music
* Synthetic data
* 3D content
* Structured information

A simplified representation is:

```text
Input
  ↓
Generative AI Model
  ↓
Generated Content
```

For example:

```text
User Prompt
     ↓
Generative AI
     ↓
Text / Image / Audio / Code
```

For a GRC professional, the important concept is that Generative AI does not merely **classify or predict** information. It can **create new outputs**.

---

# 2. Traditional AI vs Generative AI

Traditional AI is often designed to make predictions, classifications, or decisions.

For example:

```text
Email
  ↓
AI Model
  ↓
Spam / Not Spam
```

Generative AI may instead produce new content:

```text
Prompt
  ↓
Generative AI
  ↓
New Email
```

The distinction is not absolute, because modern AI systems can combine predictive and generative capabilities.

---

# 3. Predictive AI

Predictive AI estimates an outcome.

Examples include:

* Fraud detection
* Credit-risk prediction
* Demand forecasting
* Customer churn prediction
* Malware classification

Conceptually:

```text
Historical Data
      ↓
AI Model
      ↓
Prediction
```

Example:

```text
Transaction Data
      ↓
Fraud Model
      ↓
Fraud Probability = 92%
```

---

# 4. Generative AI

Generative AI produces content.

Example:

```text
Prompt:
Write a security policy.

        ↓

Generative AI

        ↓

Generated Security Policy
```

Another example:

```text
Text Prompt
    ↓
Image Generation Model
    ↓
Generated Image
```

The model is generating a new output based on learned patterns.

---

# 5. Why Generative AI Is Important to GRC

Generative AI creates new governance questions.

Traditional software might:

```text
Input
 ↓
Rule
 ↓
Output
```

Generative AI may:

```text
Input
 ↓
Model
 ↓
Probabilistic Output
```

The output may vary between executions.

This introduces governance questions involving:

* Accuracy
* Reliability
* Explainability
* Data protection
* Intellectual property
* Security
* Human oversight
* Accountability
* Misuse
* Regulatory compliance

The broader category includes multiple model families.

```text
                 Generative AI

       │               │                │
       └───────────────┼────────────────┘
                       ↓
              Video / Code / 3D
```

LLMs are therefore one important component of the broader GenAI ecosystem.

# 8. Generative AI vs Content Generation

Not every automated content-generation system is necessarily Generative AI.

For example, a simple template system might produce:

```text
"Dear " + CustomerName
```

This is automated content generation but does not necessarily involve a generative model.

Generative AI typically uses a learned model to produce outputs that are not simply predefined templates.

---

# 9. How Generative AI Learns Patterns

Generative models learn statistical patterns from training data.

A simplified concept is:

```text
Large Dataset
      ↓
Training
      ↓
Learned Parameters
      ↓
Generative Model
      ↓
New Output
```

The model does not simply store a database of complete answers.

Instead, training produces a large set of learned parameters representing patterns in the training data.

---

# 10. Parameters

A **parameter** is a numerical value learned during model training.

Large AI models may contain:

* Millions
* Billions
* Hundreds of billions
* More parameters

Parameters help determine how the model transforms input into output.

Simplified:

```text
Input
  ↓
Parameters
  ↓
Output
```

Parameters should not be confused with:

* User prompts
* Configuration settings
* API parameters
* Training examples

---

# 11. Training Data

Generative AI models require data during training.

Depending on the model, training data can include:

* Books
* Websites
* Images
* Audio
* Video
* Code
* Documents
* Synthetic data

The exact dataset depends on the model and provider.

---

# 12. Data Quality

The quality of training data affects model behavior.

Poor-quality data may introduce:

* Errors
* Bias
* Duplicates
* Toxic content
* Misinformation
* Security vulnerabilities

A simplified relationship is:

```text
Training Data
      ↓
Data Quality
      ↓
Model Behavior
```

This is why data governance is an important component of AI governance.

---

# 13. Data Provenance

**Data provenance** refers to understanding the origin and history of data.

Questions include:

* Where did the data originate?
* Who owns it?
* How was it collected?
* Was it modified?
* Was it authorized for use?
* What licenses apply?
* What transformations occurred?

For GRC, provenance is important for:

* Compliance
* Privacy
* Intellectual property
* Auditability
* Risk management

---

# 14. Training vs Generation

The training phase and generation phase are different.

### Training

```text
Data
 ↓
Learning Process
 ↓
Model Parameters
```

### Generation

```text
Prompt
 ↓
Trained Model
 ↓
Generated Output
```

The model is generally not retrained every time a user submits a prompt.

---

# 15. Inference

The process of using a trained model to produce an output is called **inference**.

Conceptually:

```text
User Input
     ↓
Trained Model
     ↓
Inference
     ↓
Generated Output
```

For example:

```text
"Explain phishing."

       ↓

LLM inference

       ↓

Generated explanation
```

Inference is therefore the operational phase of model use.

---

# 16. Generation Is Probabilistic

Generative AI generally does not operate like a deterministic rule engine.

A simplified representation is:

```text
Input
 ↓
Probability Distribution
 ↓
Selection
 ↓
Output
```

For example, given:

```text
"The capital of France is..."
```

the model assigns very high probability to:

```text
Paris
```

But for open-ended prompts, many possible continuations may be plausible.

---

# 17. Tokens

Many text-generating models process text using **tokens**.

A token can represent:

* A complete word
* Part of a word
* Punctuation
* A symbol
* Other text fragments

Example:

```text
"cybersecurity"
```

might be represented internally as multiple tokens depending on the tokenizer.

The exact tokenization depends on the model.

---

# 18. Tokenization

Tokenization converts input into a representation that the model can process.

Conceptually:

```text
Text
 ↓
Tokenizer
 ↓
Tokens
 ↓
Numerical Representation
 ↓
Model
```

For GRC professionals, tokenization becomes relevant to:

* Cost
* Context limits
* Data processing
* Logging
* Performance

---

# 19. Context

A generative model does not necessarily operate only on the current sentence.

It may process a **context window** containing:

* System instructions
* User messages
* Previous conversation
* Retrieved documents
* Tool results

Conceptually:

```text
System Instructions
        +
User Prompt
        +
Conversation
        +
Retrieved Context
        ↓
      Model
        ↓
      Output
```

This becomes extremely important for security and governance.

---

# 20. Context Window

The **context window** represents the amount of information the model can process within a given interaction.

Conceptually:

```text
┌───────────────────────────────┐
│        Context Window         │
│                               │
│ System Instructions           │
│ User Prompt                   │
│ Conversation                  │
│ Documents                     │
│ Tool Results                  │
│                               │
└───────────────────────────────┘
                  ↓
                Model
```

Different models support different context sizes.

---

# 21. Context Is Not the Same as Training

A common misconception is:

> "If I provide a document to an AI model, the model has learned it."

Usually, that is not what happens.

Providing a document during an interaction generally means:

```text
Document
 ↓
Context
 ↓
Model
 ↓
Response
```

It does not necessarily mean:

```text
Document
 ↓
Training
 ↓
Permanent Model Change
```

This distinction is extremely important for GRC and data-protection discussions.

# 22. Prompt

A **prompt** is information provided to guide the model's behavior or output.

It may contain:

* Instructions
* Questions
* Context
* Examples
* Constraints
* Data

Example:

# 23. Prompt Engineering

**Prompt engineering** is the practice of designing prompts to obtain desired model behavior.

Examples include:

* Providing clear instructions
* Defining output formats
* Providing examples
* Adding constraints
* Supplying relevant context

For example:

```text
Poor:
"Analyze this."

Better:
"Identify the five highest cybersecurity risks
and rank them by business impact."
```

# 28. Generative AI Model Families

Several major approaches have emerged.

Important model families include:

# 29. Autoregressive Models

Autoregressive models generate output sequentially.

For text:

```text
Token 1
  ↓
Token 2
  ↓
Token 3
  ↓
Token 4
  ↓
...
```

Each generated element depends on previously generated context.

Many modern language models use autoregressive generation.

---

# 30. Transformer-Based Generative Models

Transformers became foundational to modern generative AI.

They enable models to process relationships between tokens and other representations efficiently.

A simplified architecture is:

```text
Input
 ↓
Tokenization
 ↓
Embeddings
 ↓
Transformer Layers
 ↓
Output Probabilities
 ↓
Generated Tokens
```

Transformers are central to modern LLMs and many multimodal systems.

---

# 31. Diffusion Models

Diffusion models are particularly important for image and media generation.

A simplified concept is:

```text
Training:

Real Data
   ↓
Add Noise
   ↓
Learn Denoising Process
```

During generation:

```text
Random Noise
     ↓
Iterative Denoising
     ↓
Generated Image
```

This is fundamentally different from autoregressive text generation.

---

# 32. Generative Adversarial Networks

**GANs** consist conceptually of two competing models:

```text
Generator
    ↓
Synthetic Content
    ↓
Discriminator
    ↓
Real / Fake
```

The generator attempts to create realistic content while the discriminator attempts to distinguish generated content from real content.

GANs were particularly influential in the development of generative image technology.

---

# 33. Variational Autoencoders

**Variational Autoencoders (VAEs)** learn a compressed latent representation of data.

Conceptually:

```text
Input
 ↓
Encoder
 ↓
Latent Representation
 ↓
Decoder
 ↓
Generated Output
```

VAEs are useful for:

* Representation learning
* Generation
* Data synthesis
* Latent-space manipulation

---

# 34. Latent Space

A **latent space** is a mathematical representation where learned features or concepts can be represented.

Conceptually:

```text
Real-world Data
       ↓
      Model
       ↓
  Latent Representation
       ↓
     Generation
```

Latent representations are important across multiple generative AI architectures.

# 64. Autoregressive Generation

Autoregressive models generate content sequentially.

For text:

```text
Input
  ↓
Token 1
  ↓
Token 2
  ↓
Token 3
  ↓
Token 4
  ↓
...
```

Each new token is generated based on the preceding context.

For example:

```text
"The company should"
        ↓
"implement"
        ↓
"strong"
        ↓
"access"
        ↓
"controls."
```

The model repeatedly predicts what should come next.

---

# 65. Next-Token Prediction

Modern language models are commonly trained around the concept of predicting the next token.

Conceptually:

```text
"The security team should"
              ↓
       Probability
       Distribution
              ↓
        ┌─────┼─────┐
        ↓     ↓     ↓
     review  monitor assess
```

The model assigns probabilities to possible next tokens.

The generation process then selects a token according to the model's generation strategy.

---

# 66. Why Next-Token Prediction Can Produce Complex Content

Although next-token prediction sounds simple, repeatedly applying it can produce complex outputs.

```text
Token 1
  ↓
Token 2
  ↓
Token 3
```

# 69. Attention

**Attention** allows the model to determine which parts of the available context are important when processing information.

For example:

```text
"The auditor reviewed the security report
because it contained several critical findings."
```

The model needs to understand relationships between words and concepts.

Attention helps establish these relationships.

---

# 70. Self-Attention

In self-attention, tokens are compared with other tokens within the relevant context.

Conceptually:

```text
Token A ──────┐
              ↓
Token B → Attention → Representation
              ↑
Token C ──────┘
```

The model calculates relationships between representations.

This enables it to capture contextual dependencies.

---

# 71. Query, Key, and Value

A simplified attention mechanism uses:

* Query
* Key
* Value

Conceptually:

```text
Query
  │
  ├──── Compare ──── Key
  │
  ↓
Attention Score
  │
  ↓
Weighted Value
```

The mathematical details are important to AI engineers, but for GRC purposes the key concept is:

> **Attention allows the model to dynamically determine which contextual information should influence a representation.**

---

# 72. Multi-Head Attention

```text
        │          │          │
        └──────────┼──────────┘
                   ↓
              Combined
                   ↓
                Output
```

Different heads can learn different relationships or patterns.

# 77. Diffusion Models

Diffusion models became especially important for image generation.

The basic training concept is:

```text

   ↓

   ↓

   ↓

```

During generation:

```text

   ↓

   ↓
Denoising Step
   ↓
Denoising Step
   ↓

```

# 78. Diffusion Training

During training, the model learns how data changes when noise is progressively added.

Conceptually:

```text
Image
 ↓
Low Noise
 ↓
More Noise
 ↓
Heavy Noise
 ↓
Almost Random Noise
```

The model learns to reverse this process.

---

# 79. Diffusion Inference

During inference, the process runs in the opposite direction.

```text
Random Noise
     ↓
Denoising
     ↓
Structure Appears
     ↓
Details Appear
     ↓
Final Image
```

This allows the model to generate new images rather than simply retrieving existing ones.

# 95. Sampling

Generation usually involves selecting outputs from probability distributions.

For example:

```text
Token A → 0.50
Token B → 0.30
Token C → 0.15
Token D → 0.05
```

A generation strategy determines how these probabilities are used.

Sampling configuration can influence:

* Creativity
* Diversity
* Predictability
* Repetition

---

# 96. Temperature

**Temperature** is commonly used to influence the randomness of token selection.

Conceptually:

```text
Lower Temperature
        ↓
More predictable output

Higher Temperature
        ↓
More varied output
```

Very high temperature can produce less predictable results.

Very low temperature can produce more deterministic-looking responses.

The exact behavior depends on the model and implementation.

---

# 97. Why Temperature Matters to GRC

Temperature can influence operational consistency.

For example:

```text
Low Temperature
→ More consistent answers

Higher Temperature
→ Greater variation
```

For a compliance-reporting application, excessive variability may be undesirable.

For creative content generation, variability may be beneficial.

Therefore:

> **Model configuration should be aligned with the business use case and risk profile.**

---

# 98. Top-k Sampling

**Top-k sampling** limits candidate selection to the top *k* probable tokens.

Example:

```text
All possible tokens
       ↓
Top 10 candidates
       ↓
Selection
```

This limits extremely unlikely choices.

---

# 99. Top-p Sampling

**Top-p**, also called nucleus sampling, selects from the smallest group of tokens whose combined probability reaches a specified threshold.

Conceptually:

```text
Probability Distribution
        ↓
Select candidates covering probability p
        ↓
Sample
```

This creates a dynamic candidate set.

# 152. Part 2 Key Takeaways

A GRC professional should now understand:

5. Diffusion models are particularly important for image and media generation.

# 158. Prompt Injection

**Prompt injection** occurs when an attacker attempts to manipulate the instructions interpreted by an AI system.

Simplified:

```text
Trusted Instructions
        +
Untrusted Input
        ↓
      Model
        ↓
Unexpected Behavior
```

For example, an attacker may provide instructions designed to cause the model to disregard application rules.

---

# 159. Direct Prompt Injection

A direct prompt injection comes directly from the user.

Conceptually:

```text
User
 ↓
Malicious Prompt
 ↓
AI Application
 ↓
Model
 ↓
Manipulated Response
```

The attacker intentionally crafts instructions to alter model behavior.

---

# 160. Indirect Prompt Injection

Indirect prompt injection occurs when malicious instructions are contained inside data that the AI system retrieves or processes.

For example:

```text
User
 ↓
AI Application
 ↓
Retrieve Document
 ↓
Malicious Instruction Inside Document
 ↓
Model
```

This is particularly important for systems using:

* RAG
* Web browsing
* Email processing
* Document analysis
* External content

---

# 161. Why Indirect Prompt Injection Matters

An enterprise AI assistant might be authorized to read internal documents.

An attacker could attempt to place malicious instructions inside one of those documents.

Conceptually:

```text
External Content
       ↓
Enterprise Retrieval
       ↓
AI Context
       ↓
Model
       ↓
Unexpected Action
```

The threat therefore crosses the boundary between **data** and **instructions**.

---

# 162. Prompt Injection Is Not Traditional Injection

Traditional SQL injection might exploit a database query.

```text
User Input
 ↓
SQL Query
 ↓
Database
```

Prompt injection targets the interpretation of natural-language instructions.

```text
User / Data
 ↓
Prompt / Context
 ↓
AI Model
```

The underlying security principles differ, although both involve malicious input influencing system behavior.

# 164. Excessive AI Agency

# 238. Part 3 Key Takeaways

The major lessons from Part 3 are:

1. GenAI introduces a broad and evolving threat landscape.
2. Prompt injection can manipulate model behavior.
3. Indirect prompt injection is particularly relevant to RAG and external content.
4. AI privileges should follow least-privilege principles.
5. Sensitive information can leak through prompts, context, outputs, logs, or providers.
6. Shadow AI can bypass organizational governance.
7. Models and AI applications are subject to supply-chain risks.
8. Model updates can change system behavior and therefore require change management.
9. Hallucination can create significant business and compliance risk.
10. Automation bias can cause users to over-trust AI outputs.
11. GenAI can enable phishing, fraud, impersonation, deepfakes, and malicious code generation.
12. Privacy risks extend across the complete AI data lifecycle.
13. Intellectual-property risks must be addressed through appropriate governance.
14. High-impact AI use cases require stronger controls and oversight.
15. AI systems should use defense in depth rather than relying on model-level guardrails.
16. Deterministic security controls should enforce authorization and access decisions.
17. AI threat modeling should cover users, prompts, context, models, outputs, tools, APIs, and enterprise systems.
18. AI security, AI safety, privacy, and enterprise GRC must work together.
19. AI risk ownership should be distributed across business, risk, security, compliance, and assurance functions.
20. The AI model itself should never be treated as the complete security boundary.

# 337. GRC Professional's GenAI Checklist

When evaluating a GenAI system, ask:

### Governance

* Is the use case approved?
* Who owns the system?
* Who accepts the risk?

### Data

* What data enters the system?
* How is it classified?
* Where is it stored?
* How long is it retained?

### Model

* Which model is used?
* Who provides it?
* Which version is deployed?
* How is it evaluated?

### Security

* How are users authenticated?
* How is authorization enforced?
* How are secrets protected?
* How is prompt injection addressed?

### Privacy

* Is personal information processed?
* What is the lawful basis?
* What are retention requirements?
* Who are the processors?

### Human Oversight

* Is human review required?
* Can humans override AI decisions?

### Vendor

* Has the provider been assessed?
* What subprocessors exist?
* What happens during provider failure?

### Monitoring

* Are AI activities logged?
* Are security events monitored?
* Are model changes tracked?

### Assurance

* Has the system been tested?
* Are controls operating effectively?
* Is there audit evidence?
