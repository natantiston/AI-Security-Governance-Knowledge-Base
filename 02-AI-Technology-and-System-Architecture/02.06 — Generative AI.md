# 02.06 — Generative AI

## Part 1 — Generative AI Fundamentals, Concepts, Evolution, and Core Architecture

---

# 1. Introduction to Generative AI

**Generative Artificial Intelligence (Generative AI or GenAI)** refers to AI systems capable of generating new content based on patterns learned from data.

Generated content can include:

* Text
* Images
* Audio
* Video
* Code
* Music
* Synthetic data
* 3D content
* Structured information

A simplified representation is:

```text
Input
  ↓
Generative AI Model
  ↓
Generated Content
```

For example:

```text
User Prompt
     ↓
Generative AI
     ↓
Text / Image / Audio / Code
```

For a GRC professional, the important concept is that Generative AI does not merely **classify or predict** information. It can **create new outputs**.

---

# 2. Traditional AI vs Generative AI

Traditional AI is often designed to make predictions, classifications, or decisions.

For example:

```text
Email
  ↓
AI Model
  ↓
Spam / Not Spam
```

Generative AI may instead produce new content:

```text
Prompt
  ↓
Generative AI
  ↓
New Email
```

The distinction is not absolute, because modern AI systems can combine predictive and generative capabilities.

---

# 3. Predictive AI

Predictive AI estimates an outcome.

Examples include:

* Fraud detection
* Credit-risk prediction
* Demand forecasting
* Customer churn prediction
* Malware classification

Conceptually:

```text
Historical Data
      ↓
AI Model
      ↓
Prediction
```

Example:

```text
Transaction Data
      ↓
Fraud Model
      ↓
Fraud Probability = 92%
```

---

# 4. Generative AI

Generative AI produces content.

Example:

```text
Prompt:
Write a security policy.

        ↓

Generative AI

        ↓

Generated Security Policy
```

Another example:

```text
Text Prompt
    ↓
Image Generation Model
    ↓
Generated Image
```

The model is generating a new output based on learned patterns.

---

# 5. Why Generative AI Is Important to GRC

Generative AI creates new governance questions.

Traditional software might:

```text
Input
 ↓
Rule
 ↓
Output
```

Generative AI may:

```text
Input
 ↓
Model
 ↓
Probabilistic Output
```

The output may vary between executions.

This introduces governance questions involving:

* Accuracy
* Reliability
* Explainability
* Data protection
* Intellectual property
* Security
* Human oversight
* Accountability
* Misuse
* Regulatory compliance

---

# 6. Generative AI Is a Broad Category

Generative AI is not synonymous with ChatGPT or LLMs.

The broader category includes multiple model families.

```text
                 Generative AI
                       │
       ┌───────────────┼────────────────┐
       ↓               ↓                ↓
      Text           Images            Audio
       │               │                │
      LLMs        Diffusion Models   Audio Models
       │               │                │
       └───────────────┼────────────────┘
                       ↓
              Video / Code / 3D
```

LLMs are therefore one important component of the broader GenAI ecosystem.

Generative AI can operate across different modalities.

Prompt → Text
```

### Image

Prompt → Image
```

# 8. Generative AI vs Content Generation

Not every automated content-generation system is necessarily Generative AI.

For example, a simple template system might produce:

```text
"Dear " + CustomerName
```

This is automated content generation but does not necessarily involve a generative model.

Generative AI typically uses a learned model to produce outputs that are not simply predefined templates.

---

# 9. How Generative AI Learns Patterns

Generative models learn statistical patterns from training data.

A simplified concept is:

```text
Large Dataset
      ↓
Training
      ↓
Learned Parameters
      ↓
Generative Model
      ↓
New Output
```

The model does not simply store a database of complete answers.

Instead, training produces a large set of learned parameters representing patterns in the training data.

---

# 10. Parameters

A **parameter** is a numerical value learned during model training.

Large AI models may contain:

* Millions
* Billions
* Hundreds of billions
* More parameters

Parameters help determine how the model transforms input into output.

Simplified:

```text
Input
  ↓
Parameters
  ↓
Output
```

Parameters should not be confused with:

* User prompts
* Configuration settings
* API parameters
* Training examples

---

# 11. Training Data

Generative AI models require data during training.

Depending on the model, training data can include:

* Books
* Websites
* Images
* Audio
* Video
* Code
* Documents
* Synthetic data

The exact dataset depends on the model and provider.

---

# 12. Data Quality

The quality of training data affects model behavior.

Poor-quality data may introduce:

* Errors
* Bias
* Duplicates
* Toxic content
* Misinformation
* Security vulnerabilities

A simplified relationship is:

```text
Training Data
      ↓
Data Quality
      ↓
Model Behavior
```

This is why data governance is an important component of AI governance.

---

# 13. Data Provenance

**Data provenance** refers to understanding the origin and history of data.

Questions include:

* Where did the data originate?
* Who owns it?
* How was it collected?
* Was it modified?
* Was it authorized for use?
* What licenses apply?
* What transformations occurred?

For GRC, provenance is important for:

* Compliance
* Privacy
* Intellectual property
* Auditability
* Risk management

---

# 14. Training vs Generation

The training phase and generation phase are different.

### Training

```text
Data
 ↓
Learning Process
 ↓
Model Parameters
```

### Generation

```text
Prompt
 ↓
Trained Model
 ↓
Generated Output
```

The model is generally not retrained every time a user submits a prompt.

---

# 15. Inference

The process of using a trained model to produce an output is called **inference**.

Conceptually:

```text
User Input
     ↓
Trained Model
     ↓
Inference
     ↓
Generated Output
```

For example:

```text
"Explain phishing."

       ↓

LLM inference

       ↓

Generated explanation
```

Inference is therefore the operational phase of model use.

---

# 16. Generation Is Probabilistic

Generative AI generally does not operate like a deterministic rule engine.

A simplified representation is:

```text
Input
 ↓
Probability Distribution
 ↓
Selection
 ↓
Output
```

For example, given:

```text
"The capital of France is..."
```

the model assigns very high probability to:

```text
Paris
```

But for open-ended prompts, many possible continuations may be plausible.

---

# 17. Tokens

Many text-generating models process text using **tokens**.

A token can represent:

* A complete word
* Part of a word
* Punctuation
* A symbol
* Other text fragments

Example:

```text
"cybersecurity"
```

might be represented internally as multiple tokens depending on the tokenizer.

The exact tokenization depends on the model.

---

# 18. Tokenization

Tokenization converts input into a representation that the model can process.

Conceptually:

```text
Text
 ↓
Tokenizer
 ↓
Tokens
 ↓
Numerical Representation
 ↓
Model
```

For GRC professionals, tokenization becomes relevant to:

* Cost
* Context limits
* Data processing
* Logging
* Performance

---

# 19. Context

A generative model does not necessarily operate only on the current sentence.

It may process a **context window** containing:

* System instructions
* User messages
* Previous conversation
* Retrieved documents
* Tool results

Conceptually:

```text
System Instructions
        +
User Prompt
        +
Conversation
        +
Retrieved Context
        ↓
      Model
        ↓
      Output
```

This becomes extremely important for security and governance.

---

# 20. Context Window

The **context window** represents the amount of information the model can process within a given interaction.

Conceptually:

```text
┌───────────────────────────────┐
│        Context Window         │
│                               │
│ System Instructions           │
│ User Prompt                   │
│ Conversation                  │
│ Documents                     │
│ Tool Results                  │
│                               │
└───────────────────────────────┘
                  ↓
                Model
```

Different models support different context sizes.

---

# 21. Context Is Not the Same as Training

A common misconception is:

> "If I provide a document to an AI model, the model has learned it."

Usually, that is not what happens.

Providing a document during an interaction generally means:

```text
Document
 ↓
Context
 ↓
Model
 ↓
Response
```

It does not necessarily mean:

```text
Document
 ↓
Training
 ↓
Permanent Model Change
```

This distinction is extremely important for GRC and data-protection discussions.

---

# 22. Prompt

A **prompt** is information provided to guide the model's behavior or output.

It may contain:

* Instructions
* Questions
* Context
* Examples
* Constraints
* Data

Example:

```text
"Summarize this security incident in five bullet points."
```

---

# 23. Prompt Engineering

**Prompt engineering** is the practice of designing prompts to obtain desired model behavior.

Examples include:

* Providing clear instructions
* Defining output formats
* Providing examples
* Adding constraints
* Supplying relevant context

For example:

```text
Poor:
"Analyze this."

Better:
"Identify the five highest cybersecurity risks
and rank them by business impact."
```

---

# 24. System Instructions

Some AI applications provide higher-level instructions that establish expected behavior.

Conceptually:

```text
System Instructions

Developer/Application Instructions
        ↓
User Prompt
        ↓
Model
```

The exact hierarchy depends on the implementation.

These instructions may establish:

* Role
* Rules
* Output requirements
* Safety restrictions
* Application behavior

# 28. Generative AI Model Families

Several major approaches have emerged.

Important model families include:

* Autoregressive models
* Transformer-based models
* Diffusion models
* Generative adversarial networks
* Variational autoencoders
* Flow-based models

Different architectures are better suited to different generation tasks.

---

# 29. Autoregressive Models

Autoregressive models generate output sequentially.

For text:

```text
Token 1
  ↓
Token 2
  ↓
Token 3
  ↓
Token 4
  ↓
...
```

Each generated element depends on previously generated context.

Many modern language models use autoregressive generation.

---

# 30. Transformer-Based Generative Models

Transformers became foundational to modern generative AI.

They enable models to process relationships between tokens and other representations efficiently.

A simplified architecture is:

```text
Input
 ↓
Tokenization
 ↓
Embeddings
 ↓
Transformer Layers
 ↓
Output Probabilities
 ↓
Generated Tokens
```

Transformers are central to modern LLMs and many multimodal systems.

---

# 31. Diffusion Models

Diffusion models are particularly important for image and media generation.

A simplified concept is:

```text
Training:

Real Data
   ↓
Add Noise
   ↓
Learn Denoising Process
```

During generation:

```text
Random Noise
     ↓
Iterative Denoising
     ↓
Generated Image
```

This is fundamentally different from autoregressive text generation.

---

# 32. Generative Adversarial Networks

**GANs** consist conceptually of two competing models:

```text
Generator
    ↓
Synthetic Content
    ↓
Discriminator
    ↓
Real / Fake
```

The generator attempts to create realistic content while the discriminator attempts to distinguish generated content from real content.

GANs were particularly influential in the development of generative image technology.

---

# 33. Variational Autoencoders

**Variational Autoencoders (VAEs)** learn a compressed latent representation of data.

Conceptually:

```text
Input
 ↓
Encoder
 ↓
Latent Representation
 ↓
Decoder
 ↓
Generated Output
```

VAEs are useful for:

* Representation learning
* Generation
* Data synthesis
* Latent-space manipulation

---

# 34. Latent Space

A **latent space** is a mathematical representation where learned features or concepts can be represented.

Conceptually:

```text
Real-world Data
       ↓
      Model
       ↓
  Latent Representation
       ↓
     Generation
```

Latent representations are important across multiple generative AI architectures.

---

# 35. Synthetic Data

Generative AI can create synthetic datasets.

Example:

```text
Real Customer Data
        ↓
Generative Model
        ↓
Synthetic Customer Data
```

Synthetic data may be used for:

* Testing
* Development
* Simulation
* Model training
* Privacy-preserving experimentation

However, synthetic data is not automatically free from privacy or security risk.

---

# 36. Synthetic Data Risks

Synthetic data can potentially:

* Preserve characteristics of original data
* Reproduce sensitive patterns
* Introduce bias
* Contain unrealistic relationships
* Create false confidence

Therefore, synthetic data requires governance.

# 44. Deepfakes

A **deepfake** is synthetic or manipulated media that can convincingly represent people or events.

Generative AI can enable:

* Face synthesis
* Voice cloning
* Video manipulation
* Identity impersonation

This introduces significant:

* Cybersecurity
* Fraud
* Privacy
* Legal
* Reputational

risks.

# 45. Generative AI and Social Engineering

Generative AI can increase the scale and quality of social engineering.

Traditional phishing:

```text
Attacker
 ↓
Generic Email
```

Generative AI-enabled phishing:

```text
Public Information
 ↓
Generative AI
 ↓
Personalized Message
 ↓
Target
```

This can make phishing more convincing and scalable.

---

# 46. Generative AI and Cybersecurity

Generative AI can be used by defenders and attackers.

### Defensive uses

* Threat analysis
* Security summarization
* Code analysis
* Incident response assistance
* Detection engineering
* Security documentation

### Offensive or malicious uses

* Phishing generation
* Social engineering
* Malware development assistance
* Reconnaissance assistance
* Fraud content

This creates a dual-use governance problem.

---

# 47. Dual-Use Technology

Generative AI is a **dual-use technology**.

The same capability can support legitimate and malicious objectives.

```text
                Generative AI
                      │
              ┌───────┴───────┐
              ↓               ↓
           Defensive       Malicious
              │               │
           Security         Fraud
           Analysis         Phishing

```

GRC programs must therefore consider both sides.

# 52. Open vs Closed Models

Generative AI models can broadly be delivered through different approaches.

### Closed / proprietary models

The provider controls significant aspects of:

* Model weights
* Infrastructure
* Training
* Updates

### Open-weight models

The model weights may be made available for organizations to download or operate.

These approaches create different governance considerations.

---

# 53. Open-Weight Model Governance

Open-weight models may provide greater control over:

* Deployment
* Data processing
* Customization
* Infrastructure

But they can introduce additional responsibilities for:

* Security
* Patching
* Model provenance
* Dependency management
* Infrastructure
* Vulnerability management

Control does not automatically mean lower risk.

# 57. The GRC Perspective

A GRC professional does not need to build a diffusion model or train a transformer from scratch.

The objective is to understand enough to answer:

> **What technology is being used, how does it operate, what can go wrong, who is responsible, and what controls are required?**

That is the governing principle of Chapter 2.

---

# 58. Generative AI Governance Questions

When evaluating a GenAI system, ask:

1. What type of content does it generate?
2. What model architecture is being used?
3. What data was used to develop the model?
4. What data does the application process?
5. Where is the model hosted?
6. Who operates the model?
7. What users can access it?
8. What external services are connected?
9. What decisions depend on its output?
10. What happens if the output is wrong?
11. What security controls exist?
12. What evidence demonstrates control effectiveness?

# 60. Key Takeaways — Part 1

A GRC professional should understand that:

1. **Generative AI creates new content from learned patterns.**
2. **LLMs are one type of Generative AI, not the entire category.**
3. GenAI can generate text, images, audio, video, code, and other content.
4. Different generative architectures have different security and governance characteristics.
5. Training and inference are different lifecycle stages.
6. Prompts and context influence model behavior.
7. Generated output is probabilistic and may be incorrect.
8. Training data quality and provenance matter.
9. GenAI is a dual-use technology.
10. GenAI introduces security, privacy, IP, operational, ethical, and regulatory risks.
11. Governance must cover the complete AI application, not only the underlying model.
12. GenAI systems must be governed throughout their lifecycle.
