# 13.14 — AI Penetration Testing

## Part 1 — AI Penetration Testing Foundations

### 1. Definition of AI Penetration Testing

AI Penetration Testing is an authorized, controlled security assessment designed to identify and demonstrate exploitable weaknesses in AI systems, applications, models, data pipelines, integrations, tools, agents, and supporting infrastructure.

Unlike purely functional evaluation, penetration testing attempts to move from **weakness discovery to controlled exploitation** and determine whether a vulnerability can produce a meaningful security impact.

---

### 2. Purpose of AI Penetration Testing

The purpose of AI penetration testing is to establish evidence about whether identified vulnerabilities can be exploited within realistic attack conditions.

Objectives include:

* Discovering exploitable weaknesses
* Validating vulnerability severity
* Demonstrating attack paths
* Testing security controls
* Measuring blast radius
* Testing privilege boundaries
* Validating detection
* Testing containment
* Supporting remediation decisions

---

### 3. AI Penetration Testing vs AI Security Testing

AI security testing validates defined security properties through structured tests. Penetration testing goes further by attempting controlled exploitation.

```text id="pentest31a"
Security Testing
      |
      v
Security Requirement
      |
      v
Test Case
      |
      v
Control Validation


Penetration Testing
      |
      v
Potential Weakness
      |
      v
Exploit Attempt
      |
      v
Attack Path
      |
      v
Impact Validation
```

Penetration testing therefore complements, rather than replaces, broader AI security testing.

### 5. AI Penetration Testing Objectives

The assessment should determine whether an attacker can exploit weaknesses to achieve defined objectives such as:

* Unauthorized data access
* Security-control bypass
* Privilege escalation
* Tool abuse
* Agent manipulation
* Cross-user access
* Cross-tenant access
* Credential exposure
* Persistence
* Lateral movement

The objective is controlled validation of actual security risk.

---

### 6. Risk-Based AI Penetration Testing

Penetration-testing depth should be proportional to AI system risk.

Higher testing intensity is appropriate for systems with:

* Privileged tool access
* Sensitive data
* High autonomy
* External exposure
* Critical business functions
* Administrative capabilities
* Access to enterprise infrastructure

### 9. AI Penetration Testing Rules of Engagement

Rules of engagement define how the assessment may be conducted.

They should establish:

* Authorized targets
* Testing period
* Approved techniques
* Prohibited techniques
* Permitted identities
* Data restrictions
* Tool restrictions
* Stop conditions
* Escalation procedures
* Emergency contacts

The rules should prevent testing from unintentionally causing operational damage.

### 13. AI Vulnerability Discovery

Penetration testing should identify vulnerabilities across the AI stack.

Potential vulnerability categories include:

* Input handling
* Prompt injection
* Authorization
* Data isolation
* Tool permissions
* Agent controls
* API security
* Configuration
* Dependencies
* Infrastructure

Discovery should establish whether a weakness is actually exploitable.

---

### 14. AI Exploitability Assessment

A vulnerability should be evaluated for practical exploitability.

Assessment factors include:

* Preconditions
* Required privileges
* Attack complexity
* Reliability
* Required interaction
* Detectability
* Potential impact

A theoretical weakness should be distinguished from a demonstrated exploit path.

---

### 15. AI Prompt Injection Penetration Testing

Penetration testing should determine whether attacker-controlled input can influence trusted AI instructions.

Testing should evaluate whether injection can lead to:

* Unauthorized information disclosure
* Tool misuse
* Security-control bypass
* Agent manipulation
* Privilege escalation

---

### 17. AI Jailbreak Penetration Testing

Jailbreak penetration testing attempts to bypass defined AI restrictions and determine whether bypass can produce a security impact.

Testing should distinguish:

* Behavioral restriction bypass
* Application-control bypass
* Authorization bypass
* Actual unauthorized action

---

### 18. AI Authentication Penetration Testing

Authentication mechanisms should be tested against AI-specific attack paths.

Testing may evaluate:

* Authentication bypass
* Session manipulation
* Identity confusion
* Token misuse
* Service-account abuse

---

### 19. AI Authorization Penetration Testing

Authorization must be independently assessed.

Testing should determine whether AI-generated requests can obtain capabilities beyond the user's authorized permissions.

### 20. AI Privilege Escalation Penetration Testing

The assessment should determine whether an attacker can move from lower privilege to higher privilege.

The test should document:

* Initial identity
* Initial privilege
* Exploitation path
* Requested privilege
* Authorization decision
* Effective privilege
* Resulting access

---

### 21. Cross-User Penetration Testing

AI systems should be assessed for vulnerabilities that allow one user to access another user's information.

Potential targets include:

* Conversations
* Memory
* Documents
* Retrieved data
* Tool results
* User-specific configuration

---

### 22. Cross-Tenant Penetration Testing

Multi-tenant AI systems require explicit tenant-isolation testing.

Testing should determine whether vulnerabilities permit access to:

* Another tenant's data
* Another tenant's memory
* Another tenant's retrieval index
* Another tenant's tools
* Another tenant's administrative functions

---

### 23. AI Data Exfiltration Penetration Testing

Penetration testing should attempt to demonstrate whether protected information can be extracted.

Potential exfiltration paths include:

* Model output

* Tools

### 24. AI Secrets Penetration Testing

The assessment should determine whether sensitive secrets can be exposed.

* API keys
* Tokens
* Credentials

* Service credentials

### 25. AI RAG Penetration Testing

Testing should cover:

* Retrieval authorization
* Malicious documents
* Retrieval manipulation
* Ranking weaknesses
* Context injection
* Data leakage
* Tenant isolation

### 26. AI Vector Database Penetration Testing

Vector databases should be evaluated for exploitable weaknesses involving:

* Access control
* Query authorization
* Metadata
* Embeddings
* Index integrity
* Cross-tenant isolation

The assessment should determine whether weaknesses can produce unauthorized retrieval.

### 27. AI Memory Penetration Testing

Persistent memory should be assessed for vulnerabilities that permit:

* Unauthorized memory insertion
* Memory modification
* Cross-user retrieval
* Persistent manipulation
* Unauthorized disclosure

Memory should be treated as a security-sensitive component.

---

### 28. AI Model Penetration Testing

Model-level weaknesses should be assessed where they can produce practical system impact.

Potential areas include:

* Adversarial behavior
* Model manipulation
* Memorization
* Backdoor behavior
* Unsafe instruction following

Model findings should be correlated with application-level consequences.

* Affected components

### 46. AI Penetration Test Failure Management

Significant exploitation findings should trigger defined responses.

Depending on severity, responses may include:

* Immediate escalation
* Containment
* Release blocking
* Capability restriction
* Remediation
* Additional testing
* Risk review

---

### 47. AI Penetration Test Remediation and Retesting

Remediation should address the underlying vulnerability and attack path.

Retesting should verify:

1. The original exploit no longer succeeds.
2. Reasonable variants are mitigated.
3. Alternate attack paths are considered.
4. Security controls remain effective.
5. Regression testing passes.

---

### 48. AI Penetration Testing Independence

High-risk AI penetration testing should have appropriate independence from development.

Independent assessment can reduce the risk of:

* Confirmation bias
* Incomplete assumptions
* Scope minimization
* Underestimation of attack paths

The required level of independence should be proportional to AI risk.

---

### 49. Continuous AI Penetration Testing

AI penetration assurance should not be treated as permanently valid after one assessment.

Reassessment may be triggered by:

* New model
* Prompt changes
* New tools
* New agents
* RAG changes
* Memory changes
* Authorization changes
* Infrastructure changes
* New vulnerabilities
* Security incidents

Known exploitable paths should become regression tests where appropriate.

---

### 50. Core Principle of AI Penetration Testing

AI Penetration Testing must establish **controlled, authorized, risk-based, evidence-producing evidence that identified AI vulnerabilities can or cannot be exploited to produce meaningful security impact**.

The assessment must extend beyond the model:

```text id="pentest50k"
AI Vulnerability
      |
      v
Exploitability
      |
      v
Attack Path
      |
      v
Security-Control Interaction
      |
      v
Privilege / Data / Tool Access
      |
      v
Attack Chain
      |
      v
Business Impact
      |
      v
Detection
      |
      v
Containment
      |
      v
Recovery
```

AI penetration testing should evaluate the complete system boundary, including:

* Applications
* Models
* Prompts
* Context
* RAG
* Vector databases
* Memory
* Tools
* Agents
* APIs
* Identity
* Authorization
* Dependencies
* Containers
* Infrastructure
* Security controls
* Monitoring

Every significant finding should be attributable to the exact system state, attack path, tester identity, authorization context, evidence, and observed impact.

A successful exploit should not automatically imply unrestricted enterprise compromise. Independent authorization, least privilege, segmentation, tool controls, monitoring, and containment should constrain the impact of AI compromise.

Likewise, failure to exploit one vulnerability does not establish universal security.

**AI penetration-testing capability ≠ security assurance.
Vulnerability ≠ exploitability.
Exploitability ≠ enterprise compromise.
Model behavior ≠ authorization.
Tool request ≠ tool permission.
Agent capability ≠ enterprise authority.
Passing a penetration test ≠ permanent trust.**

Material changes to the AI system, new vulnerabilities, newly discovered attack paths, increased privileges, increased autonomy, new tools, changed data access, or significant security incidents should be capable of triggering renewed penetration testing, regression testing, containment, remediation, rollback, or reauthorization.
