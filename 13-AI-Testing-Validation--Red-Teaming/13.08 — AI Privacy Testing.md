# 13.08 — AI Privacy Testing

## Part 1 — AI Privacy Testing Foundations

### 1. Definition of AI Privacy Testing

AI Privacy Testing is the systematic evaluation of whether an AI system appropriately protects personal, sensitive, confidential, and otherwise regulated information throughout its lifecycle and operational workflows.

Testing should examine whether the AI system:

* Collects only authorized information
* Uses data for approved purposes
* Prevents unauthorized disclosure
* Enforces access controls
* Protects data during processing
* Prevents unintended retention
* Handles deletion correctly
* Protects information across model and application boundaries

Privacy testing must consider the complete AI system rather than only the underlying model.

---

### 2. Purpose of AI Privacy Testing

The purpose of AI Privacy Testing is to generate evidence that AI systems operate within defined privacy requirements and do not create unacceptable privacy risks.

Testing should identify:

* Unauthorized data exposure
* Excessive collection
* Improper data use
* Data retention failures
* Cross-user leakage
* Cross-tenant leakage
* Memorization
* Inference of sensitive information
* Inadequate deletion
* Privacy-control failures

---

### 3. AI Privacy Testing vs Security Testing

Privacy testing and security testing overlap but address different assurance questions.

**Security testing** primarily evaluates whether unauthorized parties can compromise systems, data, identities, or controls.

**Privacy testing** evaluates whether personal or sensitive information is appropriately collected, processed, disclosed, retained, inferred, and deleted according to defined privacy requirements.

A system can be technically secure while still violating privacy requirements through excessive collection or inappropriate use.

### 5. AI Privacy Testing Objectives

Privacy-testing objectives should be explicitly defined according to the system's intended use and risk.

Objectives may include determining whether:

* Personal data is collected appropriately
* Data is used only for approved purposes
* Access controls prevent unauthorized exposure
* Data is isolated between users or tenants
* Sensitive information is not unintentionally generated
* Retention requirements are enforced
* Deletion mechanisms work correctly
* Privacy controls remain effective after system changes

---

### 6. Risk-Based AI Privacy Testing

Privacy testing must be proportional to privacy risk.

Risk factors may include:

* Volume of personal data
* Sensitivity of data
* Number of individuals affected
* AI autonomy
* Model memorization potential
* Data-sharing arrangements
* External AI providers
* Geographic processing
* Retention requirements
* Consequences of disclosure

Higher-risk systems require deeper and more frequent privacy testing.

---

### 8. Personal Data Testing

Privacy testing should identify whether personal data is handled according to approved requirements.

Examples include:

* Names
* Email addresses
* Identification information
* Location information
* Account information
* Employment information
* Financial information

Testing should verify that data flows correspond to documented purposes.

### 9. Sensitive Data Testing

Sensitive information requires enhanced testing.

Depending on applicable requirements, this may include:

* Health information
* Financial information
* Biometric information
* Authentication information
* Precise location
* Government identifiers

Testing should determine whether sensitive data can be unnecessarily exposed, inferred, retained, or transferred.

### 11. Data Collection Testing

Testing should evaluate whether AI applications collect only information necessary for approved purposes.

Testing may examine:

* Required fields
* Optional fields
* Hidden collection
* Metadata
* Telemetry
* Browser/device information
* Conversation content

Unnecessary collection can create privacy risk even when the collected information is securely stored.

---

### 12. Purpose Limitation Testing

Privacy testing should determine whether personal information is used only for approved purposes.

Testing should evaluate whether data collected for one purpose is unexpectedly:

* Used for another purpose
* Included in prompts
* Used for training
* Added to memory
* Sent to external providers
* Used for analytics

---

### 13. Data Minimization Testing

AI systems should be tested to determine whether unnecessary personal information is processed.

Testing may examine:

* Prompt construction
* Context assembly
* Retrieval
* Memory
* Logging
* Tool parameters

The objective is to ensure that AI components receive only the information necessary for the approved task.

---

Testing should cover:

* Administrators
* Developers

### 15. Cross-User Privacy Testing

AI systems must be tested for leakage between users.

* Prompt
* Context
* Retrieval
* Memory
* Output
* Recommendations

---

### 16. Cross-Tenant Privacy Testing

Multi-tenant AI systems require explicit tenant-isolation testing.

Testing should attempt to determine whether tenant A can access or influence:

* Tenant B's documents
* Tenant B's embeddings
* Tenant B's memory
* Tenant B's conversations
* Tenant B's model context

Tenant isolation failures can represent severe privacy and security vulnerabilities.

---

Testing may include:

* Session creation
* Session termination
* Session expiration
* Reauthentication
* Session recovery
* New-session initialization

---

Testing should determine whether information from:

* Previous sessions
* Other users
* Shared contexts
* Archived conversations

### 19. AI Memory Privacy Testing

Persistent AI memory introduces additional privacy risks.

Testing should evaluate:

* Memory creation
* Memory retrieval
* Memory scope
* Memory modification
* Memory deletion
* Memory isolation

Memory should not retain personal information beyond its authorized purpose.

---

### 20. RAG Privacy Testing

RAG systems must be tested for unauthorized retrieval of personal information.

Testing should evaluate:

* Document access controls
* Retrieval filtering
* Tenant isolation
* Metadata filtering
* Embedding access
* Retrieval ranking

A secure document repository does not automatically guarantee privacy-safe AI retrieval.

---

### 21. Vector Database Privacy Testing

Vector stores should be tested for privacy leakage.

Testing may examine whether unauthorized users can:

* Retrieve embeddings
* Infer document contents
* Search restricted information
* Access another tenant's vectors
* Exploit metadata

Embeddings should not automatically be considered harmless simply because they are not human-readable documents.

---

### 22. AI Model Memorization Testing

Models should be tested for inappropriate memorization of personal information.

Testing may evaluate whether the model can reproduce:

* Personal identifiers
* Private conversations
* Sensitive records
* Training examples
* Confidential documents

The risk is particularly important for models trained or fine-tuned using sensitive information.

### 24. Fine-Tuning Privacy Testing

### 25. Inference Privacy Testing

* Membership in sensitive datasets
* Confidential relationships
* Sensitive classifications

Inference risks should be evaluated according to the intended system and threat model.

### 29. Context Privacy Testing

Material privacy remediation must be retested.

Retesting should determine whether:

1. The original privacy weakness has been addressed.
2. Unauthorized disclosure is prevented.
3. Retention/deletion requirements remain satisfied.
4. New privacy weaknesses have not been introduced.
5. Security and functional properties remain acceptable.

High-risk AI privacy assessments should receive appropriate independent validation.

Independent validation may involve:

* Privacy specialists
* AI security teams
* Data protection teams
* Internal audit
* Qualified external assessors

Privacy should be continuously evaluated where risk requires ongoing assurance.

Monitoring should consider:

* New data sources

### 49. AI Privacy Testing and Assurance

Privacy testing establishes evidence about defined privacy properties under defined conditions.

It does not independently establish:

* Legal compliance
* Complete security
* Fairness
* Reliability
* Overall AI safety

Privacy assurance requires interpretation of test evidence within the applicable legal, regulatory, contractual, organizational, and technical context.

---

### 50. Core Principle of AI Privacy Testing

**AI Privacy Testing must establish evidence that personal, sensitive, confidential, and otherwise protected information is collected, processed, transmitted, retrieved, generated, stored, retained, and deleted according to defined privacy requirements and authorized purposes. Testing must examine the complete AI data lifecycle and technical architecture, including applications, prompts, context, models, training data, fine-tuning, retrieval, vector stores, memory, tools, agents, APIs, logs, monitoring, backups, and external AI providers where they can affect privacy. Testing must evaluate data minimization, purpose limitation, access control, user and tenant isolation, memorization, inference, extraction, prompt and context exposure, output leakage, logging, retention, deletion, privacy rights processes, provider data handling, and privacy-control effectiveness according to risk. Sensitive test data must itself be protected, and fairness or privacy attributes used for controlled evaluation must not automatically become production inputs. Every test must be attributable and traceable to the exact system state, data flow, configuration, model, dataset, and test conditions evaluated. Privacy findings must be classified, remediated, independently validated where required, and retested. Previously identified privacy weaknesses should become regression tests where practical. Material changes to models, datasets, prompts, applications, retrieval, memory, tools, providers, data flows, logging, retention, or processing purposes must be capable of triggering renewed privacy testing and reassessment. Privacy evidence is conditional on the system state and processing conditions evaluated; passing a privacy test does not establish permanent privacy assurance or universal legal compliance.**

### 117. Core Control Principle

**AI Privacy Testing controls must establish a controlled, measurable, attributable, and repeatable mechanism for determining whether AI systems appropriately protect personal, sensitive, confidential, and regulated information throughout collection, processing, transmission, retrieval, generation, storage, retention, and deletion. Controls must cover the complete AI privacy attack and processing surface, including applications, models, training data, fine-tuning, prompts, context, retrieval, vector stores, memory, tools, agents, APIs, logs, monitoring, backups, and external AI providers where applicable. Privacy requirements must map to data flows, test cases, evidence, and acceptance criteria. Testing must evaluate data collection, purpose limitation, minimization, access control, user and tenant isolation, session and conversation boundaries, memory, retrieval, model memorization, inference, extraction, prompt and context exposure, output leakage, logging, monitoring, APIs, provider processing, data transfers, retention, deletion, backups, applicable data-subject rights, and privacy-control effectiveness according to risk. Sensitive test data must itself be minimized, isolated, protected, and appropriately authorized. Every assessment must identify the exact system state, dataset, model, configuration, data flows, environment, tester, and test conditions. Privacy results must maintain integrity and provenance. Material findings must be classified, remediated, independently validated where required, and retested. Automated privacy failures must be capable of triggering escalation, remediation, containment, or release blocking. Previously identified weaknesses should become regression tests where practical. Material changes to models, datasets, prompts, applications, retrieval, memory, tools, providers, data flows, logging, retention, or processing purposes must be capable of triggering renewed privacy testing. Privacy evidence remains conditional on the system state, processing activities, data categories, populations, providers, and assumptions evaluated; passing a privacy test does not establish permanent privacy assurance or universal legal compliance.**
