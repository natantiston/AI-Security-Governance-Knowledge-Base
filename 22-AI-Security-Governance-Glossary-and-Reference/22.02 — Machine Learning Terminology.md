# 22.02 — Machine Learning Terminology

## Part 1 — Foundations of Machine Learning and Learning Paradigms

## 1. Introduction

Machine Learning (ML) is one of the foundational disciplines behind modern Artificial Intelligence. It enables systems to identify patterns, learn relationships from data, generate predictions, classify information, detect anomalies, and support or automate decisions.

In enterprise environments, ML is increasingly embedded in business applications, cybersecurity platforms, telecommunications infrastructure, financial systems, customer management platforms, cloud services, and operational technology.

However, understanding ML from a cybersecurity and Governance, Risk, and Compliance (GRC) perspective requires more than knowing how an algorithm works.

An organization must understand:

- What type of machine learning is being used?
- What data is used to train, validate, and test the model?
- Who controls the training process?
- How is model performance measured?
- What happens when the model produces an incorrect prediction?
- Can the model's behavior change after deployment?
- Who is accountable for decisions supported or generated by the model?
- What security controls protect the model, its data, and its operational environment?

These questions are important because different ML techniques introduce different security, privacy, operational, and governance risks.

For example, a supervised learning model trained to detect fraudulent transactions presents different governance considerations from an unsupervised learning model designed to detect unusual network traffic.

Similarly, a reinforcement learning system that learns through interactions with an environment introduces different control requirements from a traditional classification model.

This lesson establishes the terminology needed to understand machine learning technologies and assess their implications within enterprise AI governance.

### 1.1 Learning Objectives

By completing this lesson, you should be able to:

1. Explain the fundamental terminology associated with machine learning.
2. Distinguish machine learning from traditional rule-based programming.
3. Identify the major machine learning paradigms.
4. Understand how training, validation, testing, and inference differ.
5. Explain the roles of datasets, features, labels, parameters, and hyperparameters.
6. Understand how ML models learn patterns and generate predictions.
7. Identify the governance and cybersecurity implications of different ML approaches.
8. Apply ML terminology when conducting enterprise AI risk assessments.

## 2. Machine Learning Fundamentals

### 2.1 Machine Learning (ML)

Definition:

Machine Learning is a branch of Artificial Intelligence that enables computer systems to learn patterns and relationships from data and use those learned patterns to perform tasks without requiring every individual decision rule to be explicitly programmed.

Instead of relying exclusively on predefined instructions, an ML system uses algorithms to identify statistical relationships within data and construct a model that can generalize to previously unseen inputs.

Example:

A telecommunications operator wants to identify customers who are likely to terminate their subscriptions.

A traditional programming approach might use predefined conditions:

- Customer has submitted three complaints.
- Customer has not used the service for 30 days.
- Customer has requested contract cancellation information.

If the conditions are satisfied, the system flags the customer as high risk.

A machine learning approach uses historical customer data, including:

- Subscription duration.
- Monthly spending.
- Complaint history.
- Network quality.
- Service usage.
- Payment behavior.
- Previous cancellation records.

The ML algorithm learns relationships between these variables and historical customer churn outcomes.

The trained model can then estimate the probability that an existing customer will terminate their subscription.

GRC implications:

- Training data must be accurate, relevant, and appropriately authorized.
- Model performance must be measured and documented.
- Historical biases must be identified.
- Predictions should not automatically be treated as factual conclusions.
- The business owner must define how model outputs influence customer-related decisions.

### 2.2 Traditional Programming vs. Machine Learning

The fundamental difference is how the system obtains the logic used to produce an outcome.

Traditional programming

| Dimension     | Traditional programming              | Machine learning                                                      |
| ------------- | ------------------------------------ | --------------------------------------------------------------------- |
| Logic         | Explicitly defined by developers     | Learned from training data                                            |
| Primary input | Data and programmed rules            | Training data and learning algorithm                                  |
| Output        | Result of executing rules            | Result of applying learned patterns                                   |
| Adaptation    | Requires rule modification           | Requires model retraining or adaptation                               |
| Testing       | Functional and rule validation       | Functional, statistical, and performance evaluation                   |
| Main risks    | Programming errors and logic defects | Data quality, bias, model errors, drift, and adversarial manipulation |

Important distinction:

Machine learning does not eliminate programming.

ML systems still require software engineering, data pipelines, model configuration, infrastructure, security controls, and operational processes. What changes is that part of the decision logic is learned from data rather than being entirely specified through explicit rules.

GRC consideration: Organizations must govern both conventional software components and the ML-specific components. A model may be statistically accurate while the application integrating it remains insecure.

### 2.3 Machine Learning Algorithm

Definition:

A machine learning algorithm is a computational procedure used to learn patterns or relationships from data and produce a model.

The algorithm defines the learning method, including how the system processes data, adjusts parameters, and attempts to optimize a particular objective.

Examples include:

- Linear Regression.
- Logistic Regression.
- Decision Trees.
- Random Forest.
- Support Vector Machines (SVM).
- K-Nearest Neighbors (KNN).
- K-Means Clustering.
- Gradient Boosting.
- Neural Networks.

Example:

A bank wants to identify potentially fraudulent transactions.

It may use a Random Forest algorithm to analyze historical transactions and learn patterns associated with fraudulent activity.

The algorithm processes the training dataset and produces a trained model containing learned decision structures.

Important distinction:

An algorithm is not the same as a model.

| Term      | Meaning                                                       |
| --------- | ------------------------------------------------------------- |
| Algorithm | The learning procedure                                        |
| Model     | The learned representation produced by the learning procedure |
| Training  | The process of applying the algorithm to data                 |
| Inference | Using the trained model to produce an output                  |

### 2.4 Machine Learning Model

Definition:

A machine learning model is the learned computational representation of patterns and relationships extracted from training data.

Once trained, the model can process new inputs and generate predictions, classifications, scores, recommendations, or other outputs.

Example:

A telecommunications operator uses a supervised learning algorithm to develop a network fault prediction model.

The model learns relationships between:

- Network latency.
- Packet loss.
- Signal strength.
- Device temperature.
- Historical equipment failures.
- Traffic utilization.

Once trained, it can estimate the likelihood of equipment failure based on current network telemetry.

GRC implications:

The model should have identifiable ownership, documentation, versioning, validation evidence, deployment approval, and monitoring arrangements.

An organization should also know:

- Which algorithm produced the model?
- Which training dataset was used?
- When was the model trained?
- What is the model's approved purpose?
- Which systems consume its outputs?
- Who can modify, replace, or retire it?

### 2.5 Model Parameters

Definition:

Model parameters are internal values learned automatically during the training process.

They determine how a trained model processes inputs and produces outputs.

The learning algorithm adjusts these values to minimize a defined error or loss function, or otherwise optimize its learning objective.

Example:

In a linear regression model:

\\[ y = wx + b \\]

Where:

- \\(y\\) = predicted output.
- \\(x\\) = input feature.
- \\(w\\) = learned weight.
- \\(b\\) = learned bias.

The model learns the values of \\(w\\) and \\(b\\) from training data.

GRC implications:

Model parameters are important because unauthorized modification may change the model's behavior.

Security controls should protect:

- Model files.
- Parameter files.
- Model checkpoints.
- Model repositories.
- Deployment artifacts.

Unauthorized changes to a model can introduce malicious or unintended behavior without necessarily changing the surrounding application code.

### 2.6 Hyperparameters

Definition:

Hyperparameters are configuration values established before or during model training that influence how the learning algorithm operates.

Unlike model parameters, hyperparameters are generally not learned directly as part of the model's ordinary parameter optimization process.

Examples include:

- Learning rate.
- Number of training epochs.
- Batch size.
- Maximum tree depth.
- Number of decision trees.
- Regularization strength.
- Number of clusters.

Example:

A machine learning engineer develops a Random Forest model for detecting suspicious network activity.

The engineer configures:

- Number of trees: 200.
- Maximum tree depth: 15.
- Minimum samples per leaf: 5.

These settings influence the model's learning process and resulting performance.

GRC implications:

Hyperparameter configurations should be documented and controlled because changes can affect:

- Prediction accuracy.
- Model complexity.
- Overfitting.
- Generalization.
- Processing requirements.
- Operational stability.

A production model should not be modified through uncontrolled configuration changes.

### 2.7 Feature

Definition:

A feature is an individual measurable input variable used by a machine learning model to identify patterns and generate predictions.

Features represent characteristics or attributes of the data being analyzed.

Examples in telecommunications:

| Feature                  | Description                                      |
| ------------------------ | ------------------------------------------------ |
| Average network latency  | Average communication delay                      |
| Packet loss percentage   | Percentage of packets not successfully delivered |
| Monthly data consumption | Customer data usage                              |
| Number of complaints     | Customer complaint frequency                     |
| Payment delay            | Number of days a payment is overdue              |
| Signal strength          | Measured radio signal quality                    |

Example:

A model predicts whether a customer will cancel a subscription.

Potential input features include:

- Monthly spending.
- Number of complaints.
- Contract duration.
- Service interruptions.
- Customer support interactions.

The model analyzes the relationship between these features and historical churn outcomes.

GRC implications:

Features require governance because they may contain personal, confidential, sensitive, or commercially valuable information.

The organization should assess:

- Whether the feature is necessary.
- Whether its use is lawful and authorized.
- Whether it introduces bias.
- Whether it could expose sensitive attributes indirectly.
- Whether its quality and accuracy are adequate.

### 2.8 Label

Definition:

A label is the known target outcome associated with a training example in supervised machine learning.

Labels provide the reference information that allows the algorithm to learn relationships between input features and expected outputs.

Example:

A dataset used to train a fraud detection model might contain:

| Transaction ID | Amount | Location         | Label      |
| -------------- | ------ | ---------------- | ---------- |
| TX001          | €500   | Madrid           | Legitimate |
| TX002          | €4,500 | Unknown location | Fraudulent |
| TX003          | €35    | Madrid           | Legitimate |
| TX004          | €8,000 | Foreign country  | Fraudulent |

In this example, the label indicates whether the transaction was legitimate or fraudulent.

GRC implications:

Incorrect labels can undermine model reliability.

For example, if legitimate transactions are incorrectly classified as fraudulent in the training dataset, the model may learn misleading patterns.

Label quality controls should consider:

- Labeling methodology.
- Source reliability.
- Human review.
- Labeling consistency.
- Disputed or ambiguous records.
- Label correction and audit trails.

### 2.9 Dataset

Definition:

A dataset is an organized collection of data used for developing, training, validating, testing, or operating a machine learning system.

Datasets may contain structured, semi-structured, or unstructured information.

Examples include:

- Customer transaction records.
- Network telemetry.
- Security event logs.
- Images.
- Audio recordings.
- Text documents.
- Sensor measurements.

Common dataset categories:

| Dataset category   | Purpose                                                           |
| ------------------ | ----------------------------------------------------------------- |
| Training dataset   | Used to teach the model                                           |
| Validation dataset | Used to evaluate and tune model configurations during development |
| Test dataset       | Used for an independent evaluation of model performance           |
| Production dataset | Used as input when the deployed model performs inference          |
| Benchmark dataset  | Used to compare model performance against defined reference tasks |

GRC implications:

Dataset governance must address:

- Data ownership.
- Data provenance.
- Data classification.
- Data quality.
- Privacy and consent requirements, where applicable.
- Retention and deletion.
- Access controls.
- Data integrity.
- Third-party data restrictions.

A model's quality and reliability are strongly influenced by the quality and representativeness of the data used to develop it.

## 3. Machine Learning Learning Paradigms

Machine learning approaches are commonly categorized according to how an algorithm receives information and learns from data.

The four major paradigms are:

1. Supervised learning.
2. Unsupervised learning.
3. Semi-supervised learning.
4. Reinforcement learning.

Self-supervised learning is also an important paradigm, particularly in modern deep learning and foundation model development.

Each paradigm introduces different technical characteristics and governance considerations.

### 3.1 Supervised Learning

Definition:

Supervised learning is a machine learning approach in which a model is trained using labeled data containing input examples and their corresponding expected outputs.

The algorithm learns the relationship between the input features and the known labels.

After training, the model can use this learned relationship to predict outcomes for previously unseen data.

Learning process:

Labeled Training Dataset

Input features + known outcomes

Learning Algorithm

Learns relationships between inputs and labels

Trained Model

Prediction on New Data

Example: Telecom customer churn prediction

A telecommunications operator has historical customer records containing:

- Customer age or age group, where appropriate.
- Subscription type.
- Monthly expenditure.
- Complaint history.
- Network service quality.
- Contract duration.
- Cancellation status.

The model learns which patterns are associated with customers who previously cancelled their subscriptions.

It then estimates churn risk for existing customers.

Common supervised learning applications:

- Fraud detection.
- Spam classification.
- Credit risk assessment.
- Customer churn prediction.
- Malware classification.
- Network fault prediction.
- Image classification.
- Medical image analysis.

GRC and cybersecurity implications:

| Risk area         | Governance consideration                                             |
| ----------------- | -------------------------------------------------------------------- |
| Data quality      | Verify the accuracy and completeness of labeled data                 |
| Label integrity   | Establish reliable labeling and review procedures                    |
| Bias              | Assess whether historical labels encode discriminatory outcomes      |
| Privacy           | Ensure training data is lawfully collected and processed             |
| Model performance | Measure false positives, false negatives, and other relevant metrics |
| Model security    | Protect training data, model artifacts, and development pipelines    |
| Accountability    | Define who is responsible for decisions based on predictions         |

Important consideration:

A supervised model learns from historical examples. If historical decisions were biased, inaccurate, or inconsistent, the model may reproduce those patterns.

The fact that a model has been trained on historical organizational data does not automatically make its predictions objective or reliable.

### 3.2 Classification

Definition:

Classification is a supervised machine learning task in which a model assigns an input to one or more predefined categories.

The model learns from labeled examples and predicts the category associated with new inputs.

Examples:

| Application             | Classification categories           |
| ----------------------- | ----------------------------------- |
| Email security          | Spam / Not spam                     |
| Fraud detection         | Fraudulent / Legitimate             |
| Malware detection       | Malicious / Benign                  |
| Customer churn          | Likely to churn / Unlikely to churn |
| Network monitoring      | Normal / Suspicious                 |
| Document classification | Confidential / Internal / Public    |

Example: Cybersecurity email classification

An enterprise security platform uses an ML model to classify incoming emails.

The model evaluates characteristics such as:

- Sender reputation.
- Email content.
- URL patterns.
- Attachment characteristics.
- Historical threat indicators.

The model assigns an email to a category such as legitimate, spam, or phishing.

Important terminology:

- Binary classification: Predicts between two classes.
- Multiclass classification: Predicts one class among more than two mutually exclusive classes.
- Multilabel classification: Assigns multiple labels to a single input.

GRC implications:

Classification errors can create operational consequences.

For example:

- False positives may block legitimate business communications.
- False negatives may allow phishing emails into the organization.
- Incorrect confidentiality classification may expose sensitive information.

Organizations should define acceptable error thresholds and escalation processes based on the business impact of classification errors.

### 3.3 Regression

Definition:

Regression is a supervised machine learning task in which a model predicts a continuous numerical value.

Unlike classification, which predicts categories, regression estimates a numerical outcome.

Examples:

| Application            | Predicted value                        |
| ---------------------- | -------------------------------------- |
| Network performance    | Expected latency in milliseconds       |
| Energy management      | Predicted electricity consumption      |
| Financial forecasting  | Expected revenue                       |
| Customer analytics     | Expected customer lifetime value       |
| Predictive maintenance | Estimated remaining equipment lifetime |
| Demand forecasting     | Expected number of transactions        |

Example: Network latency prediction

A telecommunications operator trains a regression model using:

- Historical network traffic.
- Time of day.
- Network utilization.
- Geographic location.
- Previous latency measurements.

The model estimates expected latency for a particular network segment.

Its output may be:

\\[ \text{Predicted Latency} = 42.5 \text{ ms} \\]

GRC implications:

The organization should assess:

- Accuracy of numerical predictions.
- Acceptable error margins.
- Impact of inaccurate forecasts.
- Model drift.
- Data representativeness.
- Whether predictions are being used beyond their approved purpose.

For critical operational environments, an inaccurate numerical prediction may lead to capacity planning errors, degraded service, or inappropriate resource allocation.

### 3.4 Unsupervised Learning

Definition:

Unsupervised learning is a machine learning approach in which algorithms analyze data without relying on predefined target labels.

The objective is to identify underlying structures, patterns, similarities, relationships, or anomalies within the dataset.

Unlike supervised learning, the algorithm is not provided with the correct answer for every training example.

Learning process:

Unlabeled Dataset

Input data without predefined target labels

Unsupervised Learning Algorithm

Identifies patterns and structures

Identified Patterns or Clusters

Example: Network anomaly detection

A telecommunications operator collects millions of network traffic records.

The organization does not have labels identifying every normal and malicious network activity.

An unsupervised learning algorithm analyzes traffic characteristics and identifies groups of similar behavior.

It may identify an unusual pattern involving:

- Unexpected traffic volume.
- Unusual connection frequency.
- Abnormal protocol usage.
- Unusual communication destinations.

The security team investigates these patterns to determine whether they indicate malicious activity or legitimate operational changes.

Common unsupervised learning applications:

- Network anomaly detection.
- Customer segmentation.
- Fraud pattern discovery.
- Behavioral analysis.
- Log analysis.
- Data clustering.
- Market segmentation.

GRC and cybersecurity implications:

Unsupervised learning can identify previously unknown patterns, but an unusual pattern is not necessarily a security incident.

Organizations must establish:

- Baseline behavior definitions.
- Alert investigation procedures.
- False-positive management.
- Analyst review and escalation.
- Model performance monitoring.
- Data access and privacy controls.

Important distinction:

An anomaly detection model identifies deviations from learned or established patterns. It does not automatically determine whether the deviation is malicious, fraudulent, or unauthorized.

### 3.5 Clustering

Definition:

Clustering is an unsupervised learning technique that groups data points according to their similarities or other defined relationships.

The objective is to organize data into groups, known as clusters, without requiring predefined labels.

Example: Customer segmentation

A telecommunications operator wants to group customers according to their service usage.

The model analyzes:

- Monthly data consumption.
- Voice call duration.
- Subscription spending.
- Service preferences.
- Contract characteristics.

It may identify clusters such as:

| Cluster   | Observed characteristics                       |
| --------- | ---------------------------------------------- |
| Cluster A | High data usage and high monthly spending      |
| Cluster B | Low data usage and low monthly spending        |
| Cluster C | High voice usage and moderate data consumption |
| Cluster D | Low overall activity                           |

The business can use these clusters to understand customer behavior and improve service offerings.

Common clustering algorithms:

- K-Means.
- Hierarchical Clustering.
- DBSCAN.
- Gaussian Mixture Models.

GRC implications:

Clustering can unintentionally create groups based on sensitive or discriminatory characteristics, particularly when input features act as proxies for protected attributes.

Organizations should evaluate:

- Feature selection.
- Grouping outcomes.
- Potential discriminatory effects.
- Data minimization.
- Business purpose.
- Appropriate human review.

### 3.6 Anomaly Detection

Definition:

Anomaly detection is the process of identifying observations, events, or patterns that differ significantly from expected or established behavior.

It can be implemented using supervised, unsupervised, or semi-supervised techniques.

Examples:

- Unusual user login activity.
- Unexpected data transfers.
- Abnormal network traffic.
- Unusual transaction behavior.
- Unexpected API access patterns.
- Abnormal resource consumption.

Example: Insider threat detection

An organization uses an anomaly detection model to monitor user activity.

A particular employee account normally accesses a limited set of business applications during working hours.

The model detects an unusual sequence:

1. Access to a previously unused application.
2. Large-scale document downloads.
3. Access outside normal working hours.
4. Transfers to an unusual external destination.

The model raises an alert for security investigation.

GRC implications:

An anomaly is an indicator requiring investigation, not proof of misconduct.

Organizations should establish:

- Appropriate monitoring authorization.
- Employee privacy safeguards.
- Alert severity definitions.
- Investigation procedures.
- Evidence preservation.
- Human review before disciplinary action.

### 3.7 Semi-Supervised Learning

Definition:

Semi-supervised learning is a machine learning approach that combines a relatively small amount of labeled data with a larger amount of unlabeled data during model training.

The approach is useful when obtaining reliable labels is expensive, time-consuming, or requires specialist expertise.

Learning process:

Labeled Data

# Small

Known outcomes

Unlabeled Data

# Large

No known outcomes

Semi-Supervised Learning

Trained Model

Example: Malware detection

A security organization has:

- 5,000 malware samples classified by security analysts.
- 500,000 additional files without verified labels.

A semi-supervised learning approach can use the labeled samples alongside the larger unlabeled dataset to learn useful representations and improve classification performance.

GRC implications:

- Verify the quality of the labeled subset.
- Assess the reliability of pseudo-labels if used.
- Monitor propagation of incorrect labels.
- Document how unlabeled data contributes to training.
- Establish validation and testing procedures.
- Evaluate whether the combined dataset introduces bias.

Important distinction:

Semi-supervised learning is not simply a model that learns without labels. It uses both labeled and unlabeled data.

### 3.8 Self-Supervised Learning

Definition:

Self-supervised learning is a machine learning approach in which a model generates its own training supervision from the structure or content of the input data.

Instead of relying on manually assigned labels for every example, the training process creates a learning objective from the data itself.

This technique is particularly important in modern deep learning and foundation model development.

Example: Language model pretraining

A language model is trained using large collections of text.

A common objective is to predict a missing or subsequent token based on surrounding context.

For example:

Input:

> The capital of France is \_\_\_.

The model learns to predict:

> Paris.

The training objective is derived from the text itself rather than requiring a human to manually label every sentence with its expected answer.

Other self-supervised learning approaches include:

- Masked language modeling.
- Next-token prediction.
- Contrastive learning.
- Reconstruction-based learning.

GRC implications:

Self-supervised learning may involve very large datasets collected from multiple sources.

Governance must therefore address:

- Data provenance.
- Copyright and licensing.
- Privacy and personal data.
- Data quality.
- Harmful or inappropriate content.
- Training data contamination.
- Model memorization and information leakage.
- Documentation of training objectives.

Important distinction:

Self-supervised learning is not the same as unsupervised learning in every technical context. Self-supervised methods create supervisory signals from the data itself, whereas conventional unsupervised approaches seek structure without explicitly constructing target labels in the same manner.

### 3.9 Reinforcement Learning

Definition:

Reinforcement Learning (RL) is a machine learning paradigm in which an agent learns how to make decisions by interacting with an environment and receiving feedback in the form of rewards or penalties.

The agent attempts to learn a strategy that maximizes cumulative reward over time.

Unlike supervised learning, the agent is not necessarily given a correct answer for every individual decision.

Instead, it learns from the consequences of its actions.

Core components:

| Term        | Definition                                                   |
| ----------- | ------------------------------------------------------------ |
| Agent       | The entity that makes decisions                              |
| Environment | The system or context in which the agent operates            |
| State       | The current condition of the environment                     |
| Action      | A decision or operation performed by the agent               |
| Reward      | Feedback indicating the desirability of an outcome           |
| Policy      | The strategy used by the agent to select actions             |
| Episode     | A sequence of interactions between the agent and environment |
| Return      | Cumulative reward obtained over time                         |

Reinforcement learning architecture:

Agent

Selects an action using its policy

Action

Environment

Changes in response to the action

New state and reward

Feedback to Agent

Updates learning and future action selection

Repeated interaction

Example: Network resource optimization

A telecommunications operator wants to optimize network resource allocation.

An RL agent interacts with a simulated network environment.

It may learn to:

- Allocate bandwidth.
- Adjust network parameters.
- Manage congestion.
- Optimize resource utilization.
- Respond to changing traffic conditions.

The agent receives rewards for meeting defined performance objectives and penalties for actions that degrade service.

GRC and cybersecurity implications:

Reinforcement learning introduces additional governance considerations because the model learns through interaction and action.

Key risks include:

- Unsafe exploration.
- Reward manipulation.
- Unexpected behavior.
- Unintended operational consequences.
- Inadequate simulation environments.
- Unauthorized actions.
- Changes in behavior after retraining.
- Insufficient human oversight.

Critical governance requirement:

An RL agent should not be allowed to experiment freely in a production environment where its actions could affect critical services.

Organizations should define action boundaries, testing environments, approval mechanisms, rollback procedures, and monitoring requirements.

## 4. Consolidated Comparison of Machine Learning Paradigms

The following table summarizes the major learning approaches and their typical enterprise applications.

| Learning paradigm | Training data                   | Primary objective                                        | Enterprise example            |
| ----------------- | ------------------------------- | -------------------------------------------------------- | ----------------------------- |
| Supervised        | Labeled                         | Learn input-to-output relationships                      | Fraud classification          |
| Unsupervised      | Unlabeled                       | Discover patterns and structures                         | Network anomaly detection     |
| Semi-supervised   | Labeled and unlabeled           | Learn using limited labels and additional unlabeled data | Malware detection             |
| Self-supervised   | Data-derived supervision        | Learn representations or predict parts of the input      | Foundation model pretraining  |
| Reinforcement     | Interaction and reward feedback | Learn a decision-making policy                           | Network resource optimization |

### 4.1 Choosing the Appropriate Learning Paradigm

Selecting an ML paradigm is not simply a technical decision. It depends on the business objective, available data, risk tolerance, operational environment, and governance requirements.

| Business requirement                           | Potential approach       | Reason                                        |
| ---------------------------------------------- | ------------------------ | --------------------------------------------- |
| Predict customer churn                         | Supervised learning      | Historical churn outcomes can provide labels  |
| Detect unknown network anomalies               | Unsupervised learning    | Patterns may not have predefined labels       |
| Classify malware with limited verified samples | Semi-supervised learning | Combines verified samples with unlabeled data |
| Pretrain a language model                      | Self-supervised learning | Training objectives can be derived from text  |
| Optimize network resources through interaction | Reinforcement learning   | Learns actions through feedback               |

The selected approach must be validated against the intended use case. No paradigm is automatically appropriate merely because it is technically available.

## 5. Machine Learning Terminology from an Enterprise GRC Perspective

Understanding machine learning terminology allows GRC professionals to ask more precise questions during AI assessments.

A risk assessment should not stop at identifying that a project uses machine learning. It should identify the specific learning approach, the data involved, the model's purpose, and the operational consequences of its outputs.

### 5.1 ML Governance Assessment Matrix

| ML concept               | GRC assessment question                                          | Evidence expected                          |
| ------------------------ | ---------------------------------------------------------------- | ------------------------------------------ |
| Algorithm                | Which learning algorithm is being used and why?                  | Technical design documentation             |
| Model                    | What is the approved model and business purpose?                 | Model inventory and model card             |
| Parameters               | How are model parameters protected?                              | Model repository access controls           |
| Hyperparameters          | Who approves training configuration changes?                     | Configuration records and change approvals |
| Features                 | Which input variables influence predictions?                     | Feature inventory                          |
| Labels                   | How are training labels generated and validated?                 | Labeling methodology                       |
| Dataset                  | What are the sources and classifications of training data?       | Data inventory and lineage                 |
| Supervised learning      | How is label accuracy established?                               | Label quality assessment                   |
| Unsupervised learning    | How are detected anomalies investigated?                         | Alert handling procedures                  |
| Semi-supervised learning | How are unlabeled data and derived labels controlled?            | Data and training documentation            |
| Self-supervised learning | How is training data provenance established?                     | Dataset provenance records                 |
| Reinforcement learning   | What actions can the agent perform, and within which boundaries? | Action policy and safety controls          |

### 5.2 Common ML Governance Failures

Organizations may encounter the following problems when implementing ML systems:

1\. Uncontrolled training data: Models are developed using data without adequate ownership, classification, or authorization.

2\. Poor label quality: Incorrect labels cause the model to learn misleading relationships.

3\. Insufficient model documentation: There is no reliable record of the model's purpose, training process, or limitations.

4\. Unapproved feature usage: Models use unnecessary or sensitive variables without appropriate justification.

5\. Weak model validation: Performance is evaluated only during development, with insufficient independent testing.

6\. Uncontrolled model changes: Models or hyperparameters are modified without documented approvals.

7\. Inadequate operational monitoring: Model performance deteriorates without detection.

8\. Unclear accountability: Business owners, model developers, and system operators do not understand their respective responsibilities.

### 5.3 Practical Enterprise Scenario

Scenario: AI-powered cybersecurity monitoring platform

A telecommunications operator deploys a machine learning platform to detect suspicious network behavior.

The platform:

- Collects network traffic metadata.
- Analyzes user and device behavior.
- Identifies abnormal traffic patterns.
- Assigns anomaly scores.
- Generates alerts for the Security Operations Center (SOC).
- Allows analysts to investigate suspicious activity.

The platform uses unsupervised learning for anomaly detection and supervised learning for classifying known threat patterns.

A GRC assessment should establish:

| Assessment area   | Required consideration                                                    |
| ----------------- | ------------------------------------------------------------------------- |
| Business purpose  | Detection of suspicious network activity                                  |
| Data governance   | Authorization and classification of network telemetry                     |
| Model governance  | Documentation and ownership of both models                                |
| Security          | Protection of training datasets and model artifacts                       |
| Performance       | Detection accuracy and false-positive rates                               |
| Human oversight   | SOC analyst validation before incident escalation                         |
| Change management | Approval of model updates and training changes                            |
| Accountability    | Clear responsibility between SOC, ML engineering, and security governance |
| Monitoring        | Detection of performance deterioration and data drift                     |
| Auditability      | Evidence of model versions, alerts, investigations, and decisions         |

Key governance observation:

The platform contains two distinct models with different purposes. Their risks, performance requirements, validation evidence, and operating controls should be assessed separately rather than treating the platform as one undifferentiated AI component.

| Algorithm vs. model                            | The algorithm learns; the model represents what was learned                                                              |
| Parameters vs. hyperparameters                 | Parameters are learned; hyperparameters configure the learning process                                                   |
| Feature vs. label                              | Features are inputs; labels are known target outcomes                                                                    |
| Training vs. inference                         | Training develops the model; inference uses the trained model                                                            |
| Classification vs. regression                  | Classification predicts categories; regression predicts numerical values                                                 |
| Supervised vs. unsupervised                    | Supervised learning uses labels; unsupervised learning identifies patterns without predefined target labels              |
| Semi-supervised vs. self-supervised            | Semi-supervised learning combines labeled and unlabeled data; self-supervised learning derives supervision from the data |
| Anomaly vs. malicious activity                 | An anomaly is an unusual observation, not automatically a security incident                                              |
| Reinforcement learning vs. supervised learning | Reinforcement learning learns from interaction and reward feedback rather than relying exclusively on labeled examples   |

### Core Principle

Machine learning governance begins with understanding how a model learns, what data influences its behavior, and how its outputs affect enterprise decisions. Without this understanding, an organization cannot reliably assess model risk, establish appropriate controls, or demonstrate accountability for AI-enabled outcomes.

## Part 2 — Model Training, Evaluation, Optimization, and Performance

## 7. Machine Learning Model Development Lifecycle

Understanding machine learning requires understanding how a model is developed, evaluated, approved, deployed, and maintained.

A machine learning model does not become reliable simply because it has completed training. It must undergo a structured development and validation process to establish whether it performs adequately for its intended purpose.

From an enterprise GRC perspective, the model development lifecycle is important because every stage introduces potential risks involving data quality, security, privacy, performance, accountability, and operational control.

### 7.1 Model Training

Definition:

Model training is the process through which a machine learning algorithm learns patterns and relationships from a training dataset by adjusting its internal parameters according to a defined learning objective.

During training, the algorithm processes examples, generates predictions or representations, evaluates errors against its learning objective, and updates its parameters.

The objective is to produce a model capable of performing its intended task on data it has not previously encountered.

Example:

A telecommunications operator develops a model to predict network equipment failures.

The training dataset contains historical information about:

- Equipment temperature.
- CPU utilization.
- Memory consumption.
- Network traffic.
- Packet loss.
- Historical equipment failures.
- Maintenance records.

The algorithm analyzes these records and learns relationships between operational conditions and equipment failures.

The resulting model can estimate failure risk using new network telemetry.

Prediction and Error Calculation

GRC implications:

- Training data must have documented sources and appropriate authorization.
- Training environments must be protected against unauthorized access.
- Model training configurations must be documented.
- Training activities should be reproducible where required.
- Model artifacts must be protected against unauthorized modification.
- Training results must be evaluated before production approval.

### 7.2 Training Dataset

Definition:

A training dataset is the collection of examples used by a machine learning algorithm to learn patterns, relationships, or representations.

The training dataset provides the information from which the model develops its learned behavior.

Example:

A fraud detection model may be trained using five years of historical transaction records containing transaction amounts, locations, timestamps, device information, and verified fraud outcomes.

GRC considerations:

The organization should establish:

- Dataset ownership.
- Data provenance.
- Data classification.
- Data quality requirements.
- Privacy and retention requirements.
- Dataset versioning.
- Access restrictions.
- Training data integrity.

A training dataset should not be treated as an ordinary collection of files. It is a critical input that influences model behavior and business outcomes.

### 7.3 Validation Dataset

Definition:

A validation dataset is a separate dataset used during model development to evaluate performance and support decisions about model configuration, hyperparameter selection, and model optimization.

It helps developers determine whether the model is learning useful patterns and whether its performance generalizes beyond the training data.

Example:

An ML engineering team trains a customer churn prediction model using historical customer records.

The team uses a separate validation dataset to compare different configurations and select an appropriate model.

The validation dataset helps determine whether the model is overfitting the training data.

GRC considerations:

- Validation data should be appropriately separated from training data.
- Validation methodology should be documented.
- Performance thresholds should be defined.
- Repeated model tuning should not compromise the independence of final testing.
- Validation results should be retained as evidence.

### 7.4 Test Dataset

Definition:

A test dataset is an independent dataset used to evaluate the performance of a trained model after development and tuning.

It provides an assessment of how the model performs on data that was not used to train or tune it.

Example:

A fraud detection model is developed using historical transaction records.

After training and validation, the model is evaluated using an independent test dataset containing transactions that were excluded from the development process.

The test results help determine whether the model meets the organization's acceptance criteria.

GRC considerations:

- Test datasets should be independent of model training.
- Test results should be documented.
- Acceptance criteria should be defined before final evaluation.
- Critical performance weaknesses should be investigated.
- Test evidence should be available for audit and approval.

Important distinction:

The training, validation, and test datasets have different purposes. Reusing the same data indiscriminately can produce misleading performance results.

### 7.5 Dataset Splitting

Definition:

Dataset splitting is the process of dividing a dataset into separate subsets for training, validation, and testing.

A common approach is:

- 70% training.
- 15% validation.
- 15% testing.

These proportions are illustrative rather than universal requirements.

The appropriate split depends on dataset size, model type, business purpose, and data characteristics.

Example:

An organization has 100,000 labeled records.

| Dataset    | Percentage | Number of records |
| ---------- | ---------- | ----------------- |
| Training   | 70%        | 70,000            |
| Validation | 15%        | 15,000            |
| Testing    | 15%        | 15,000            |
| Total      | 100%       | 100,000           |

Important consideration:

Random splitting is not appropriate for every dataset.

For time-dependent data, such as network traffic or financial transactions, a chronological split may be more appropriate to avoid training on information from the future when evaluating performance on earlier observations.

GRC implications:

Dataset splitting methodology should be documented and justified. Data leakage between subsets can invalidate model evaluation and create false confidence in model performance.

## 8. Model Learning and Optimization Terminology

### 8.1 Epoch

Definition:

An epoch is one complete pass through the entire training dataset during model training.

During an epoch, the model processes the training examples and updates its parameters according to the selected optimization method.

Models commonly require multiple epochs to learn useful patterns.

Example:

A model is trained using 50,000 records.

If the training process runs for 10 epochs, the model processes the complete training dataset ten times, although the exact number of parameter updates depends on the training configuration.

GRC implications:

The number of epochs can influence model performance and training duration.

Too few epochs may result in underfitting, while too many may contribute to overfitting.

Training configurations should therefore be documented and evaluated.

### 8.2 Batch

Definition:

A batch is a subset of training examples processed together during a single training step.

Instead of processing the entire dataset at once, training algorithms often divide the dataset into smaller batches.

Example:

A training dataset contains 10,000 records.

If the batch size is 100, the model processes 100 records per batch.

One complete epoch would involve 100 batches, assuming all records are used and the dataset divides evenly.

### 8.3 Batch Size

Definition:

Batch size is the number of training examples processed together in one training step.

Batch size influences computational efficiency, memory requirements, and training behavior.

| Batch size | General characteristics                                                  |
| ---------- | ------------------------------------------------------------------------ |
| Small      | Lower memory requirements; more frequent parameter updates               |
| Large      | Greater memory requirements; fewer updates per epoch                     |
| Very large | May require substantial computational resources and careful optimization |

GRC implications:

Batch size is relevant to:

- Infrastructure capacity planning.
- Training cost management.
- Computational resource security.
- Reproducibility.
- Training performance documentation.

### 8.4 Learning Rate

Definition:

The learning rate is a hyperparameter that determines the size of parameter updates during model training.

It influences how quickly the model adjusts its parameters in response to calculated errors or optimization signals.

Conceptual example:

Imagine a model attempting to find the lowest point in a landscape representing its loss function.

- A learning rate that is too high may cause the model to overshoot the optimum.
- A learning rate that is too low may cause training to progress very slowly.
- An appropriate learning rate can support stable and efficient optimization.

GRC implications:

Learning rate configurations should be documented because they influence training behavior and can affect model reliability.

Uncontrolled changes to training configurations can produce materially different model outcomes.

### 8.5 Loss Function

Definition:

A loss function is a mathematical function that measures the difference between a model's predicted output and the expected or reference output, according to a defined objective.

The training process attempts to minimize the loss or otherwise optimize the selected objective.

Examples:

| Loss function             | Typical application               |
| ------------------------- | --------------------------------- |
| Mean Squared Error (MSE)  | Regression                        |
| Mean Absolute Error (MAE) | Regression                        |
| Binary Cross-Entropy      | Binary classification             |
| Categorical Cross-Entropy | Multiclass classification         |
| Hinge Loss                | Certain classification algorithms |

Example:

A model predicts that network latency will be 50 milliseconds, while the observed latency is 60 milliseconds.

The difference between the prediction and the observed value contributes to the model's loss according to the selected loss function.

GRC implications:

The selected loss function reflects what the model is being optimized to achieve.

This matters because optimizing one type of error does not necessarily minimize the organization's overall business or security risk.

For example, a fraud detection model that heavily penalizes false positives may behave differently from one that heavily penalizes false negatives.

The business owner should understand these trade-offs.

### 8.6 Optimization Algorithm

Definition:

An optimization algorithm is a computational method used to adjust model parameters to minimize a loss function or optimize another defined objective.

It determines how parameter updates are calculated during training.

Common examples:

- Gradient Descent.
- Stochastic Gradient Descent (SGD).
- Mini-batch Gradient Descent.
- Adam.
- RMSprop.

GRC implications:

Optimization methods influence training behavior, computational requirements, and reproducibility.

The development team should document the selected method and relevant configuration.

### 8.7 Gradient Descent

Definition:

Gradient Descent is an optimization technique that adjusts model parameters in the direction that reduces the loss function, using gradient information.

It is commonly used in machine learning and deep learning.

Conceptual explanation:

Imagine a model positioned on a slope representing its current loss.

The gradient indicates the direction of increasing loss.

Gradient descent adjusts the model parameters in the opposite direction to reduce the loss.

A simplified update rule is:

\\[ \theta\_{new} = \theta\_{old} - \eta \nabla\_{\theta} L(\theta) \\]

Where:

- \\(\theta\\) = model parameters.
- \\(\eta\\) = learning rate.
- \\(L(\theta)\\) = loss function.
- \\(\nabla\_{\theta}L(\theta)\\) = gradient of the loss with respect to the parameters.

GRC relevance:

Gradient descent is primarily a technical training concept, but its operational implications include training stability, reproducibility, computational resource consumption, and model performance.

### 8.8 Stochastic Gradient Descent (SGD)

Definition:

Stochastic Gradient Descent is an optimization approach that updates model parameters using gradients calculated from individual training examples or small subsets of examples, rather than the entire dataset.

It can provide computational efficiency and is widely used in machine learning.

Important distinction:

- Batch Gradient Descent calculates updates using the full training dataset.
- Stochastic Gradient Descent uses individual examples.
- Mini-batch Gradient Descent uses small batches of examples.

These approaches differ in how they calculate parameter updates.

### 8.9 Convergence

Definition:

Convergence refers to the process of an optimization algorithm approaching a stable solution or region where further updates produce relatively small improvements according to the optimization objective.

Convergence does not automatically mean the model is accurate, unbiased, secure, or suitable for production.

GRC consideration:

A model can converge successfully and still perform poorly on real-world data.

Model acceptance must therefore depend on independent evaluation and business requirements rather than training convergence alone.

## 9. Model Performance and Evaluation Metrics

Model evaluation is essential for determining whether a machine learning system performs adequately for its intended purpose.

However, model performance cannot be represented by a single metric in every situation.

Different metrics measure different aspects of model behavior, and the appropriate metric depends on the business problem and the consequences of prediction errors.

### 9.1 Accuracy

Definition:

Accuracy measures the proportion of total predictions that a classification model correctly identifies.

\\[ Accuracy = \frac{TP + TN}{TP + TN + FP + FN} \\]

Where:

- TP = True Positives.
- TN = True Negatives.
- FP = False Positives.
- FN = False Negatives.

Example:

A cybersecurity model evaluates 1,000 email messages.

It correctly classifies 950 messages and incorrectly classifies 50.

\\[ Accuracy = \frac{950}{1000} = 95\\% \\]

Accuracy: 95%

GRC implications:

Accuracy alone can be misleading when the dataset is imbalanced.

For example, if only 1% of network events are malicious, a model that classifies every event as legitimate could achieve 99% accuracy while detecting none of the threats.

### 9.2 Confusion Matrix

Definition:

A confusion matrix is a table that compares a classification model's predicted categories with the actual categories.

It is used to understand the types of classification errors made by the model.

Example: Phishing email detection

| Actual / Predicted | Predicted phishing | Predicted legitimate |
| ------------------ | ------------------ | -------------------- |
| Actual phishing    | TP = 90            | FN = 10              |
| Actual legitimate  | FP = 20            | TN = 880             |

Interpretation:

- 90 phishing emails were correctly identified.
- 10 phishing emails were missed.
- 20 legitimate emails were incorrectly flagged.
- 880 legitimate emails were correctly classified.

The confusion matrix provides the foundation for several important evaluation metrics.

### 9.3 True Positive (TP)

Definition:

A true positive occurs when a model correctly identifies a positive case.

Example:

A cybersecurity model identifies a genuinely malicious file as malicious.

### 9.4 True Negative (TN)

Definition:

A true negative occurs when a model correctly identifies a negative case.

Example:

A cybersecurity model correctly classifies a legitimate file as benign.

### 9.5 False Positive (FP)

Definition:

A false positive occurs when a model incorrectly classifies a negative case as positive.

Example:

A legitimate email is incorrectly classified as phishing.

Operational impact:

- Unnecessary investigations.
- Business disruption.
- Increased SOC workload.
- Legitimate transactions or communications being blocked.

### 9.6 False Negative (FN)

Definition:

A false negative occurs when a model incorrectly classifies a positive case as negative.

Example:

A phishing email is incorrectly classified as legitimate.

Operational impact:

- Threats may bypass detection.
- Security incidents may remain undetected.
- Sensitive information may be compromised.
- Regulatory or contractual obligations may be affected.

Important distinction:

In cybersecurity, false negatives can be particularly serious because they represent threats that the model failed to detect. However, false positives also matter because excessive alert volume can cause analyst fatigue and reduce detection effectiveness.

### 9.7 Precision

Definition:

Precision measures the proportion of predicted positive cases that are actually positive.

\\[ Precision = \frac{TP}{TP+FP} \\]

Using the phishing example:

\\[ Precision = \frac{90}{90+20} = 81.82\\% \\]

Interpretation:

Approximately 81.82% of emails classified as phishing were genuinely phishing emails.

GRC relevance:

Precision is important when false positives create significant operational costs or business disruption.

### 9.8 Recall

Definition:

Recall measures the proportion of actual positive cases correctly identified by the model.

It is also known as sensitivity or the true positive rate.

\\[ Recall = \frac{TP}{TP+FN} \\]

Using the same example:

\\[ Recall = \frac{90}{90+10} = 90\\% \\]

Interpretation:

The model detected 90% of the actual phishing emails.

GRC relevance:

Recall is important when failing to identify a threat or harmful event creates substantial risk.

For example, malware detection systems may prioritize high recall to reduce the likelihood of malicious files escaping detection, while still needing to manage false positives.

### 9.9 F1 Score

Definition:

The F1 score is the harmonic mean of precision and recall.

It provides a combined measure of these two metrics.

\\[ F1 = 2 \times \frac{Precision \times Recall} {Precision + Recall} \\]

Using the previous example:

\\[ F1 \approx 85.71\\% \\]

GRC relevance:

The F1 score can be useful when both false positives and false negatives matter.

However, it does not represent the business cost of each type of error. Risk assessments should therefore consider the consequences of errors separately.

### 9.10 Specificity

Definition:

Specificity measures the proportion of actual negative cases correctly identified by the model.

\\[ Specificity = \frac{TN}{TN+FP} \\]

Using the phishing example:

\\[ Specificity = \frac{880}{880+20} = 97.78\\% \\]

Interpretation:

The model correctly identifies approximately 97.78% of legitimate emails.

### 9.11 False Positive Rate (FPR)

Definition:

The false positive rate measures the proportion of actual negative cases incorrectly classified as positive.

\\[ FPR = \frac{FP}{FP+TN} \\]

A high false positive rate can increase operational workload and reduce trust in automated detection systems.

### 9.12 False Negative Rate (FNR)

Definition:

The false negative rate measures the proportion of actual positive cases incorrectly classified as negative.

\\[ FNR = \frac{FN}{FN+TP} \\]

A high false negative rate indicates that the model is failing to detect a significant proportion of actual positive cases.

### 9.13 Receiver Operating Characteristic (ROC) Curve

Definition:

A Receiver Operating Characteristic (ROC) curve is a graphical representation of a classification model's performance across different decision thresholds.

It plots:

- True Positive Rate (Recall) on the vertical axis.
- False Positive Rate on the horizontal axis.

The curve helps evaluate the trade-off between detecting positive cases and incorrectly flagging negative cases.

### 9.14 Area Under the Curve (AUC)

Definition:

Area Under the Curve (AUC), commonly referring to the Area Under the ROC Curve (ROC-AUC), measures how well a classification model ranks positive examples above negative examples across possible thresholds.

An ROC-AUC of 1.0 indicates perfect ranking discrimination, while an ROC-AUC of 0.5 represents performance equivalent to random ranking under the standard binary classification interpretation.

GRC relevance:

AUC can help compare classification models, but it does not establish that a model is suitable for a particular operational threshold.

The business impact of false positives and false negatives must still be assessed.

### 9.15 Mean Absolute Error (MAE)

Definition:

Mean Absolute Error measures the average absolute difference between predicted values and actual values.

It is commonly used in regression tasks.

\\[ MAE = \frac{1}{n} \sum\_{i=1}^{n}|y_i-\hat{y}\_i| \\]

Where:

- \\(y_i\\) = actual value.
- \\(\hat{y}\_i\\) = predicted value.
- \\(n\\) = number of observations.

Example:

A network performance model predicts latency values.

The average absolute difference between predicted and observed latency is 5 milliseconds.

The MAE is therefore 5 milliseconds.

### 9.16 Mean Squared Error (MSE)

Definition:

Mean Squared Error measures the average of squared differences between predicted and actual values.

\\[ MSE = \frac{1}{n} \sum\_{i=1}^{n}(y_i-\hat{y}\_i)^2 \\]

Because errors are squared, larger prediction errors receive greater weight.

GRC relevance:

MSE can be useful where large prediction errors have disproportionately serious consequences.

However, its numerical value is expressed in squared units, which can make direct interpretation less intuitive.

### 9.17 Root Mean Squared Error (RMSE)

Definition:

Root Mean Squared Error is the square root of Mean Squared Error.

\\[ RMSE = \sqrt{MSE} \\]

RMSE is expressed in the same units as the predicted variable and penalizes larger errors more heavily than MAE.

Example:

If a network latency prediction model has an RMSE of 8 milliseconds, the metric reflects the magnitude of prediction errors while giving relatively greater weight to large deviations.

### 9.18 Model Evaluation Metrics Reference Table

| Metric      | Measures                                 | Common application        |
| ----------- | ---------------------------------------- | ------------------------- |
| Accuracy    | Overall correct predictions              | Classification            |
| Precision   | Reliability of positive predictions      | Fraud and threat alerting |
| Recall      | Detection of actual positive cases       | Threat detection          |
| F1 Score    | Balance between precision and recall     | Imbalanced classification |
| Specificity | Correct identification of negative cases | Classification            |
| FPR         | Incorrect positive predictions           | Alert quality             |
| FNR         | Missed positive cases                    | Detection effectiveness   |
| ROC-AUC     | Ranking discrimination across thresholds | Binary classification     |
| MAE         | Average absolute prediction error        | Regression                |
| MSE         | Average squared prediction error         | Regression                |
| RMSE        | Square root of average squared error     | Regression                |

GRC principle:

Model evaluation metrics must be selected according to the intended use case and its risk profile. A model with high overall accuracy may still be unsuitable if it performs poorly on the cases that matter most to the business.

## 10. Model Generalization and Reliability

### 10.1 Generalization

Definition:

Generalization is a model's ability to perform effectively on new, previously unseen data that is representative of the intended operating environment.

A model that performs well only on its training dataset may not be reliable in production.

Example:

A model trained to detect fraudulent transactions achieves excellent results on its training data but performs poorly when exposed to transactions from new geographic locations.

This indicates weak generalization to the new data distribution.

GRC implications:

- Evaluate performance using independent test data.
- Assess representativeness of training data.
- Consider changes in operating conditions.
- Test across relevant user groups and environments.
- Monitor real-world performance after deployment.

### 10.2 Overfitting

Definition:

Overfitting occurs when a model learns the training data too closely, including noise and patterns that do not generalize to unseen data.

The result is strong performance on training data but weaker performance on new data.

Example:

A fraud detection model memorizes specific transaction patterns from historical records.

It achieves 99% training accuracy but only 65% accuracy on independent test data.

This suggests that the model has learned patterns that do not generalize effectively.

Common causes:

- Excessively complex models.
- Insufficient training data.
- Noisy training data.
- Excessive training.
- Inadequate regularization.

GRC implications:

Overfitting creates false confidence in model reliability.

Organizations should require independent testing and investigate significant differences between training and test performance.

### 10.3 Underfitting

Definition:

Underfitting occurs when a model is too simple or insufficiently trained to capture important relationships in the data.

It performs poorly on both training and unseen data.

Example:

A telecommunications operator attempts to predict network failures using a simple model that considers only equipment temperature.

However, failures are also influenced by traffic utilization, power conditions, hardware age, and environmental factors.

The model may be too simplistic to capture the underlying relationships.

GRC implications:

An underfitted model may provide unreliable predictions despite following the approved development process.

Model acceptance should therefore be based on demonstrated performance rather than the mere existence of development and testing documentation.

### 10.4 Bias-Variance Trade-Off

Definition:

The bias-variance trade-off describes the relationship between two sources of model prediction error:

- Bias: Error associated with overly simplistic assumptions.
- Variance: Error associated with excessive sensitivity to variations in training data.

A model with high bias may underfit. A model with high variance may overfit.

The objective is to develop a model that balances these characteristics and generalizes effectively.

GRC relevance:

The bias-variance trade-off is a technical concept, but its outcome directly affects model reliability.

Organizations should not assume that a more complex model is automatically a better model.

### 10.5 Regularization

Definition:

Regularization refers to techniques used to discourage excessive model complexity and reduce overfitting.

Regularization introduces constraints or penalties into the learning process to encourage models to generalize better.

Common examples include:

- L1 regularization (Lasso).
- L2 regularization (Ridge).
- Dropout in neural networks.
- Early stopping.

GRC relevance:

Regularization techniques should be documented where relevant to model development and validation. Their effectiveness must be evaluated through independent performance testing.

### 10.6 Early Stopping

Definition:

Early stopping is a training technique that stops model training when validation performance stops improving or begins deteriorating according to a defined criterion.

It helps reduce overfitting and unnecessary training.

Example:

A model's validation loss decreases during the first 20 epochs but starts increasing afterward.

The development process may use early stopping to terminate training before further training degrades generalization performance.

### 10.7 Data Leakage

Definition:

Data leakage occurs when information that would not legitimately be available at prediction time enters the model development or evaluation process, resulting in misleading performance estimates.

It can occur when training data contains future information, target-derived variables, or information improperly shared between training and testing datasets.

Example:

A telecommunications operator develops a model to predict whether a customer will cancel a subscription.

The dataset includes a feature indicating whether the customer has already requested account closure.

The model may achieve excellent results because it receives information that directly reveals the outcome it is supposed to predict.

This is a form of target leakage.

Common forms of data leakage:

| Leakage type             | Description                                                             |
| ------------------------ | ----------------------------------------------------------------------- |
| Target leakage           | Input features contain information derived from the outcome             |
| Train-test contamination | Information is shared improperly between training and testing           |
| Temporal leakage         | Future information is used to predict past or current outcomes          |
| Preprocessing leakage    | Data transformations are fitted using information from the test dataset |

GRC implications:

Data leakage can invalidate model validation and cause management to approve models based on misleading performance evidence.

The development process should document data splitting, preprocessing, feature selection, and leakage testing.

### 10.8 Model Robustness

Definition:

Model robustness is the ability of a model to maintain acceptable performance when exposed to reasonable variations, disturbances, or changes in its input data and operating conditions.

A robust model should not experience unacceptable performance degradation because of minor or expected input variations.

Example:

A cybersecurity model should continue detecting suspicious network behavior when traffic volumes fluctuate within expected operational ranges.

GRC implications:

Robustness testing should consider:

- Noisy data.
- Missing values.
- Unexpected input formats.
- Environmental variations.
- Changes in user behavior.
- Adversarial manipulation.
- Performance degradation.

### 10.9 Model Reliability

Definition:

Model reliability refers to the degree to which a model consistently performs its intended function within defined performance and operational requirements.

Reliability is broader than a single accuracy metric.

It may include:

- Prediction consistency.
- Operational availability.
- Performance stability.
- Repeatability.
- Resilience to expected changes.
- Appropriate handling of uncertain or invalid inputs.

GRC consideration:

An organization should define what constitutes acceptable model reliability for each business application.

A recommendation model used for marketing may tolerate different levels of error than a model supporting fraud detection or critical network operations.

## 11. Practical Enterprise GRC Exercise

### Scenario: Evaluation of a Machine Learning Fraud Detection Model

A financial services organization has implemented an ML-based fraud detection model.

The model:

- Uses supervised learning.
- Processes historical transaction data.
- Classifies transactions as legitimate or potentially fraudulent.
- Generates risk scores.
- Sends high-risk transactions for further review.

The organization reports 98% accuracy during development.

However, the GRC team must determine whether the model is suitable for production.

### 11.1 Initial Assessment Questions

| Area            | GRC question                                                               |
| --------------- | -------------------------------------------------------------------------- |
| Training        | What training methodology was used?                                        |

| Data quality    | How was data accuracy established?                                         |

### 11.2 Risk Identification

| Risk ID | Identified risk                 | Potential impact                           | Required control                                            |
| ------- | ------------------------------- | ------------------------------------------ | ----------------------------------------------------------- |
| ML-001  | Inaccurate training labels      | Incorrect fraud classifications            | Label validation and quality assurance                      |

### 11.3 Model Approval Criteria

Before approving the model for production, the organization should establish:

1. Documented business purpose.
2. Approved training and validation methodology.
3. Evidence of data quality and provenance.
4. Independent test results.
5. Defined acceptance thresholds.
6. Evaluation of false-positive and false-negative consequences.
7. Security assessment of model artifacts and development infrastructure.
8. Documented model limitations.
9. Approved operational ownership.
10. Monitoring and incident escalation procedures.

Critical observation:

The reported 98% accuracy is insufficient to approve the model.

The GRC team needs to understand the underlying evaluation dataset, class distribution, confusion matrix, precision, recall, and operational consequences of incorrect predictions.

A model that achieves 98% accuracy but misses a substantial proportion of fraudulent transactions may be unsuitable for its intended purpose.

| Loss vs. accuracy                       | Loss measures an optimization objective; accuracy measures the proportion of correct classification predictions    |
| Precision vs. recall                    | Precision measures the correctness of positive predictions; recall measures how many actual positives are detected |
| False positive vs. false negative       | False positives incorrectly flag negative cases; false negatives miss actual positive cases                        |
| Overfitting vs. underfitting            | Overfitting learns training data too closely; underfitting fails to capture important patterns                     |
| Generalization vs. training performance | Generalization concerns performance on unseen data                                                                 |
| Data leakage vs. legitimate prediction  | Leakage introduces information that should not be available for the intended prediction                            |
| Robustness vs. accuracy                 | Accuracy measures predictive correctness; robustness concerns maintaining performance under variations             |

### Core Principle

A machine learning model must be evaluated on its ability to generalize, its error characteristics, and its operational consequences—not merely on its training results or headline accuracy. Enterprise model approval must be supported by independent evidence, defined acceptance criteria, and documented risk controls.

# 22.02 — Machine Learning Terminology

## Part 3 — Advanced Machine Learning Concepts, Model Architectures, and Security Implications

## 13. Advanced Machine Learning Concepts

Machine learning systems involve more than algorithms, datasets, and performance metrics. Modern ML architectures use additional techniques to improve prediction quality, manage complex data relationships, reduce computational requirements, and support more sophisticated applications.

For AI Security Governance professionals, these concepts matter because they influence model behavior, explainability, security exposure, operational dependencies, and the effectiveness of governance controls.

### 13.1 Feature Engineering

Definition:

Feature engineering is the process of selecting, transforming, creating, or extracting input variables to improve the ability of a machine learning model to learn meaningful patterns from data.

It involves preparing raw data into features that are more useful for the intended learning task.

Example: Telecommunications customer churn prediction

A telecommunications operator has raw customer records containing:

- Monthly invoices.
- Customer service interactions.
- Network interruptions.
- Subscription history.
- Payment records.

The ML engineering team creates additional features:

| Raw data                     | Engineered feature              | Purpose                                |
| ---------------------------- | ------------------------------- | -------------------------------------- |
| Individual complaint records | Complaints in the last 90 days  | Measure recent dissatisfaction         |
| Monthly invoices             | Average monthly spending        | Identify spending patterns             |
| Network interruption logs    | Number of service interruptions | Measure service reliability            |
| Payment records              | Average payment delay           | Identify payment behavior              |
| Subscription dates           | Customer tenure                 | Measure customer relationship duration |

These engineered features may provide more useful information than the original raw records.

Common feature engineering techniques:

- Normalization.
- Standardization.
- Encoding categorical variables.
- Aggregation.
- Date and time extraction.
- Missing-value handling.
- Feature transformation.
- Dimensionality reduction.

GRC implications:

Feature engineering can introduce governance risks when developers create variables that indirectly represent sensitive attributes or introduce discriminatory relationships.

Controls should address:

- Feature documentation.
- Feature ownership.
- Data lineage.
- Privacy review.
- Bias assessment.
- Approval of feature changes.
- Reproducibility of feature transformations.

### 13.2 Feature Selection

Definition:

Feature selection is the process of identifying and retaining the most relevant input variables for a machine learning model while removing irrelevant, redundant, or unnecessary features.

Its purpose is to improve model efficiency, reduce complexity, and potentially improve generalization.

Example:

A fraud detection model initially uses 100 input features.

After evaluation, the development team identifies 25 features that provide sufficient predictive value.

The remaining features are removed because they contribute little useful information or introduce unnecessary complexity.

GRC implications:

Feature selection supports data minimization and can reduce the exposure of unnecessary information.

However, removing a feature solely because it appears less predictive may also conceal important fairness or operational considerations.

The organization should document why relevant features were selected or excluded.

### 13.3 Feature Extraction

Definition:

Feature extraction is the process of transforming raw data into a more compact or meaningful representation that can be used by a machine learning model.

Unlike feature selection, which chooses existing features, feature extraction creates new representations from the original data.

Examples:

- Extracting visual patterns from images.
- Extracting frequency characteristics from audio.
- Extracting semantic representations from text.
- Converting raw network traffic into statistical behavior indicators.

Example: Network security monitoring

A network monitoring system processes raw traffic records and extracts:

- Average packet size.
- Connection duration.
- Number of destination addresses.
- Traffic frequency.
- Protocol distribution.

These extracted features are supplied to an anomaly detection model.

GRC implications:

Feature extraction should be documented because transformations can affect data meaning, model explainability, and the ability to trace model outputs back to their source information.

### 13.4 Feature Vector

Definition:

A feature vector is an ordered collection of numerical or encoded feature values representing a particular data instance for processing by a machine learning model.

Example:

A network connection may be represented as:

\\[ X = [120, 45, 0.8, 15] \\]

Where:

- 120 = connection duration.
- 45 = average packet size.
- 0.8 = packet loss ratio.
- 15 = number of destination connections.

The actual meaning and units depend on the feature definition.

GRC implications:

Feature vectors should be protected against unauthorized modification, and their structure should be documented to support model integrity and reproducibility.

### 13.5 Feature Scaling

Definition:

Feature scaling is the process of adjusting numerical feature values to comparable scales so that variables with different magnitudes do not disproportionately influence certain machine learning algorithms.

Two common approaches are normalization and standardization.

Normalization:

Normalization commonly transforms values into a defined range, such as 0 to 1.

A common min-max scaling formula is:

\\[ X' = \frac{X-X\_{min}}{X\_{max}-X\_{min}} \\]

Standardization:

Standardization transforms values using the mean and standard deviation.

\\[ Z = \frac{X-\mu}{\sigma} \\]

Where:

- \\(X\\) = original value.
- \\(\mu\\) = mean.
- \\(\sigma\\) = standard deviation.

GRC implications:

Feature scaling procedures should be consistently applied during training and inference.

Incorrect or inconsistent preprocessing can cause production predictions to differ significantly from development results.

## 14. Machine Learning Architecture and Model Types

### 14.1 Decision Tree

Definition:

A Decision Tree is a supervised machine learning algorithm that makes predictions by repeatedly splitting data according to conditions applied to input features.

The structure resembles a tree consisting of:

- Root node.
- Decision nodes.
- Branches.
- Leaf nodes.

Each decision node evaluates a condition, while leaf nodes represent predicted outcomes.

Example: Fraud detection

A simplified decision tree may evaluate:

```
                    Transaction Amount
                            |
                   Is amount > €5,000?
                       /         \
                     Yes          No
                      |            |
             Check Location    Check Device
                  |                 |
          Is location unusual?  Is device trusted?
               /     \             /      \
             Yes      No          Yes      No
              |        |            |        |
           High     Medium       Low       Medium
           Risk      Risk        Risk       Risk
```

Common applications:

- Fraud classification.
- Customer churn prediction.
- Credit risk assessment.
- Medical decision support.
- Security event classification.

Advantages:

- Relatively easy to understand.
- Can represent nonlinear relationships.
- Supports interpretable decision paths.
- Handles numerical and categorical features, depending on implementation.

Limitations:

- Can overfit.
- May be unstable when training data changes.
- Individual trees may have lower predictive performance than ensemble approaches.

GRC implications:

Decision trees can provide useful decision-path evidence, but organizations must still validate the data, thresholds, model limitations, and potential discriminatory outcomes.

### 14.2 Random Forest

Definition:

Random Forest is an ensemble learning algorithm that combines multiple decision trees to generate predictions.

Each tree is trained using variations of the training data and feature selection. Their predictions are combined to produce a final result.

For classification, the final prediction commonly uses majority voting. For regression, it commonly uses an average of individual predictions.

Example:

A fraud detection model uses 200 decision trees.

Each tree independently evaluates transaction characteristics and produces a classification.

The Random Forest combines these predictions to determine whether a transaction should be classified as legitimate or potentially fraudulent.

Advantages:

- Reduces the instability associated with a single decision tree.
- Can model complex relationships.
- Often provides strong performance on structured datasets.
- Supports feature importance analysis.

Limitations:

- More complex than an individual decision tree.
- Can require more computational resources.
- Individual predictions may be difficult to explain.
- Feature importance measures can be misleading if interpreted without context.

GRC implications:

The organization should document the number of trees, relevant hyperparameters, training data, validation methodology, and explainability limitations.

### 14.3 Support Vector Machine (SVM)

Definition:

Support Vector Machine is a supervised machine learning algorithm used primarily for classification and, in some implementations, regression.

It attempts to identify a decision boundary that separates different classes while maximizing the margin between them.

The observations closest to the decision boundary are called support vectors.

Example:

An enterprise cybersecurity platform uses an SVM model to classify network activity as normal or suspicious.

The model analyzes selected network traffic features and identifies a decision boundary between the two categories.

Important terminology:

- Hyperplane: The decision boundary separating classes.
- Margin: The distance between the decision boundary and the closest observations.
- Support vectors: Data points that influence the position of the decision boundary.
- Kernel: A mathematical function that allows certain nonlinear relationships to be represented in a transformed feature space.

GRC implications:

SVM models may be effective for certain classification tasks, but their decision boundaries can be difficult to explain, particularly when nonlinear kernels are used.

Explainability requirements should be evaluated according to the model's intended application.

### 14.4 K-Nearest Neighbors (KNN)

Definition:

K-Nearest Neighbors is a supervised learning algorithm that predicts the class or value of a new observation by examining the closest examples in the training dataset.

The value of K determines how many neighboring observations are considered.

For classification, the algorithm commonly uses the majority class among the nearest neighbors.

For regression, it commonly averages their target values.

Example:

An organization wants to classify a network connection.

The KNN model compares the connection's features against historical examples.

If the five nearest examples are:

- Three suspicious.
- Two normal.

A majority-voting classifier may classify the new connection as suspicious.

GRC implications:

- Training data must be protected.
- Distance calculations must be appropriate for the feature types.
- Feature scaling may be necessary.
- Prediction performance should be tested with representative data.
- Computational and storage requirements should be assessed.

### 14.5 Gradient Boosting

Definition:

Gradient Boosting is an ensemble learning technique that combines multiple weak predictive models, commonly decision trees, into a stronger predictive model.

Each subsequent model attempts to reduce the errors or residuals of the existing ensemble according to the selected optimization objective.

Common implementations:

- XGBoost.
- LightGBM.
- CatBoost.

Example:

A bank develops a credit risk model.

The first decision tree provides an initial prediction. Subsequent trees focus on improving prediction errors made by the existing model.

The combined ensemble produces the final risk prediction.

GRC implications:

Gradient boosting models can provide strong predictive performance but may require additional explainability techniques and careful validation.

Model complexity, feature importance, training data, and performance across relevant populations should be assessed.

### 14.7 Deep Learning

Definition:

Deep Learning is a subfield of machine learning that uses neural networks with multiple processing layers to learn increasingly complex representations from data.

## 15. Advanced Neural Network Architectures

### 15.1 Convolutional Neural Network (CNN)

Definition:

A Convolutional Neural Network is a type of deep neural network designed primarily to process data with grid-like structures, particularly images.

CNNs use convolutional operations to identify local patterns and spatial relationships.

Common applications:

- Image recognition.
- Object detection.
- Medical imaging.
- Video analysis.
- Industrial inspection.
- Facial recognition.

Example: Physical security monitoring

A company deploys a video analytics system to detect unauthorized access to restricted facilities.

A CNN-based model analyzes image frames and identifies visual patterns associated with people, objects, or restricted-area activity.

GRC implications:

- Assess image and video data privacy.
- Evaluate potential biometric processing.
- Verify lawful and authorized use.
- Assess accuracy across relevant environmental conditions.
- Review surveillance and access controls.
- Establish human review and escalation processes.

### 15.2 Recurrent Neural Network (RNN)

Definition:

A Recurrent Neural Network is a neural network architecture designed to process sequential data by maintaining information from previous processing steps.

RNNs use recurrent connections to incorporate earlier information when processing subsequent elements in a sequence.

Common applications:

- Time-series forecasting.
- Speech recognition.
- Sequence classification.
- Language processing.
- Predictive maintenance.

Example: Network traffic forecasting

A telecommunications operator analyzes network utilization over time.

An RNN processes historical traffic measurements to predict future network demand.

GRC implications:

The organization should assess:

- Data sequence integrity.
- Temporal dependencies.
- Training data representativeness.
- Prediction stability.
- Model performance under changing conditions.

### 15.3 Long Short-Term Memory (LSTM)

Definition:

Long Short-Term Memory is a type of recurrent neural network architecture designed to capture longer-term dependencies in sequential data.

It uses specialized gating mechanisms to control what information is retained, updated, or forgotten.

Common applications:

- Time-series prediction.
- Speech recognition.
- Sequential anomaly detection.
- Predictive maintenance.
- Demand forecasting.

Example:

A telecom operator uses an LSTM model to analyze months of network performance data and identify patterns that may precede equipment failures.

GRC implications:

LSTM models require careful validation of historical sequence data, prediction reliability, and performance under changing operating conditions.

### 15.4 Transformer Architecture

Definition:

A Transformer is a neural network architecture that uses attention mechanisms to process relationships between elements in a sequence.

Transformers are widely used in modern language models and multimodal AI systems.

Unlike traditional recurrent architectures, Transformer models can process many sequence positions in parallel during training, subject to their architecture and implementation.

Key concepts:

- Self-attention.
- Attention heads.
- Query, Key, and Value.
- Positional encoding or positional information.
- Encoder.
- Decoder.
- Transformer blocks.

Example:

A language model processes the sentence:

> The network administrator changed the firewall configuration because it was outdated.

The model uses contextual relationships between words to interpret the sentence.

Attention mechanisms help it determine which parts of the sequence are relevant when computing representations.

GRC implications:

Transformer-based models can have significant computational, data governance, security, and explainability requirements.

Their use in enterprise environments should be evaluated according to their actual application and operational authority.

### 15.5 Attention Mechanism

Definition:

An attention mechanism is a technique that enables a neural network to assign different levels of importance to different parts of its input when computing a representation or output.

In Transformers, self-attention allows tokens to incorporate information from other tokens in the same sequence.

Example:

Consider:

> The employee submitted the report because she completed the investigation.

The model needs to understand the contextual relationship between "she" and "employee."

Attention mechanisms help the model represent relationships between relevant tokens.

GRC implications:

Attention weights or visualizations can sometimes provide insight into model behavior, but they should not automatically be treated as complete explanations of why a model produced a particular output.

### 15.6 Encoder

Definition:

An encoder is a neural network component that transforms input information into an internal representation.

In Transformer architectures, encoder layers commonly use self-attention and feed-forward processing.

Typical applications:

- Text representation.
- Classification.
- Information extraction.
- Semantic understanding.
- Feature representation.

### 15.7 Decoder

Definition:

A decoder is a neural network component that generates or transforms outputs based on learned representations and available context.

In Transformer architectures, decoder components may use masked self-attention and, in encoder-decoder models, cross-attention to encoder outputs.

Decoder-only architectures are widely used for autoregressive language generation.

GRC implications:

The distinction between encoders and decoders is important when evaluating how an AI system processes inputs and produces outputs, particularly when assessing data flows and model architecture.

## 16. Model Training Strategies and Adaptation

### 16.1 Transfer Learning

Definition:

Transfer Learning is a machine learning approach in which knowledge learned by a model on one task or dataset is reused to improve performance on another related task.

Rather than training a model entirely from scratch, developers start with an existing trained model.

Example:

A company uses a pretrained image recognition model and adapts it to identify damaged industrial equipment.

The original model has already learned general visual features. The development team uses this knowledge to support the new classification task.

Advantages:

- Reduces training requirements.
- Can reduce computational costs.
- May improve performance when labeled data is limited.
- Allows reuse of existing model capabilities.

GRC implications:

Transfer learning introduces dependencies on the original model's:

- Training data.
- Licensing terms.
- Security properties.
- Known limitations.
- Intended purpose.
- Model provenance.

An organization must not assume that a pretrained model is trustworthy simply because it is commercially available or widely used.

### 16.2 Fine-Tuning

Definition:

Fine-tuning is the process of continuing model training using a task-specific or domain-specific dataset to adapt a pretrained model to a particular use case.

Fine-tuning modifies some or all of the model's learned parameters, depending on the method.

Example:

An enterprise wants to adapt a pretrained language model to understand telecommunications terminology.

The model is fine-tuned using approved examples involving:

- Network incident descriptions.
- Telecommunications service terminology.
- Technical support conversations.
- Internal operational language.

The resulting model may become more effective for the intended domain.

GRC implications:

- Training data must be authorized.
- Fine-tuning activities must be documented.
- The resulting model must be independently evaluated.
- Privacy and confidential data exposure must be assessed.
- Model versioning must be maintained.
- Changes in model behavior must be reviewed.

### 16.3 Retraining

Definition:

Retraining is the process of training a model again using updated or revised data, potentially incorporating new examples, changed operating conditions, or corrected historical records.

Retraining may be required when model performance deteriorates or the underlying data distribution changes.

Example:

A fraud detection model was trained using transaction behavior from 2024.

By 2026, fraud techniques and customer transaction patterns have changed.

The organization retrains the model using more recent and appropriately validated data.

GRC implications:

Retraining should be governed by:

- Defined triggers.
- Approved data sources.
- Change management.
- Independent testing.
- Model versioning.
- Deployment authorization.
- Rollback procedures.

Retraining should not automatically result in production deployment.

### 16.4 Incremental Learning

Definition:

Incremental Learning is an approach in which a model learns from new data over time without necessarily being retrained from scratch using the entire historical dataset.

It allows the model to incorporate new information progressively.

Example:

A network anomaly detection model receives new network behavior data regularly and updates its learned patterns to account for changing network conditions.

GRC implications:

Incremental learning can introduce additional governance complexity because the model may change during operation.

Organizations should establish:

- Approved update sources.
- Model version tracking.
- Performance monitoring.
- Update authorization.
- Integrity verification.
- Rollback capabilities.
- Controls against malicious or corrupted training inputs.

### 16.5 Online Learning

Definition:

Online Learning is a machine learning approach in which a model is updated continuously or incrementally as new data becomes available.

It differs from traditional batch training, where a model is trained using a prepared dataset and subsequently deployed.

Example:

A fraud detection system updates its model as new verified transaction outcomes become available.

GRC implications:

Online learning can increase exposure to data poisoning, unauthorized model changes, and unexpected behavior.

For critical enterprise applications, organizations should define whether automatic updates are permitted, which data can influence the model, and what validation or approval mechanisms are required.

### 16.6 Batch Learning

Definition:

Batch Learning is an approach in which a model is trained using a fixed dataset or a prepared collection of data before being deployed.

The model is generally updated through a separate training process rather than continuously learning from each new production observation.

Example:

A telecommunications operator retrains its customer churn model every three months using a newly prepared dataset.

The updated model is tested and approved before deployment.

GRC implications:

Batch learning can provide a more controlled model update process because training occurs at defined intervals.

However, model performance may deteriorate between retraining cycles if the operating environment changes significantly.

### 16.7 Federated Learning

Definition:

Federated Learning is a distributed machine learning approach in which multiple participants collaboratively train a shared model while keeping their raw training data within their respective local environments.

Participants generally exchange model updates or other learning information rather than centrally transferring all raw training data.

Example:

Three telecommunications operators want to develop a shared model for detecting certain network threats.

Each operator trains the model locally using its own network data.

The participants exchange model updates through a coordinated federated learning process.

A central aggregation mechanism combines the updates to improve the shared model.

- Supports collaboration across organizations.

Security and GRC risks:

Federated learning does not automatically guarantee privacy or security.

Potential risks include:

- Malicious model updates.

### 16.8 Distributed Training

Definition:

Distributed Training is a machine learning approach in which training workloads are divided across multiple computing devices or processing nodes to improve scalability and computational efficiency.

Example:

An organization trains a large neural network using multiple GPUs distributed across several servers.

The training workload is coordinated so that the devices can process data and update model parameters collectively.

GRC implications:

Distributed training introduces infrastructure and supply-chain considerations, including:

- Inter-node communication protection.
- Training artifact integrity.
- Cloud provider security.
- Access control.
- Resource allocation.
- Logging and monitoring.

## 17. Dimensionality Reduction and Representation Learning

### 17.1 Dimensionality

Definition:

Dimensionality refers to the number of features or variables used to represent an observation in a dataset.

A dataset with 10 input features has 10-dimensional feature representation, assuming each feature represents one dimension.

Example:

A network monitoring model may use 200 features extracted from network traffic.

This creates a high-dimensional dataset.

High dimensionality can increase computational requirements and make model development more complex.

### 17.2 Dimensionality Reduction

Definition:

Dimensionality Reduction is the process of reducing the number of input variables or dimensions while attempting to preserve relevant information.

It can reduce computational requirements, remove redundancy, and support visualization or model development.

Common techniques:

- Principal Component Analysis (PCA).
- t-Distributed Stochastic Neighbor Embedding (t-SNE).
- Uniform Manifold Approximation and Projection (UMAP).

### 17.3 Principal Component Analysis (PCA)

Definition:

Principal Component Analysis is a statistical dimensionality reduction technique that transforms correlated input variables into a smaller number of new variables called principal components.

The components are constructed to capture as much of the dataset's variance as possible, in descending order.

Example:

A network monitoring dataset contains 100 correlated performance metrics.

PCA may transform these into 10 principal components that capture a substantial proportion of the original data's variance.

GRC implications:

PCA can reduce complexity, but the resulting components may be less directly interpretable than the original features.

Organizations should document:

- Why dimensionality reduction is necessary.
- Which variables are included.
- How components are generated.
- What information may be lost.
- Whether the resulting model remains suitable for its intended purpose.

### 17.4 Embedding

Definition:

An embedding is a numerical representation of data in a vector space, where the representation is designed to capture useful characteristics or relationships.

Embeddings can represent:

- Words.
- Sentences.
- Documents.
- Images.
- Audio.
- Users.
- Products.
- Other data objects.

Example:

An enterprise document search system converts documents into numerical vectors.

Documents with similar semantic meaning may be represented by vectors that are closer together in the embedding space.

This allows the system to retrieve conceptually related documents even when they do not contain exactly the same words.

GRC implications:

Embeddings should be governed as derived data.

They may reveal information about the original content or enable sensitive relationships to be inferred.

Controls should address:

- Source data authorization.
- Access restrictions.
- Retention.
- Vector database security.
- Embedding generation integrity.
- Data deletion and lifecycle management.

### 17.5 Latent Space

Definition:

Latent Space is a learned representation space in which a model encodes underlying patterns, characteristics, or structures of the original input data.

The dimensions of latent space do not necessarily correspond directly to human-readable characteristics.

Example:

An image recognition model transforms an image into an internal representation containing information relevant to identifying objects.

This internal representation can be described as a latent representation.

GRC implications:

Latent representations may be difficult to interpret directly.

The organization should understand what information is encoded, how the representation is used, and whether it introduces privacy or security risks.

### 17.6 Representation Learning

Definition:

Representation Learning is a machine learning approach in which a model automatically learns useful representations of input data rather than relying entirely on manually engineered features.

It is a central capability of deep learning.

Example:

A neural network trained to recognize images may automatically learn representations of:

- Edges.
- Shapes.
- Textures.
- Objects.
- Complex visual patterns.

GRC implications:

Automatically learned representations can make models more capable but may also reduce transparency into how specific input characteristics influence the final output.

## 18. Model Interpretability and Explainability

Understanding why an ML model produces a particular output is important for governance, auditability, regulatory compliance, and operational accountability.

However, interpretability and explainability are related but distinct concepts.

### 18.1 Interpretability

Definition:

Interpretability refers to the degree to which a human can understand how a model works and how its internal structure or components relate to its outputs.

An interpretable model generally provides a relatively direct understanding of its decision logic.

Example:

A simple decision tree may provide a visible sequence of conditions leading to a prediction.

An analyst can examine the decision path and understand why the model assigned a particular category.

### 18.2 Explainability

Definition:

Explainability refers to the ability to provide meaningful explanations of a model's predictions, behavior, or outputs.

Explainability techniques may be applied to models that are not inherently easy to interpret.

Example:

A complex neural network predicts that a transaction is potentially fraudulent.

An explainability technique identifies which input characteristics contributed most strongly to that prediction.

### 18.3 Explainable AI (XAI)

Definition:

Explainable AI refers to methods, techniques, and approaches designed to make AI model behavior and outputs more understandable to humans.

Examples include:

- SHAP.
- LIME.
- Feature importance analysis.
- Partial Dependence Plots.
- Counterfactual explanations.

### 18.4 SHAP

Definition:

SHAP (SHapley Additive exPlanations) is an explainability approach based on Shapley values from cooperative game theory.

It estimates how individual input features contribute to a model's prediction relative to a reference or baseline.

Example:

A customer churn model predicts an 85% probability of churn.

A SHAP analysis may identify the following contributions:

| Feature                      | Contribution to prediction |
| ---------------------------- | -------------------------- |
| High number of complaints    | Increased churn prediction |
| Recent network interruptions | Increased churn prediction |
| Long customer tenure         | Reduced churn prediction   |
| High service satisfaction    | Reduced churn prediction   |

These values help explain the factors influencing the prediction, subject to the assumptions and limitations of the method.

### 18.5 LIME

Definition:

LIME (Local Interpretable Model-Agnostic Explanations) is an explainability technique that approximates the behavior of a complex model around a specific prediction using a simpler interpretable model.

It is commonly used to explain individual predictions.

Example:

An ML model rejects a transaction as suspicious.

LIME creates a local approximation around that transaction to identify which input characteristics influenced the prediction.

### 18.6 Model-Agnostic Explainability

Definition:

Model-agnostic explainability refers to techniques that can be applied to different types of machine learning models without requiring access to their internal architecture.

SHAP and LIME can be used in model-agnostic ways, depending on their implementation.

GRC implications:

Model-agnostic techniques can help organizations evaluate complex third-party models.

However, explanations produced by approximation techniques are not necessarily complete or definitive descriptions of internal model behavior.

### 18.7 Counterfactual Explanation

Definition:

A counterfactual explanation describes how an input would need to change to produce a different model outcome.

It answers a question similar to:

"What would have to be different for the model to produce another result?"

Example:

A customer receives a high-risk credit assessment.

A counterfactual explanation may indicate that the model's prediction would change if the customer's debt-to-income ratio were lower, assuming the other relevant conditions remain unchanged.

GRC implications:

Counterfactual explanations can help users understand model outcomes and support challenge or review processes.

However, organizations must ensure that suggested changes are realistic, lawful, and not misleading.

### 18.8 Feature Importance

Definition:

Feature importance is a measure intended to indicate how influential particular input variables are in a model's predictions.

Different methods calculate importance differently.

Examples include:

- Tree-based feature importance.
- Permutation importance.
- SHAP-based importance.

GRC implications:

Feature importance can support model review, but it does not automatically establish causation.

A feature that is highly predictive is not necessarily the underlying cause of an outcome.

### 18.9 Explainability Limitations

Explainability techniques have limitations that GRC professionals must understand.

| Limitation               | Governance concern                                                     |
| ------------------------ | ---------------------------------------------------------------------- |
| Approximation            | Explanation may not perfectly represent the original model             |
| Correlated features      | Contributions may be difficult to separate                             |
| Local explanation        | Explanation for one prediction may not describe overall model behavior |
| Misinterpretation        | Users may assume explanations prove causality                          |
| Incomplete transparency  | Third-party models may restrict access to internal details             |
| Explanation manipulation | Explanations may create misleading confidence                          |

Core governance requirement:

An organization should select explainability methods appropriate to the model, use case, decision impact, and stakeholder needs.

## 20. Summary — Part 3

This part covered advanced machine learning techniques, model architectures, training strategies, representation learning, and explainability.

The most important distinctions are:

| Distinction                                 | What must be understood                                                                                                                      |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Feature engineering vs. feature selection   | Engineering transforms or creates features; selection chooses relevant existing features                                                     |
| Feature extraction vs. feature selection    | Extraction creates representations; selection retains existing variables                                                                     |
| Decision Tree vs. Random Forest             | A decision tree uses one tree; Random Forest combines multiple trees                                                                         |
| Random Forest vs. Gradient Boosting         | Random Forest generally combines independently developed trees; Gradient Boosting builds models sequentially to improve an existing ensemble |
| Neural Network vs. Deep Learning            | A neural network is an architecture; deep learning uses neural networks with multiple processing layers                                      |
| CNN vs. RNN                                 | CNNs are designed for spatial or grid-like patterns; RNNs process sequential information                                                     |
| RNN vs. LSTM                                | LSTM is a specialized recurrent architecture designed to capture longer-term dependencies                                                    |
| Transformer vs. RNN                         | Transformers use attention mechanisms; RNNs use recurrent connections                                                                        |
| Transfer learning vs. fine-tuning           | Transfer learning reuses learned knowledge; fine-tuning is one way of adapting a pretrained model                                            |
| Retraining vs. incremental learning         | Retraining develops a model again; incremental learning incorporates new information progressively                                           |
| Online vs. batch learning                   | Online learning updates as new data arrives; batch learning uses prepared datasets                                                           |
| Federated learning vs. centralized training | Federated learning coordinates distributed training while keeping raw data local; centralized training brings data together for training     |
| Interpretability vs. explainability         | Interpretability concerns understanding model structure; explainability concerns explaining behavior and outputs                             |
| SHAP vs. LIME                               | SHAP uses Shapley-value-based attribution; LIME approximates local model behavior                                                            |
| Feature importance vs. causation            | Predictive importance does not establish a causal relationship                                                                               |

### Core Principle

Advanced machine learning capabilities introduce additional architectural, operational, and governance dependencies. An enterprise must understand not only which model architecture or learning technique is deployed, but also how it is trained, adapted, explained, secured, and controlled throughout its lifecycle.
