# 17.09 — AI Prompt Injection Incidents

## Part 1 — AI Prompt Injection Incident Foundations, Attack Concepts, Trust Boundaries, Impact and Governance

### 1. AI Prompt Injection Incident

An **AI Prompt Injection Incident** occurs when an attacker or other untrusted input causes an AI system to process instructions that alter, bypass, manipulate, or interfere with its intended behavior.

Prompt injection can affect:

- direct user interactions;
- retrieved documents;
- web content;
- emails;
- files;
- tool outputs;
- APIs;
- agent environments;
- memory;
- multimodal inputs.

A prompt injection attempt is not automatically a confirmed security incident. Incident classification should depend on evidence, impact, and organizational incident criteria.

### 2. Objective of AI Prompt Injection Incident Management

The objective is to identify, assess, contain, investigate, remediate, and learn from prompt injection conditions that may compromise the intended behavior or security boundaries of an AI system.

The capability should address:

- attack identification;
- affected prompts;
- affected models;
- trust boundaries;
- tool access;
- data exposure;
- unauthorized actions;
- containment;
- evidence;
- recovery;
- recurrence prevention.

### 3. AI Prompt Injection

**AI Prompt Injection** is an attempt to influence an AI system by supplying instructions or content that conflicts with, overrides, manipulates, or attempts to circumvent the system's intended instructions or control boundaries.

Prompt injection can be:

- direct;
- indirect;
- persistent;
- contextual;
- multimodal;
- tool-mediated;
- retrieval-mediated.

### 4. AI Prompt Injection Event

A Prompt Injection Event is an observed input or condition that attempts to influence an AI system through manipulated instructions or untrusted content.

Examples include:

- a user attempting to override system instructions;
- a document containing hidden instructions;
- a web page containing malicious instructions;
- a tool response containing adversarial content.

An event becomes an incident when organizational incident criteria are met.

### 5. AI Prompt Injection Incident versus Prompt Injection Attempt

A prompt injection attempt represents an attempted manipulation.

A prompt injection incident represents a condition requiring formal incident management because the attempt caused, or credibly threatened, a material security or operational impact.

A failed attack does not necessarily constitute an incident.

### 6. AI Prompt Injection Incident versus AI Security Incident

A prompt injection incident may constitute an AI security incident when it affects confidentiality, integrity, availability, authorization, security controls, or other protected security properties.

However, not every prompt injection attempt produces a security incident.

For example:

```text id="p7m4qx"
MALICIOUS PROMPT
      |
      v
MODEL REJECTS REQUEST
      |
      v
NO MATERIAL IMPACT
```

The event may still be useful security telemetry even if it does not meet the organization's incident threshold.

### 7. AI Prompt Injection Incident versus Model Failure

A model failure concerns unexpected or unacceptable model behavior.

Prompt injection concerns an input or contextual mechanism intended to influence model behavior.

A model can fail without prompt injection, and prompt injection can occur without producing observable model failure.

### 8. AI Prompt Injection Incident versus Model Compromise

Model compromise concerns unauthorized modification, replacement, or control of the model or model artifact.

Prompt injection generally operates through inputs or contextual information rather than modification of model weights.

The two can nevertheless interact.

### 9. AI Prompt Injection Incident versus Data Poisoning

Data poisoning manipulates data used to train, fine-tune, evaluate, or otherwise influence an AI system.

Prompt injection manipulates instructions or contextual content processed by the AI system.

A poisoned dataset may contain prompt-injection content, creating an interaction between the two attack classes.

### 10. AI Prompt Injection Incident versus Social Engineering

Social engineering manipulates people into performing actions or disclosing information.

Prompt injection primarily attempts to manipulate an AI system.

A campaign can combine both:

```text id="c8v2nr"
ATTACKER
   |
   +------> HUMAN USER
   |           |
   |           v
   |       AI SYSTEM
   |
   +------> DIRECT AI INPUT
               |
               v
           AI SYSTEM
```

The human and AI attack paths should be assessed separately.

### 11. AI Prompt Injection Attack

An AI Prompt Injection Attack intentionally supplies instructions or contextual information designed to influence AI behavior outside its intended operating boundaries.

Potential objectives include:

- bypassing system instructions;
- extracting protected information;
- manipulating tool use;
- influencing decisions;
- bypassing safety controls;
- changing agent behavior;
- causing unauthorized actions.

### 12. AI Prompt Injection Vector

A Prompt Injection Vector is the mechanism through which malicious instructions reach the AI system.

Potential vectors include:

- user prompts;
- documents;
- web pages;
- email;
- retrieved content;
- images;
- audio;
- tool responses;
- API responses;
- database records.

### 13. AI Prompt Injection Entry Point

The Entry Point is the specific interface through which untrusted content enters the AI processing environment.

Examples include:

- chat interface;
- API endpoint;
- document upload;
- web browser;
- retrieval system;
- email connector;
- agent tool.

Identifying the entry point supports containment and attack-path analysis.

### 14. AI Prompt Injection Attack Surface

The Prompt Injection Attack Surface includes every component through which instructions or instruction-like content can influence AI behavior.

The attack surface may include:

- prompts;
- system messages;
- retrieved documents;
- tools;
- memory;
- external content;
- APIs;
- plugins;
- agent environments;
- multimodal inputs.

The attack surface extends beyond the visible chat interface.

### 15. AI Prompt Injection Trust Boundary

A Trust Boundary exists where information crosses between environments with different trust assumptions.

Examples include:

- user input entering an enterprise AI system;
- public web content entering retrieval;
- supplier information entering an AI workflow;
- tool output entering an agent context.

Trust boundaries should have explicit security assumptions and controls.

### 16. AI Prompt Injection Instruction Hierarchy

An Instruction Hierarchy represents the relative authority of instructions within an AI system.

A conceptual hierarchy may include:

```text id="j5r8wd"
SYSTEM / GOVERNANCE INSTRUCTIONS
             |
             v
APPLICATION INSTRUCTIONS
             |
             v
AUTHORIZED USER INSTRUCTIONS
             |
             v
UNTRUSTED RETRIEVED CONTENT
             |
             v
EXTERNAL / THIRD-PARTY CONTENT
```

Actual implementation differs across AI architectures.

The hierarchy should not be assumed to provide security merely because instructions appear in different message roles.

### 17. AI Prompt Injection Instruction Conflict

Instruction Conflict occurs when instructions from different sources require incompatible actions.

Examples include:

- system policy versus user request;
- application instructions versus retrieved document;
- security policy versus tool output.

Conflict handling should be explicitly designed rather than left entirely to model interpretation.

### 18. AI Prompt Injection Instruction Precedence

Instruction Precedence defines which instructions should control behavior when multiple instructions conflict.

Precedence should be supported by application-level enforcement where practical.

Relying solely on the model to correctly interpret instruction precedence may create security risk.

### 19. AI Prompt Injection Untrusted Content

Untrusted Content is information that may contain instructions but should not automatically be treated as authorized commands.

Examples include:

- web pages;
- emails;
- uploaded documents;
- search results;
- external API responses;
- third-party data.

The distinction between **content** and **instruction** is fundamental to prompt-injection defense.

### 20. AI Prompt Injection Trusted Instruction

A Trusted Instruction is an instruction originating from an authorized control layer or actor within the system's intended security model.

Trust should be based on:

- origin;
- authorization;
- context;
- integrity;
- policy.

Text that looks authoritative is not automatically a trusted instruction.

### 21. AI Prompt Injection Direct Prompt Injection

Direct Prompt Injection occurs when an attacker directly supplies instructions to the AI system intended to alter its behavior.

Examples may include attempts to:

- ignore previous instructions;
- reveal protected information;
- bypass policy;
- execute unauthorized actions.

### 22. AI Prompt Injection Indirect Prompt Injection

Indirect Prompt Injection occurs when malicious instructions are embedded in content that the AI system retrieves, reads, processes, or receives from another source.

Examples include:

- malicious web pages;
- poisoned documents;
- emails;
- knowledge-base entries;
- tool responses.

The user may not intentionally provide the malicious instruction.

### 23. AI Prompt Injection Persistent Injection

Persistent Injection occurs when malicious instructions are stored or embedded in information that continues to influence future AI interactions.

Potential persistence locations include:

- memory;
- databases;
- knowledge bases;
- documents;
- agent state;
- system configurations.

### 24. AI Prompt Injection Context Injection

Context Injection occurs when attacker-controlled information is introduced into the context presented to the model.

This may occur through:

- retrieval;
- files;
- web browsing;
- tool output;
- conversation history.

### 25. AI Prompt Injection Retrieval Injection

Retrieval Injection occurs when malicious instructions enter an AI context through a retrieval mechanism.

For example:

```text id="r6k3mv"
USER QUERY
    |
    v
RETRIEVAL
    |
    v
MALICIOUS DOCUMENT
    |
    v
MODEL CONTEXT
    |
    v
MODEL OUTPUT
```

The document may contain instructions that were never explicitly provided by the user.

### 26. AI Prompt Injection Tool-Output Injection

Tool-Output Injection occurs when information returned by a tool contains instructions intended to manipulate subsequent model behavior.

Potential sources include:

- APIs;
- web browsers;
- databases;
- external services;
- plugins;
- search results.

Tool output should therefore not automatically be treated as trusted instructions.

### 27. AI Prompt Injection Multimodal Injection

Multimodal Injection embeds malicious instructions in:

- images;
- audio;
- video;
- documents;
- visual metadata;
- other non-text inputs.

The system should consider whether multimodal content can influence model instructions.

### 28. AI Prompt Injection Cross-Modal Injection

Cross-Modal Injection occurs when instructions are introduced through one modality and influence processing in another.

For example:

```text id="m4q8zs"
IMAGE
  |
  v
VISION MODEL
  |
  v
TEXT / CONTEXT
  |
  v
LLM
  |
  v
ACTION
```

This creates additional trust boundaries that should be assessed.

### 29. AI Prompt Injection Agentic Context

Agentic Context includes the information available to an AI agent while it plans and executes tasks.

It may contain:

- user instructions;
- system instructions;
- retrieved information;
- memory;
- tool results;
- environmental data.

Prompt injection risk increases when contextual information can influence high-impact actions.

### 30. AI Prompt Injection Agentic Action

An Agentic Action is an action taken by an AI system or agent based on its interpreted context.

Actions may include:

- sending messages;
- creating records;
- modifying data;
- executing code;
- calling APIs;
- changing configurations;
- initiating transactions.

The security significance of prompt injection increases when manipulated context can trigger consequential actions.

### 31. AI Prompt Injection Tool Authorization Boundary

The Tool Authorization Boundary separates model reasoning from authority to perform external actions.

A secure architecture should avoid treating the model's decision to call a tool as sufficient authorization for every possible tool action.

Authorization should be enforced by the application or tool layer.

### 32. AI Prompt Injection Privilege Escalation

Prompt Injection Privilege Escalation occurs when manipulated instructions cause an AI system to obtain or use authority beyond its intended permissions.

Examples include:

- invoking restricted tools;
- accessing unauthorized records;
- executing privileged operations;
- bypassing approval.

The underlying issue is authorization failure, not merely unusual model behavior.

### 33. AI Prompt Injection Data Exfiltration

Data Exfiltration occurs when prompt injection causes protected information to be disclosed to an unauthorized party or system.

Potential targets include:

- system prompts;
- credentials;
- personal data;
- confidential documents;
- proprietary information;
- internal system information.

Actual disclosure should be distinguished from an unsuccessful extraction attempt.

### 34. AI Prompt Injection System-Prompt Exposure

System-Prompt Exposure occurs when protected system instructions are revealed through model interaction.

Exposure may involve:

- direct disclosure;
- partial disclosure;
- inferred information;
- transformed or summarized content.

The security significance depends on what the system prompt contains and how exposure affects the system.

### 35. AI Prompt Injection Secret Exposure

Secret Exposure occurs when prompt injection causes credentials, tokens, keys, or other secrets to become accessible to an unauthorized party.

Secrets should not be placed in model-accessible context unless their exposure risk has been explicitly addressed.

### 36. AI Prompt Injection Sensitive-Data Exposure

Sensitive-Data Exposure occurs when prompt injection causes protected information to be disclosed or processed outside its intended context.

Potential data includes:

- personal information;
- confidential business information;
- security information;
- regulated information.

### 37. AI Prompt Injection Tool Abuse

Tool Abuse occurs when prompt injection causes an AI system to misuse an authorized tool.

Examples include:

- sending unauthorized messages;
- querying unauthorized records;
- modifying data;
- invoking external services;
- executing unintended commands.

Tool authorization should therefore be independent from model-generated intent where practical.

### 38. AI Prompt Injection Unauthorized Action

An Unauthorized Action occurs when the AI system performs an action that exceeds the authority granted to the user, application, or agent.

Potential actions include:

- changing records;
- sending communications;
- modifying configurations;
- executing transactions;
- accessing restricted information.

### 39. AI Prompt Injection Safety-Control Bypass

Safety-Control Bypass occurs when prompt injection causes the system to circumvent intended safety restrictions.

A bypass should be evaluated according to:

- control affected;
- exploitability;
- actual impact;
- affected use case;
- ability to reproduce.

A successful jailbreak-like response is not automatically equivalent to a material safety incident.

### 40. AI Prompt Injection Security-Control Bypass

Security-Control Bypass occurs when prompt injection causes the AI system to circumvent an intended security control.

Examples include:

- access restrictions;
- authorization rules;
- output filtering;
- tool restrictions;
- approval mechanisms.

### 41. AI Prompt Injection Policy Bypass

Policy Bypass occurs when prompt injection causes the system to produce behavior inconsistent with organizational policy.

Policy bypass should be distinguished from technical security compromise and from statutory violations.

### 42. AI Prompt Injection Instruction Override

Instruction Override occurs when untrusted content causes the model to disregard or supersede intended instructions.

The organization should determine whether the override was:

- merely generated in text;
- acted upon;
- propagated;
- capable of causing unauthorized effects.

### 43. AI Prompt Injection Context Manipulation

Context Manipulation occurs when an attacker changes information available to the model so that the model reaches an unintended conclusion or action.

This can involve:

- fabricated context;
- misleading documents;
- selective information;
- contradictory instructions;
- hidden content.

### 44. AI Prompt Injection Model Manipulation

Model Manipulation occurs when prompt injection causes model behavior to deviate from intended behavior during an interaction without necessarily changing model parameters.

This distinguishes runtime behavioral manipulation from model-artifact compromise.

### 45. AI Prompt Injection Application Manipulation

Application Manipulation occurs when prompt injection causes the surrounding AI application to perform unintended behavior.

The vulnerability may therefore exist in:

- orchestration;
- authorization;
- tool execution;
- state management;
- output handling.

Prompt injection may expose an application-security weakness rather than being the sole root cause.

### 46. AI Prompt Injection Blast Radius

Blast Radius represents the scope of users, data, systems, tools, or processes potentially affected by a successful prompt injection.

Factors include:

- model permissions;
- user population;
- shared context;
- available tools;
- persistent memory;
- downstream integrations.

### 47. AI Prompt Injection Evidence

Relevant evidence may include:

- prompts;
- system instructions;
- retrieved documents;
- tool outputs;
- model outputs;
- tool calls;
- authorization records;
- application logs;
- affected data;
- model version;
- configuration.

Evidence should be preserved according to applicable security, privacy, retention, and investigation requirements.

### 48. AI Prompt Injection Timeline

A Prompt Injection Incident Timeline should establish the sequence of:

```text id="b9x5tr"
MALICIOUS INPUT / CONTENT
          |
          v
MODEL CONTEXT
          |
          v
MODEL RESPONSE
          |
          v
TOOL / DATA ACCESS
          |
          v
UNAUTHORIZED EFFECT
          |
          v
DETECTION
          |
          v
CONTAINMENT
          |
          v
REMEDIATION
          |
          v
VALIDATION
```

The timeline should distinguish confirmed events from investigative assumptions.

### 49. AI Prompt Injection Incident Governance Principle

**Prompt injection should be governed as a trust-boundary and authorization problem, not merely as a prompt-quality problem.**

Effective governance should examine:

- instruction authority;
- untrusted content;
- retrieval;
- tool access;
- agent permissions;
- data boundaries;
- downstream actions;
- monitoring;
- human oversight.

### 50. Core Principle of AI Prompt Injection Incidents

**An AI system should not be permitted to convert untrusted content into trusted authority merely because the content is presented within the model's context.**

A mature prompt-injection incident capability should be able to establish:

- where the untrusted instruction originated;
- how it entered the AI context;
- which instruction or policy boundary it attempted to cross;
- what model or application processed it;
- what tools or data were accessible;
- whether an unauthorized action occurred;
- what data or systems were affected;
- how the attack was contained;
- whether persistent or downstream effects remain;
- whether controls prevented recurrence.

Prompt-injection taxonomies, attack classifications, detection mechanisms, trust-boundary models, incident severity models, playbooks, containment procedures, and testing frameworks are generally **organizational governance and implementation practices** unless a specific law, regulation, contract, or authoritative requirement makes a particular activity mandatory.

Internal `AI-IMR-*` identifiers are knowledge-base taxonomy identifiers and do not represent statutory provisions, regulatory article numbers, certification requirements, or legal obligations.
